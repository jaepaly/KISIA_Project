# KISIA 제출 구역

> **여기만 hwp·pptx 가 버전관리된다.** 최상위 `.gitignore` 가 `*.hwp` 를 전면 제외하고,
> 이 경로만 예외로 되살린다. 그렇게 하지 않으면 주간보고 12편 + 산출물 6종이
> 통째로 빠져 버전관리가 카톡·드라이브로 흩어진다.

## ⚠️ 서명 전 원본만 커밋한다

서명·날인된 최종본은 **커밋하지 않는다.** 팀원 5명의 자필 서명과 실명이 git 히스토리에
영구히 남는다 — 개인정보 트랙 팀이 자기 팀원 서명을 저장소에 흘린 상태는
발표 QnA에서 가장 아픈 질문이 된다. 훅과 CI가 `*_signed.*` `*_서명.*` `*_날인.*` 을 막는다.

서명본은 팀 드라이브(비공개)에 두고, 여기에는 **제출 이력만** 기록한다.

## 구조

```
submissions/
├─ weekly/W01..W12/        주간활동보고서 + evidence/
└─ milestones/             산출물 6종 + 최종보고서
```

## 파일명 규칙

⚠️ 협회 공지에 규칙이 있으면 **그것이 우선한다.** 아래는 공지 확인 전 잠정안이다.

```
{주차}_{산출물}_{팀명}_{YYYYMMDD}.hwp

W01_주제선정서_개인정보반0팀_20260821.hwp
W03_주간활동보고서_개인정보반0팀_20260904.hwp
```

증빙 캡처: `W03_B_학습로그_20260904.png` — 주차 · 역할 · 내용 · 날짜

## 제출 전 3단 게이트

**D-2 내용** — 5명 전원 이름이 등장하는가 / 각자 검증 가능한 산출물 링크 1개 이상인가 /
"함께 진행·논의함"만 있는 팀원은 반려 / 모든 성능 수치에 측정일·데이터 버전·모델 버전이
붙었는가 / 선행 실측치에 "선행 PoC 자체 측정" 표기가 있는가 / 실존 인물·무동의 수집
데이터가 문서에 없는가

기록됐는가 / 미반영 항목에 사유·예정일이 있는가 / **제공된 hwp 원본 위에** 작성했는가
