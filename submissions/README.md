# KISIA 제출 구역

> **`docs/` 가 정본이고, 제출 서류는 그것을 양식에 옮겨 담은 렌더링이다.** — [DEC-002](../docs/decisions.md) · [DEC-003](../docs/decisions.md)
>
> 제출 서류는 원고(md)든 제출본(hwp·pptx)이든 **팀 드라이브**에 둔다.
> 여기에는 **증빙 캡처**와 **제출 이력**만 남는다.

## 무엇을 어디에 두나

| 대상 | 위치 | 이유 |
|---|---|---|
| 증빙 캡처 (`evidence/`) | **저장소** | 주간보고 「활동 내용」의 뒷받침. `scripts/weekly_report.sh` 출력과 짝을 이룬다 |
| 제출 이력 (아래 표) | **저장소** | 언제 무엇을 누가 제출했는지 |
| **제출 원고** (`*_내용.md`) | **팀 드라이브** | 제출 후 개정되지 않고, 내용 대부분이 `docs/` 의 파생물이다. 정본이 두 곳에 있으면 어긋난다 |
| **제출본** (`*.hwp` `*.pptx`) | **팀 드라이브** | diff 가 안 되므로 버전관리로 얻는 것이 백업·타임스탬프뿐이다. 반면 실명이 실리는 최고위험 파일 종류다 |
| **서명·날인본, 자필 서명 이미지** | **팀 드라이브 (비공개)** | 아래 참조 |

> **제출 증빙은 hwp 가 아니다.** 이 문서가 아래에서 정하듯 *"제출 완료 화면 캡처"* 가 유일한 근거다.
> 따라서 제출본을 저장소에 두는 것은 증빙 논거가 되지 못한다.

## ⚠️ 서류를 쓰다 새 내용이 생기면 `docs/` 에 먼저 쓴다

제출 서류에만 있고 `docs/` 에 없는 내용은 **서류와 함께 드라이브로 사라진다.**

W2 수행계획서가 실제로 그럴 뻔했다 — 진행률 산정 규칙은 **hwp 양식에 칸이 아예 없어서** 원고에만 존재했고, W8 「전체 진행률 약 __%」가 그걸 인용해야 한다. [roadmap.md §9](../docs/roadmap.md) 로 옮겨 살렸다.

| 서류에서 나온 것 | 사는 곳 |
|---|---|
| 주차·게이트·판정·진행률 | [`docs/roadmap.md`](../docs/roadmap.md) |
| 설계·데이터·역할·환경·규제 | [`docs/plan.md`](../docs/plan.md) |

## ⚠️ 서명 전 원본만 커밋한다

서명·날인된 최종본은 **커밋하지 않는다.** 팀원 5명의 자필 서명과 실명이 git 히스토리에
영구히 남는다 — 개인정보 트랙 팀이 자기 팀원 서명을 저장소에 흘린 상태는
발표 QnA에서 가장 아픈 질문이 된다.

hwp 전면 차단으로 1차 방어가 되지만 **거기에 의존하지 않는다.** 서명본이 md·이미지 등
다른 형식으로 들어올 수 있으므로 훅과 CI가 `*_signed.*` `*_서명.*` `*_날인.*` 과
`서명완/` `서명본/` `날인본/` `signed/` 를 독립적으로 막는다.

## 구조

```
submissions/
├─ weekly/W01..W12/evidence/      증빙 캡처
└─ milestones/W01../evidence/     증빙 캡처
                                  (서류 본체는 원고·제출본 모두 드라이브)
```

## 파일명 규칙

⚠️ 협회 공지에 규칙이 있으면 **그것이 우선한다.** 아래는 공지 확인 전 잠정안이다.

```
{주차}_{산출물}_{팀명}_{YYYYMMDD}.hwp

W01_주제선정서_개인정보반0팀_20260821.hwp
W03_주간활동보고서_개인정보반0팀_20260904.hwp
```

증빙 캡처: `W03_B_학습로그_20260904.png` — 주차 · 역할 · 내용 · 날짜
