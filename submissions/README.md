# KISIA 제출 구역

> **저장소가 담는 것은 「원고」이지 「제출본」이 아니다.** — [DEC-002](../docs/decisions.md)
>
> hwp·pptx 제출본과 주간활동보고서는 **팀 드라이브**에 둔다.
> 여기에는 **마일스톤 산출물의 원고(md)**, **증빙 캡처**, **제출 이력**만 남는다.

## 무엇을 어디에 두나

| 대상 | 위치 | 이유 |
|---|---|---|
| **마일스톤 산출물 원고** (`*_내용.md`) | **저장소** | 개정되고 나중에 비교된다. 8주차 「계획 대비 변경사항」·10주차 「중간 점검 이후 개선사항」의 원자료가 이 diff다 |
| 증빙 캡처 (`evidence/`) | **저장소** | 주간보고 「활동 내용」의 뒷받침. `scripts/weekly_report.sh` 출력과 짝을 이룬다 |
| 제출 이력 (아래 표) | **저장소** | 언제 무엇을 누가 제출했는지 |
| **제출본** (`*.hwp` `*.pptx`) | **팀 드라이브** | diff 가 안 되므로 버전관리로 얻는 것이 백업·타임스탬프뿐이다. 반면 실명이 실리는 최고위험 파일 종류다 |
| **주간활동보고서** (원고·제출본 모두) | **팀 드라이브** | 매주 새 문서라 diff 로 얻을 것이 없고, 서명 수령은 카카오톡·디스코드에서 끝난다 |
| **서명·날인본, 자필 서명 이미지** | **팀 드라이브 (비공개)** | 아래 참조 |

> **제출 증빙은 hwp 가 아니다.** 이 문서가 아래에서 정하듯 *"제출 완료 화면 캡처"* 가 유일한 근거다.
> 따라서 제출본을 저장소에 두는 것은 증빙 논거가 되지 못한다.

## ⚠️ 서명 전 원본만 커밋한다

서명·날인된 최종본은 **커밋하지 않는다.** 팀원 5명의 자필 서명과 실명이 git 히스토리에
영구히 남는다 — 개인정보 트랙 팀이 자기 팀원 서명을 저장소에 흘린 상태는
발표 QnA에서 가장 아픈 질문이 된다.

hwp 전면 차단으로 1차 방어가 되지만 **거기에 의존하지 않는다.** 서명본이 md·이미지 등
다른 형식으로 들어올 수 있으므로 훅과 CI가 `*_signed.*` `*_서명.*` `*_날인.*` 과
`서명완/` `서명본/` `날인본/` `signed/` 를 독립적으로 막는다.

## 구조

```
submissions/
├─ weekly/W01..W12/evidence/   증빙 캡처만 (보고서 본체는 드라이브)
└─ milestones/                 산출물 원고 md + evidence/
```

## 파일명 규칙

⚠️ 협회 공지에 규칙이 있으면 **그것이 우선한다.** 아래는 공지 확인 전 잠정안이다.

```
{주차}_{산출물}_{팀명}_{YYYYMMDD}.hwp

W01_주제선정서_개인정보반0팀_20260821.hwp
W03_주간활동보고서_개인정보반0팀_20260904.hwp
```

증빙 캡처: `W03_B_학습로그_20260904.png` — 주차 · 역할 · 내용 · 날짜

## 제출 전 3단 게이트

**D-2 내용** — 5명 전원 이름이 등장하는가 / 각자 검증 가능한 산출물 링크 1개 이상인가 /
"함께 진행·논의함"만 있는 팀원은 반려 / 모든 성능 수치에 측정일·데이터 버전·모델 버전이
붙었는가 / 선행 실측치에 "선행 PoC 자체 측정" 표기가 있는가 / 실존 인물·무동의 수집
데이터가 문서에 없는가

**D-1 멘토·형식** — 피드백이 `[MF-ID / 내용 / 수용여부 / 반영위치 / 담당 / 기한]` 으로
기록됐는가 / 미반영 항목에 사유·예정일이 있는가 / **제공된 hwp 원본 위에** 작성했는가
(새 문서 재작성·표 삭제 금지) / 팀명·팀번호·주차 번호 / 파일명이 공지 기준과 일치하는가

**D-0 팀장 최종** — 마감 24h 전 파일 잠금 / 서명란 + 멘토 확인 / **다른 PC에서 hwp가
정상적으로 열리는가**(표 깨짐·이미지 유실) / PDF 동시 제출 여부 / 제출 경로·기한 재확인 /
제출 완료 화면 캡처
