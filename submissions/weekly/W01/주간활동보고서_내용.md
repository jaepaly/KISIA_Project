## 이번주 목표

> ⚠️ **목표는 월요일에 쓴다.** 금요일에 한 일을 목표처럼 되쓰면 *"무엇을 했고 무엇이 달라졌는지"*를 정면으로 위반한다. 이번 주는 소급 작성이므로, 다음 주부터는 월요일 킥오프에서 선기입한다.

```
1. 프로젝트 주제명 확정 및 주제 선정서 작성·제출
2. 팀명·역할 체계 확정, 역할별 작업 매뉴얼 배포 후 지망 수집
3. 멘토링 1회 실시 및 피드백 반영
4. 저장소 운영 체계 구축 (협업 규칙·보안 방어·증빙 자동화)
5. 12주 주차별 수행 계획 및 지표 3계층 확정
```

## 멘토링 내용

```
[W1 멘토링 1회차]  2026. 8. 〔__〕. 〔요일〕 / 장소 〔__〕 / 멘토 권영길 / 참석 5명

■ 논의 1 — 프로젝트 주제 표현  [MF-002]

  · 멘토 의견
    제출한 주제 초안이 길고 서술형 문장이어서 제목으로 기능하지 않으며,
    과제 내용이 명시적으로 드러나지 않는다는 의견을 제시함.
    대안으로 「온라인 공개정보의 누적/결합에 따른 개인정보 재식별 위험
    평가 및 보호조치 추천 시스템」을 제안하되, 이 역시 추가로 다듬을
    것을 함께 권고함.

  · 결정 사항
    제안안의 핵심 요소('공개'의 법적 정박, 재식별 위험, 조치 제시)는
    유지하되, 축을 개인용 영향평가로 옮겨 확정.
      → 개인용 프라이버시 영향평가:
         공개 게시글 재식별 위험 진단·완화 도구 (28자)
    '누적·결합'은 위험 발생 기전이므로 제목이 아니라 「주제 선정 배경」과
    「주요 개발 내용」에서 다루기로 함. 개인정보 보호법 제2조 제1호
    나목이 재식별을 "다른 정보와 쉽게 결합하여 알아보는 것"으로
    정의하므로 '재식별'에 결합이 이미 내포됨.
    확정안은 차기 멘토링에서 재확인 예정.

  · 수용 여부 : 수용
  · 반영 위치 : 주제선정서 전면, 계획서, README, 저장소 문서 일체
  · 담당·기한 : 팀장 / 2026. 8. 〔__〕.

■ 논의 2 — 입력·수집 경로 재검토  [MF-001]

  · 제기된 문제
    ① 브라우저 확장으로 특정 블로그 플랫폼 에디터에 적용할 경우, 현재
       작성 중인 글 외에 기존에 작성해둔 게시글에 접근이 가능한지 확실하지 않음
    ② 결과물이 특정 플랫폼에 한정된 도구로 보일 수 있음

  · 팀 검토 의견
    수집 범위가 작성 중인 글로 한정될 경우, 본 과제의 핵심 주장인
    게시글 누적에 따른 위험 상승을 시연·검증할 수 없음
    (선행 PoC 자체 측정: 1편 26.7 → 5편 69.2 → 19편 79.7).
    즉 편의성의 문제가 아니라, 핵심 구성요소인 누적·기여도 엔진의
    검증 표면이 사라지는 문제로 판단함.

  · 결정 사항
    입력 경로를 자체 가상 SNS 플랫폼으로 변경. 기존에 조사한 플랫폼 API
    제약 사항은 「향후 실서비스 이관 시의 제약」으로 이관하여 기록 유지.

  · 수용 여부 : 수용
  · 반영 위치 : 계획서 §4·§5·§6·§12, README, 주제선정서 「주요 개발 내용」,
               2주차 수행계획서
  · 담당·기한 : E(구현) · 팀장(문서) / 문서 반영 8.〔__〕, 스펙 확정 2주차

  · 후속 확인 사항
    - 가상 SNS는 플랫폼 계층, 분석 도구는 이용자 측 실행 계층으로 분리하여
      '외부 전송 없이 이용자 기기에서 탐지한다'는 설계 원칙이 유지되도록
      2주차 모듈 인터페이스 계약에 명시
    - 실제 데이터 검증을 위한 직접 입력 경로를 최소 기능으로 추가

■ 논의 3 — 〔주제 기입〕  [MF-00_]  ※ 다음 번호는 MF-008

  · 멘토 의견 : 〔기입〕
  · 수용 여부 : 〔수용 / 부분수용 / 보류 / 미수용〕
  · 반영 위치 : 〔기입〕
  · 담당·기한 : 〔기입〕

■ 차기 멘토링 : 2026. 〔__〕. 〔__〕 〔요일〕 〔__〕시 / 방식 〔대면·온라인〕
■ 「멘토 확인(인)」 처리 방식 : 〔현장 날인 / 스캔 / 전자서명 / 확인 메일 갈음〕
```

> ⚠️ **논의 항목이 하나뿐이면 얇게 읽힌다.** 실제로 오간 이야기를 같은 형식으로 2~3건 채운다.

> ④ 「기존 도구 대비 추가 탐지율」을 성패 기준으로 두는 것이 적절한지

## 제출 전 3단 게이트

**D-2 내용**
- [ ] 5명 전원 이름이 등장하는가
- [ ] 각자 **검증 가능한 산출물 링크 1개 이상**인가
- [ ] "함께 진행·논의함"만 있는 팀원은 없는가 (있으면 반려)
- [ ] 모든 성능 수치에 측정일·데이터 버전·모델 버전이 붙었는가
- [ ] 선행 수치에 **"선행 PoC 자체 측정"** 표기가 있는가
- [ ] 실존 인물·무동의 수집 데이터가 문서에 없는가

**D-1 멘토·형식**
- [ ] 피드백이 `[MF-ID / 내용 / 수용여부 / 반영위치 / 담당 / 기한]`으로 기록됐는가
- [ ] 미반영 항목에 사유·예정일이 있는가
- [ ] **제공된 hwp 원본 위에** 작성했는가 (새 문서 재작성·표 삭제 금지)
- [ ] 팀명(파도풀)·팀번호(3)·주차 번호(1주차)
- [ ] 파일명이 공지 기준과 일치하는가

**D-0 팀장 최종**
- [ ] 마감 24h 전 파일 잠금
- [ ] 서명 5칸 + 멘토 확인
- [ ] **다른 PC에서 hwp가 정상적으로 열리는가** (표 깨짐·이미지 유실)
- [ ] PDF 동시 제출 여부 확인
- [ ] 제출 경로·기한 재확인
- [ ] **제출 완료 화면 캡처 보관**
