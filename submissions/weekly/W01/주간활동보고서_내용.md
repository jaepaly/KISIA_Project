## 활동 내용

> **제출용 최종판.** 근거와 상세는 맨 아래 「부록 — 상세판」에 있다(8·10주차 원자료).

```
1주차에는 프로젝트 주제를 구체화하고 팀 운영 체계를 갖추었다. 멘토 의견에 따라
주제명을 「공개 게시글 누적·결합에 따른 재식별 위험 자가진단 및 보호조치
추천 시스템」으로 확정하고, 게시글 확보 경로를 브라우저 확장에서 자체 가상
SNS 플랫폼으로 변경하였다. 수집 범위가 작성 중인 글로 한정되면 게시글 누적에
따른 재식별 위험 상승을 검증할 수 없기 때문이다. 아울러 팀명을 '파도풀'로 정하고
역할 배정과 12주 수행 계획 수립, 저장소 운영 체계 구축을 마쳤다.

박재현(팀장)은 선행 연구와 모델·데이터 방향, 개발 환경을 검토하고 12주 수행
계획과 역할별 작업 매뉴얼 5종을 작성하였으며, 저장소 구축과 주제 선정서 작성,
멘토링 진행을 담당하였다. (증빙: 커밋 이력, docs/roadmap.md)

이지희는 팀명을 제안하고 주제명 표현·입력 경로·데이터 방향을 검토하였으며 관련
법·규제를 확인하였다. E로 배정되어 2주차 인터페이스 계약을 주관한다.
(증빙: docs/roles/notes/이지희.md)

신정현은 주제 후보와 주제명 표현을 검토하고 기존 개인정보 탐지 도구와 선행
연구를 조사하였으며, 그 결과가 주제 선정서 「유사 사례 및 차별점」의 근거가
되었다. (증빙: docs/roles/notes/신정현.md)

최진필은 주제 후보 조사와 범위 논의에 참여하고 모델 방향과 관련 법·규제를
검토하였다. 검토 결과는 1단 탐지와 2단 종합 판정의 2단 구조 확정에 반영되었다.
(증빙: docs/roles/notes/최진필.md)

이은선은 주제 범위 논의와 입력 경로 검토에 참여하고 기존 도구 조사와 장비 현황
확인을 맡아 학습용 GPU 2대 확보를 확정하였다.
(증빙: docs/roles/notes/이은선.md)
```

> ⚠️ `notes` 커밋이 제출 시점에 실제로 있어야 한다. 없으면 증빙 표기를 지운다.
> 개인별 수행 내용은 [W01_역할확인.md](W01_역할확인.md)로 팀원 전원에게 확인받아 작성하였다.

## 멘토링 내용

```
1주차 멘토링은 2026년 8월 20일(목) 온라인으로 진행하였으며 멘토 권영길 님과 팀원
5명 전원이 참석하였다. 첫째, 주제 초안이 길고 서술형이어서 제목으로 기능하지
못한다는 의견과 대안을 제시받고 그 대안도 다듬을 것을 권고받아, 주제명을 42자로
확정하고 관련 문서 전반에 반영하였다[MF-002]. 둘째, 에디터 확장은 기존 게시글
접근이 보장되지 않고 특정 플랫폼 전용으로 보일 수 있다는 점을 함께 확인하여 자체
가상 SNS 플랫폼으로 구체화하되 외적 타당성 확보 방안을 마련할 것을 권고받았으며,
플랫폼 계층과 분석 계층을 분리해 외부 전송이 발생하지 않게 하고 세부 사양은
2주차에 확정한다[MF-001]. 셋째, 배포된 6종 양식 전부에 멘토 확인란이 있어 정기
슬롯 고정이 필요함을 확인하고 정기 멘토링을 매주 목요일 20시로 정하였다
[MF-003]. 넷째, 팀원 자기소개 후 역할을 조기에 확정할 것을 권고받아 A 이은선,
B 최진필, C 신정현, D 박재현(팀장 겸임), E 이지희로 배정하였다. 차기 멘토링은
〔일시〕에 온라인으로 진행하며 「멘토 확인(인)」은 〔현장 날인 / 스캔 / 전자서명 /
확인 메일 갈음〕으로 처리한다.
```

```
  · 증빙     : docs/roles/notes/신정현.md (커밋)

■ 최진필 · B 1단 탐지 모델

  · 한 일    : 주제 후보 조사, 주제 범위 논의, 모델 방향 검토, 법·규제 확인,
               멘토링 참석 및 자기소개 · 정기 멘토링 일정 조율 논의,
               역할별 작업 매뉴얼 검토 후 1·2지망 제출(1지망 B), 담당 범위 정리
  · 달라진 것 : 모델 방향 검토 결과가 1단 탐지 + 2단 종합 판정의 2단 구조 확정에
               반영됨
               B 담당 확정 → 2주차 라벨 스키마 공동 확정 및 기존 도구 비교 착수 책임 확정
  · 증빙     : docs/roles/notes/최진필.md (커밋)

■ 이은선 · A 데이터 리드

  · 한 일    : 주제 범위 논의, 입력 경로 검토, 기존 개인정보 탐지 도구·서비스 조사,
               개발 환경·장비 현황 확인,
               멘토링 참석 및 자기소개 · 정기 멘토링 일정 조율 논의,
               역할별 작업 매뉴얼 검토 후 1·2지망 제출(2지망 A), 담당 범위 정리
  · 달라진 것 : 장비 현황 확인으로 GPU 2대(B·D) 확보 확정 → 모델 2종 병렬 학습 가능
               A 담당 확정 → 2주차 합성 코퍼스 생성 파이프라인 착수 책임 확정
  · 증빙     : docs/roles/notes/이은선.md (커밋)
```

> ⚠️ **증빙란의 `notes` 커밋이 제출 시점에 실제로 있어야 한다.**
> 위 네 사람의 「증빙」은 `docs/roles/notes/<이름>.md` 커밋을 가리킨다. **토요일까지 각자 커밋을 남기지 않으면 이 줄은 거짓이 된다.**
> 커밋이 없으면 해당 줄에서 증빙을 빼고 *"멘토링 참석 · 역할 지망 제출"* 까지만 남긴다 — 없는 증빙을 적는 것보다 낫다.

## (상세) 멘토링 내용

```
[W1 멘토링 1회차]  2026. 8. 20.(목) / 온라인 / 멘토 권영길 / 참석 5명 전원

■ 논의 1 — 프로젝트 주제 표현  [MF-002]

  · 멘토 의견
    제출한 주제 초안이 길고 서술형 문장이어서 제목으로 기능하지 않으며,
    과제 내용이 명시적으로 드러나지 않는다는 의견을 제시함.
    대안으로 「온라인 공개정보의 누적/결합에 따른 개인정보 재식별 위험
    평가 및 보호조치 추천 시스템」을 제안하되, 이 역시 추가로 다듬을
    것을 함께 권고함.

  · 결정 사항
    제안안의 구성요소(공개 · 누적·결합 · 재식별 위험 · 조치 제시)와
    문장 골격을 그대로 유지하고, 두 곳만 다듬어 확정.
      '온라인 공개정보' → '공개 게시글'
          분석 단위가 게시글임을 제목에서 드러냄
      '위험 평가' → '위험 자가진단'
          이용자 본인이 자신의 글을 점검하는 도구임을 명시하여,
          제3자가 타인의 공개정보를 평가하는 도구로 읽힐 여지를 차단
      → 공개 게시글 누적·결합에 따른 재식별 위험 자가진단 및
         보호조치 추천 시스템 (42자)
    제안안(48자)보다 짧으면서 지시 대상은 더 분명해짐.
    확정안은 차기 멘토링에서 재확인 예정.

  · 수용 여부 : 수용
  · 반영 위치 : 주제선정서 전면, 계획서, README, 저장소 문서 일체
  · 담당·기한 : 팀장 / 2026. 8. 21.(금) 문서 반영 완료

■ 논의 2 — 입력·수집 경로 재검토  [MF-001]

  · 제기된 문제
    ① 브라우저 확장으로 특정 블로그 플랫폼 에디터에 적용할 경우, 현재
       작성 중인 글 외에 기존에 작성해둔 게시글에 접근이 가능한지 확실하지 않음
    ② 결과물이 특정 플랫폼에 한정된 도구로 보일 수 있음

  · 팀 검토 의견
    수집 범위가 작성 중인 글로 한정될 경우, 본 과제의 핵심 주장인
    게시글 누적에 따른 위험 상승을 시연·검증할 수 없음
    (선행 PoC 자체 측정: 1편 26.7 → 5편 69.2 → 19편 79.7).
    즉 편의성의 문제가 아니라, 핵심 구성요소인 누적·기여도 엔진의
    검증 표면이 사라지는 문제로 판단함.

  · 결정 사항
    입력 경로를 자체 가상 SNS 플랫폼으로 변경. 기존에 조사한 플랫폼 API
    제약 사항은 「향후 실서비스 이관 시의 제약」으로 이관하여 기록 유지.

  · 수용 여부 : 수용
  · 반영 위치 : 계획서 §4·§5·§6·§12, README, 주제선정서 「주요 개발 내용」,
```
