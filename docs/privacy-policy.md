## 1. 개인정보의 처리 목적

| 목적 | 설명 |
|---|---|
| 재식별 위험 자가진단 | 이용자가 Veilo에 쓴 글에서 준식별자(나이·거주지·직업 등)를 탐지하고, 여러 편이 결합됐을 때의 재식별 위험도(k, 추정 후보 인원수)를 계산해 이용자 본인에게만 보여준다 |
| 위험 표현 대체 제안 (선택) | 위험도가 높은 표현을 다르게 쓰는 문장 후보를 제안한다. 미리 준비된 시연 인물 글은 사전에 만들어 둔 후보를 쓰고, 이용자가 직접 쓴 새 글만 필요 시 AI 모델을 호출한다 |
| 대회 시연 | Veilo에 시딩된 합성 페르소나 글로 위 진단 과정을 심사위원에게 시연한다 (`veilo.site`) |

> Veilo의 시딩 게시물(합성 페르소나 5명 분)은 **전량 합성 데이터**다. 실존 인물의 개인정보가 아니므로 이 방침이 규율하는 "개인정보"에 해당하지 않는다. 이 방침이 실제로 규율하는 것은 **방문자(심사위원 등)가 체험 중 직접 입력하는 글**이다.

## 2. 처리하는 개인정보의 항목

| 경로 | 처리 항목 | 비고 |
|---|---|---|
| Veilo 둘러보기 | 방문자 구분용 세션 쿠키 (8항 참조) | 시딩된 합성 페르소나 글 열람. 실명·연락처 등 수집 없음 |
| Veilo 글쓰기 | 이용자가 직접 입력한 글 본문·제목·사진 캡션·(선택)위치태그 | 방문자별 임시 사본에만 저장 (3항 참조). 회원가입·실명·연락처 없음 |
| 파도풀 점검 요청 | 위 게시물 텍스트 전체 | 위험도 계산 목적으로만 서버 메모리에서 처리 |
| 파도풀 "다르게 쓰기" 제안 (선택, 켜졌을 때만) | 위험 표현이 포함된 문장 1개 + 앞뒤 문장, 스팬 위치 | 글 전체·닉네임·계정 식별값은 포함되지 않음. KISIA 협회 게이트웨이를 통해 AI 모델(Claude Haiku)에 전달 |

**수집하지 않는 것**: 이름·주민등록번호·연락처·이메일·결제정보·위치(GPS)·기기 식별자. 회원가입 기능 자체가 없다.

## 3. 개인정보의 처리 및 보유 기간

- **방문자별 임시 사본**: Veilo는 방문자(심사위원 등)마다 원본과 분리된 임시 데이터 사본을 배정해, 직접 쓴 글이 다른 방문자나 원본에 영향을 주지 않게 한다. **6시간 동안 쓰지 않으면 그 사본은 자동 삭제**된다(파일 수정 시각 기준). 그와 별개로 **매일 04:00(KST)에 모든 방문자 사본을 삭제**하고 시딩 원본 상태로 되돌린다
- **파도풀 점검 요청**: 요청을 처리해 응답을 반환하면 즉시 폐기한다 — 파도풀 자체는 DB나 파일을 갖지 않는다
- **시딩 원본 데이터**: 합성 페르소나 글 원본은 읽기 전용으로 유지되며, 방문자의 조작(비공개 전환·수정 등)은 방문자 자신의 사본에만 반영된다
- **(참고 · 현재 미시행)** 설계상 예정된 M4 외적 타당성 검증 단계(서면 동의 실블로거 10~20명)는 대회 제출 시점 기준 아직 시작되지 않았다 — 시작되면 로컬 전용 처리 + 분석 종료 즉시 전량 파기 원칙을 적용한다 (`docs/plan.md` §6)

## 4. 개인정보의 제3자 제공 및 처리위탁

**점검(위험도 계산) 자체는 제3자에게 제공·위탁하지 않는다.** 파도풀은 이용자 서버 프로세스 안에서만 계산하며, 이 경로의 외부 전송은 0건이다.

**"다르게 쓰기" 제안 기능만, 켜져 있을 때 조건부로 외부 전송이 발생할 수 있다:**

| 항목 | 내용 |
|---|---|
| 전송 대상 | 위험 표현이 포함된 문장 1개 + 앞뒤 문장, 스팬 위치뿐 — **글 전체·닉네임·계정 식별값은 보내지 않는다** |
| 전송 경로 | KISIA 협회 게이트웨이(`monogpt.kr`, Anthropic 호환) — 대회 주관 측이 제공하는 경로로만 전달 |
| 모델 | Claude Haiku 4.5 |
| 처리 위치 | 게이트웨이는 국내(`monogpt.kr`)이나 그 뒤의 모델 처리는 국외일 수 있다. 보내는 것이 문장 한 줄과 앞뒤 문장뿐이고 계정 식별값이 없어 개인을 특정할 수 없는 형태지만, 정식 서비스로 가면 국외 이전 고지와 동의 절차를 갖춘다 |
| 기본값 | 소프트웨어 기본값은 꺼짐(서버 설정과 API 키가 모두 있어야 켜진다). **심사용 배포판(`veilo.site`)에서는 켜져 있다** |
| 실패 시 | 8초 안에 응답이 없거나 꺼져 있으면 미리 준비된 규칙·캐시 후보로 대체한다 — 화면은 그대로 뜨고 재시도하지 않는다 |
| 투명성 | 실제로 외부 모델을 썼는지 화면에 표시한다(`provenance.external_llm_used`) |

시연 인물 5명의 리라이트 후보는 **사전에 미리 만들어 둔 것**을 쓰므로, 그 인물들의 글을 보는 것만으로는 외부 전송이 발생하지 않는다. 외부 전송은 **방문자가 직접 새 글을 쓰고 리라이트를 요청했을 때만** 조건부로 일어난다.

## 5. 개인정보의 파기절차 및 파기방법

- 파도풀은 요청 처리 후 원문을 들고 있지 않는다 (메모리 처리, 디스크 미기록)
- Veilo 방문자 사본은 6시간 미사용 시 자동 삭제되고, 매일 04:00 재시딩 때 전량 삭제되며, 대회 발표 종료 후 서버 자체를 내릴 때 함께 사라진다
- 파도풀과 Veilo 는 별개 프로세스로 돌고, 파도풀은 Veilo 가 넘겨주는 내보내기 형식만 받는다 — 글 전체를 직접 읽지 않는다

## 6. 정보주체의 권리·의무 및 행사방법

- 회원가입이 없어 열람·정정·삭제를 요청할 영구 데이터 자체가 없다. 직접 쓴 글은 화면에서 바로 수정·비공개 전환·삭제할 수 있고, 그대로 두면(6시간 후, 늦어도 다음 날 새벽 4시) 사본 전체가 자동 삭제된다
- "다르게 쓰기" 제안을 원치 않으면 그 기능을 요청하지 않으면 된다 — 점검(위험도 계산) 자체는 이 기능과 무관하게 항상 로컬에서만 이뤄진다
- 그 외 문의·우려 사항은 9항 연락처로 알려주면 확인 후 답한다

## 8. 쿠키 등 자동 수집 장치

**방문자를 구분하기 위한 필수 세션 쿠키를 사용한다.** 이 쿠키는 방문자마다 다른 임시 사본을 배정하기 위한 기술적 식별값일 뿐이며, 이름·연락처 등 개인 식별정보를 담지 않는다. 광고·추적 목적의 쿠키는 쓰지 않는다. 브라우저 저장소도 함께 쓴다 — 3분 체험의 진행 상태는 `localStorage`(`pado_tour`)에, 새로고침 판별값은 `sessionStorage`에 둔다. 둘 다 이용자 브라우저 안에만 남고 서버로 전송되지 않으며, 브라우저의 사이트 데이터 삭제로 언제든 지울 수 있다.

## 부록 — 법적 근거 대조

이 방침의 세부 설계 근거는 `docs/compliance-mapping.md`(§13 규제 매핑표)에 조항별 출처·확인일과 함께 정리돼 있다. 핵심만 요약하면:

- 나이·거주지 등 **준식별자도 개인정보 보호법상 개인정보에 해당할 수 있다** (PIPA 제2조 1호 나목) — 그래서 개발 데이터 전량을 합성으로 만들었다
- **수집 자체가 처리행위**다 (PIPA 제2조 2호) — 그래서 무동의 실데이터를 애초에 모으지 않는다
- 외부 LLM 전송은 **제17조(제3자 제공)/제26조(위탁)**의 실질에 따라 갈리며, k값 기반 위험도 등급(`VERY_HIGH`/`HIGH`/`ACCEPTABLE`/`UNKNOWN`)을 가명정보 처리 가이드라인의 위험도 기반 체계와 방향을 맞췄다
- AI 기본법 고영향 AI 해당 여부는 **미정**으로 유보하되, 투명성 의무(판단 근거 제시·기권 표시)는 현재 설계가 이미 충족하는 방향이다

법적 결론은 단정하지 않는다 — 각 조항은 "~에 해당할 수 있어 ~로 설계했다"는 형태로만 쓴다 (팀은 변호사가 아니다).
