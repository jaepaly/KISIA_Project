> - **회원가입이 없습니다.** 이름·연락처 등 개인 식별정보를 수집하지 않습니다.

## 1. 개인정보의 처리 목적

본 서비스는 다음 목적을 위해서만 텍스트 데이터를 처리하며, 아래 목적 외로는 이용하지 않는다.

| 목적 | 설명 |
|---|---|
| 재식별 위험 자가진단 | 이용자가 입력·업로드한 글에서 준식별자(나이·거주지·직업 등)를 탐지하고, 여러 편이 결합됐을 때의 재식별 위험도를 계산해 이용자 본인에게만 보여준다 |
| 대회 시연 | 우리뜰(가상 SNS)에 시딩된 합성 페르소나 글로 위 진단 과정을 시연한다 |

> 우리뜰의 시딩 게시물은 **전량 합성 데이터**다 (`docs/plan.md` §6). 실존 인물의 개인정보가 아니므로 이 처리방침이 규율하는 "개인정보"에 해당하지 않는다. 이 방침이 실제로 규율하는 것은 **이용자가 직접 입력·업로드하는 글**이다.

## 2. 처리하는 개인정보의 항목

| 경로 | 처리 항목 | 비고 |
|---|---|---|
| 우리뜰 둘러보기 | 없음 | 시딩된 합성 페르소나 글만 열람. 이용자 계정·행위 데이터를 수집하지 않음 |
| 우리뜰 글쓰기(체험 계정) | 이용자가 직접 입력한 글 본문·제목·사진 캡션·(선택)위치태그 | 체험용 로컬 DB에만 저장, 회원가입·실명·연락처 없음 |
| 파도풀 스캔 요청 | 위 게시물의 텍스트 | 분석 목적으로만 메모리에서 처리 |
| 파도풀 수동 업로드(`/upload`) | 이용자가 직접 붙여넣거나 올린 텍스트 파일 내용 | **디스크에 저장하지 않음** — `apps/analyzer/adapters/file_adapter.py`가 메모리에서 읽고 응답 후 버림 |

**수집하지 않는 것**: 이름·주민등록번호·연락처·이메일·결제정보·위치(GPS)·기기 식별자. 회원가입 기능 자체가 없다.

## 3. 개인정보의 처리 및 보유 기간

- **파도풀(분석기) 처리 요청**: 요청 1건당 **1회성**으로 처리하고 응답을 반환하면 즉시 폐기한다. 별도 보유 기간이 없다 — 애초에 저장하지 않기 때문이다.
- **우리뜰(체험 계정) 게시물**: 시연·체험 목적의 로컬 DB(`data/interim/sns.db`)에만 있으며, 외부로 배포되지 않는다. 대회 발표 종료 후 삭제한다.
- **(참고 · 현재 미시행)** 설계상 예정된 M4 외적 타당성 검증 단계에서는 서면 동의를 받은 실블로거 10~20명의 공개 블로그 글을 로컬에서만 처리하고, **분석 종료 즉시 원본·중간 산출물을 전부 파기**한다 (`docs/plan.md` §6 데이터 원칙). 이 단계는 대회 제출 시점 기준 **아직 시작되지 않았다.**

## 4. 개인정보의 제3자 제공 및 처리위탁

**원칙적으로 제공·위탁하지 않는다.** 1단(스팬 탐지·특정성 계산)은 이용자 서버 안에서만 처리하고 외부 전송이 0건이다.

2단(종합 판정)에 외부 LLM을 쓰는 실험적 경로가 설계돼 있으나(`apps/analyzer/external.py`), 대회 제출 버전에서는:

- **기본값이 차단**이다 (`ALLOW_EXTERNAL_LLM=false`)
- 활성화하더라도 **① 이용자의 명시적 동의 AND ② 가명화 완료 후에만** 전송한다 (`or`가 아니라 `and`) — 법정 최소보다 강하게 설계했다 (`docs/compliance-mapping.md` §1-3)
- 원문이 아니라 가명 처리된 텍스트만 전송 시도 대상이 되며, 코드 레벨에서 원문 전송을 차단한다

## 5. 개인정보의 파기절차 및 파기방법

- **파기 대상 자체가 생기지 않는다** — 파도풀은 요청을 처리하고 나면 원문을 들고 있지 않는다 (메모리 처리, 디스크 미기록)
- 우리뜰 체험 계정 데이터는 로컬 SQLite 파일 삭제로 완전 파기한다
- 계층 경계(`scripts/check_boundary.sh`)로 분석기가 SNS 내부 데이터를 직접 들여다보지 않는 것도 검증한다

## 6. 정보주체의 권리·의무 및 행사방법

- 회원가입이 없어 열람·정정·삭제를 요청할 대상 데이터 자체가 없다. 우리뜰 체험 계정에 직접 작성한 글은 이용자 본인이 화면에서 즉시 수정·비공개 전환·삭제할 수 있다
- 파도풀에 입력·업로드한 글은 요청 처리와 함께 즉시 폐기되므로 별도 삭제 요청이 필요 없다
- 그 외 문의나 우려 사항은 아래 9항 연락처로 알려주면 확인 후 답한다

## 7. 안전성 확보조치

| 조치 | 내용 |
|---|---|
| 처리 위치 분리 | 분석기(`apps/analyzer`)는 SNS 저장소(`apps/sns`)의 DB·내부 모듈을 직접 참조하지 않고 HTTP 내보내기 API로만 접근 (`adapters/sns_adapter.py`) |
| 업로드 경로 격리 | 업로드 파일은 메모리에서만 처리 (`adapters/file_adapter.py`), 디스크 미기록 |
| 외부 전송 게이트 | 외부로 나가는 코드를 `external.py` 한 파일로 모으고 기본 차단 |
| 검증 | `scripts/check_boundary.sh`로 매 변경마다 계층 경계 위반 여부를 자동 점검 |

## 8. 쿠키 등 자동 수집 장치

사용하지 않는다. 화면 간 임시 상태 전달에 브라우저의 `sessionStorage`만 쓰며, 이는 이용자 브라우저 안에만 남고 서버로 전송되지 않는다. 광고·추적 목적의 쿠키는 없다.

## 부록 — 법적 근거 대조

이 방침의 세부 설계 근거는 `docs/compliance-mapping.md`(§13 규제 매핑표)에 조항별 출처·확인일과 함께 정리돼 있다. 핵심만 요약하면:

- 나이·거주지 등 **준식별자도 개인정보 보호법상 개인정보에 해당할 수 있다** (PIPA 제2조 1호 나목) — 그래서 개발 데이터 전량을 합성으로 만들었다
- **수집 자체가 처리행위**다 (PIPA 제2조 2호) — 그래서 무동의 실데이터를 애초에 모으지 않는다
- 외부 LLM 전송은 **제17조(제3자 제공)/제26조(위탁)**의 실질에 따라 갈리며, k값 기반 위험도 등급(`VERY_HIGH`/`HIGH`/`ACCEPTABLE`/`UNKNOWN`)을 가명정보 처리 가이드라인의 위험도 기반 체계와 방향을 맞췄다
- AI 기본법 고영향 AI 해당 여부는 **미정**으로 유보하되, 투명성 의무(판단 근거 제시·기권 표시)는 현재 설계가 이미 충족하는 방향이다

법적 결론은 단정하지 않는다 — 각 조항은 "~에 해당할 수 있어 ~로 설계했다"는 형태로만 쓴다 (팀은 변호사가 아니다).
