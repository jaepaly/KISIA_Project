| ☐ | 폴백 파일 | export JSON · 영상 파일 위치 확인 |
| ☐ | 화면 | 브라우저 확대 125% · 알림 끄기 · 다른 탭 닫기 |

- **목적:** 이름·전화번호가 없는 일상 글도 여러 편이 결합되면 개인의 범위가 좁혀질 수 있고, 파도풀이 위험 원인과 부담이 적은 조치를 제안한다는 것을 보여 준다.
- **기준 대본:** §2의 화면 순서와 설명을 사용한다.
- **촬영 대상:** 11/1 최종 동결 빌드
- **최종 산출물:** 11/5 팀 제출용 시연 영상 1편(공식 마감 11/6)
- **길이:** **6분 40초~7분**. 원본은 약 10~12분 촬영하고 타이핑·대기·화면 이동만 줄인다.
- **발표 연계:** 11/19 오프라인 발표도 같은 계정·화면 순서·핵심 문장을 사용한다.
- **이야기 순서:** 문제 제시 → 작성 중 단서 확인 → 계정 전체 진단 → 위험 원인 → 조치 추천 → 실제 조치 → 효과 확인.

### 5-2. 촬영 환경

AWS 사용이 중지된 동안에는 veilo.site의 온라인 분석 서버를 촬영에 사용하지 않는다. Veilo와 파도풀 분석기를 **시연 PC에서 로컬로 실행**하고, 기존 로그인·쿠키·캐시 영향을 막기 위해 **Chrome 시크릿 창**에서 접속해 녹화한다.

| 항목 | 기준 |
|---|---|
| 실행 | 시연 PC 로컬 |
| 브라우저 | Chrome 시크릿 창 · 확대 125% · 알림 끄기 |
| Veilo | `http://localhost:3000` 또는 실행 터미널에 표시된 주소 |
| 분석기 | `http://localhost:8000` |
| 엔진 | `ENGINE_MODE=real` · `STAGE2_MODE=rules` |
| 계정 | 메인 `3교대인생`(`u_8c53e7b89615`) · 예비 `옥동묵향당` |
| 예상 스캔 | 메인 계정 약 11초 · 촬영 PC에서 다시 측정 |
| 녹화 | OBS Studio · 1920×1080 · 30fps 이상 |
| 보관 | 원본·편집 프로젝트·최종본을 PC와 별도 저장공간 두 곳에 보관 |

영상 또는 설명 자료에 다음을 명시한다.

> 본 영상은 AWS 서비스 중지 기간에 촬영되어, 동일한 소스 코드와 실제 분석 엔진을 시연 PC에서 로컬로 실행한 화면을 사용했습니다.

로컬 실행은 실제 엔진을 사용하지만 공개 도메인에서 실행한 서비스 화면이라고 설명하지 않는다.

로컬 기동:

```powershell
# 터미널 1 — Veilo
$env:PADO_BASE="http://localhost:8000"
python apps/sns/app.py

# 터미널 2 — 파도풀
$env:SNS_PUBLIC_URL="http://localhost:3000"
$env:ENGINE_MODE="real"
$env:STAGE2_MODE="rules"
$env:PYTHONPATH="src"
python -m uvicorn apps.analyzer.server:app --port 8000
```

### 5-4. 장면별 촬영 대본 — 이 절만 보고 촬영

#### 공통 연출

- **형식:** 화면 녹화 + C 직접 내레이션 + 핵심 문장 자막.
- **화면:** 1920×1080, Chrome 시크릿 창, 확대 125%. 마우스 포인터는 보이게 하고 클릭할 곳에서 1초 멈춘다.
- **자막:** 하단 중앙 1~2줄, 한 줄 24자 안팎. 화면의 버튼·수치를 가리지 않는다.
- **음성:** 보통 대화보다 조금 느리게 읽고, 숫자 화면에서는 읽은 뒤 2초 멈춘다.
- **편집:** 로딩·타이핑만 줄인다. 분석 전후가 서로 다른 실행이면 연결해서 한 번에 된 것처럼 보이지 않게 전환 자막을 넣는다.
- **2단 표기 결정:** 로컬은 `STAGE2_MODE=rules`로 촬영한다. 첫 장면에 아래 안내를 4초 표시한다.

> 이 영상은 AWS 서비스 중지 기간에 동일한 소스 코드와 실제 분석 엔진을 로컬에서 실행해 촬영했습니다. 7개 항목 판정은 GPU가 없는 PC라 판단 AI 대신 규칙을 사용했습니다. 위험도·후보 수·추천 결과는 GPU 모델과 같으며, 11/1 동결 빌드에서 다시 확인했습니다.

마지막 문장의 숫자 일치가 11/1 재검증에서 확인되지 않으면 「위험도·후보 수·추천 결과의 차이는 영상 설명에 별도로 표시했습니다」로 바꾼다.

#### 촬영 전 상태

1. 저장소를 11/1 동결 커밋으로 맞춘다.
2. `seed_sns.py --reset` 또는 「⟲ 이 계정 처음 상태로」로 메인 계정을 초기화한다.
3. 「야간 3일차」·「토요일 늦잠」·「새벽 드라이브」가 공개 상태인지 확인한다.
4. 로컬 서버를 켜고 메인 계정을 한 번 스캔해 예열한다.
5. 예열 뒤 다시 초기화하고 Chrome 시크릿 창을 연다.
6. OBS에서 10초 시험 녹화 후 음성과 글자를 확인한다.
7. 장면별 파일명은 `S01_intro`, `S02_feed`처럼 저장한다.

- 로컬 주소·터미널·개인 경로는 잘라내거나 가린다.
- AWS·veilo.site 접속 실패 화면과 AWS 관리 화면은 촬영하지 않는다.

AWS와 veilo.site는 폴백으로 쓰지 않는다.

| 단계 | 방법 | 전환 조건 |
|---|---|---|
| 기본 | 시연 PC 로컬 | 정상 실행 |
| 폴백 1 | 저장한 export JSON 수동 업로드 | 로컬 계정 조회 실패 |
| 폴백 2 | 장면별 성공 녹화 | 분석기 재시작 뒤에도 오류 반복 |
| 폴백 3 | 직전 정상 편집본 | 촬영 당일 복구가 어려움 |

폴백용으로 메인 계정 export JSON, 초기 진단·추천·재계산 장면, 전체 시험 녹화본을 준비한다. 전환할 때는 「같은 분석 결과를 미리 저장한 데이터로 이어서 보여 드리겠습니다」라고 말한다.
