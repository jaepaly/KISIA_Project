# AI 보안기술개발 · 개인정보 트랙 — 프로젝트 계획서 (v2.2)

> **한 줄**: 개별 글이 아니라 **글들의 결합**에서 발생하는 개인정보 재식별 위험을 **탐지하여 정량화**하고, 그에 맞는 **최소 조치를 추천**하는 시스템.
>
> 조치는 리라이트 · 비공개 · 활동 메타 관리 중 **사용자가 고르며**, 탐지는 **외부 전송 없이 로컬에서** 수행한다.
>
> 기간 **12주** · 팀 5명 · 최종 산출물 = **동작하는 시스템 + 발표**
> (작업명: 벤치마크 `KoPrivacyLeak` / 모델 `KoPrivacyLeak-Detector` — 확정 아님)

## 1. 문제 — 조각은 무해한데, 결합이 신상을 만든다

사람들은 "주민번호·전화번호만 안 쓰면 안전하다"고 믿는다. 하지만 LLM은 **문체·맥락·활동 이력만으로** 거주지·직장·나이·가족을 추론한다(Staab et al., ICLR 2024: 인간 대비 비용 1/100·시간 1/240, top-1 **최대** 85%).

**우리는 이걸 이미 한국어 데이터로 실증했다.** 아래는 전부 자체 측정치다.

| 페르소나 | 유형 | 추론 성공 | 재식별 위험도 |
|---|---|---|---|
| R1 | 40대 남 · 등산/낚시 | **7/7** | 76.1 |
| R2 | 20대 여대생 · 덕질 | **7/7** | 83.0 |
| R3 | 30대 워킹맘 | **7/7** | 82.8 |
| R4 | 60대 여 · 손주 | **7/7** | 78.7 |
| R5 | 20대 남 · 해외 워홀 | **7/7** | 72.8 |
| R6 | 30대 여 · 지방 카페 사장 | 6/7 | 70.0 |

이름·주소를 **한 번도 쓰지 않은 글**에서 나이·성별·거주지·직장·가족·통근·소득 7속성이 나온다. 연령(20~60대)·지역(서울/지방/해외)·상황(학생/육아/은퇴/자영업)과 무관하게 재현된다.

**대표 사례(R1)**: 주소 언급 0회. "신갈저수지" "기흥호수" — **낚시터 이름 두 개**로 거주지가 용인 기흥·신갈로 특정(신뢰도 72%). 취미 정보가 곧 위치 정보가 됐다.

### 핵심 — 누적 곡선 (H3)

| 투입 글 수 | 1 | 5 | 10 | 19 |
|---|---|---|---|---|
| 추론 성공 | 4/7 | **7/7** | 7/7 | 7/7 |
| 위험도 | 26.7 | 69.2 | 71.9 | **79.7** |

**글 하나는 거의 무해하고, 다섯 개면 전 속성이 뚫린다.** 이 곡선이 이 프로젝트의 출발점이자, 조치 설계의 근거다(§2).

### 이미 방어한 반박

| 반박 | 자체 실측 대응 | 상태 |
|---|---|---|
| "추론되게 만든 걸 추론한 것 아닌가?" | **네거티브 컨트롤**: 신호 없는 글(N1) → 위험도 **8.8**, 7속성 중 6개를 스스로 기권(신뢰도 3~25) | ✅ |
| "명시적으로 써놨으니 맞힌 것 아닌가?" | **암묵-only ablation**: 명시 단서 글 제외해도 **7/7 유지**, 위험도만 10~13p 하락(R1 76.1→66.0, R3 82.8→69.9) | ✅ |
| "운 좋은 한 번 아닌가?" | **5회 반복**: 성공 속성 수 std 0.0(R1·R3), 위험도 std 0.8~4.8 | ✅ |
| "특정 모델의 특성 아닌가?" | **교차모델**(Claude vs GPT-5.5) — 기존 측정은 제외된 R7~R10 기반 | ⚠️ **R1~R6에 재실행 필요**(M1) |

> **주의**: 위 ablation 결과가 이 프로젝트 전체의 전제다. **명시적 PII를 지워도 7속성이 그대로 뚫린다.** 따라서 명시 PII 탐지기만으로는 문제가 해결되지 않는다.

## 2. 서비스 — 무엇을 어떻게 되돌리나

### 정체성 — 개인을 위한 영향평가

개인정보 보호법 제33조는 **기업에게** 개인정보 영향평가(PIA) 의무를 지운다. 시스템 도입 전에 프라이버시 영향을 미리 조사·예측하고 개선안을 도출하는 절차다. 그런데 **개인에게는 자기 데이터에 대한 영향평가 도구가 없다.**

> **우리 진단 화면 = 개인용 PIA.** Privacy by Design을 기업이 아니라 이용자 손에 쥐여준다.

### 3화면 (기존 웹앱 구조 유지)

```
스캔                    진단                       조치
내 글 불러오기    →    "AI가 추정한 당신"    →    무엇을 어떻게 되돌릴지
위험도 0~100          7속성 + 근거 + 신뢰도       추천 + 사용자 선택
```

### 조치 메뉴 — 사용자가 고른다

| 조치 | 내용 | 사용자 부담 | 확실성 |
|---|---|---|---|
| **① 리라이트** | 의미 보존하며 단서 표현만 교체 | 높음(글이 바뀜) | 잔존 단서 가능 |
| **② 활동 메타 관리** | 닉네임·아이디·위치태그·카페 지역·활동 시간대 | 중간 | 높음 |
| **③ 비공개 / 부분 비공개** | 기여도 높은 글을 비공개·기간한정 공개 | **낮음(선택만)** | **가장 확실** |
| **④ 삭제 권고** | 리라이트로도 신상이 남는 글 | 높음(되돌릴 수 없음) | 최고 |

**기존 실측이 설계 근거를 준다** — R1에서 조치 3단계 적용 시 위험도 **79 → 31 (−61%)**, R3는 **82.1 → 37.8 (−54%)**. 그리고 단계별로 보면 **②활동 메타 관리가 최저점**을 만들었고 리라이트 단독으로는 부족했다. 즉 **글을 고치는 것보다 활동 흔적을 관리하는 쪽이 효율이 높다** — 서비스가 반드시 전달해야 할 메시지다. (R1~R6 전체에서 재측정: M2)

### 추천 기본값이 필요하다

**선택지를 늘리면 선택 자체가 부담이 된다**(프라이버시 UX의 고전적 실패 지점). 그러므로:

> **먼저 추천한다** — "이 글 3개를 비공개하면 위험도 79.7 → 41. 부담 대비 효과가 가장 큽니다"
> **그다음 사용자가 바꾼다** — 다른 조치·다른 대상 선택 가능

선택권과 기본값은 충돌하지 않는다. 그리고 이 추천을 만드는 것이 §3의 모델이다.

### 왜 "몇 개만 빼면 된다"가 자명하지 않은가

H3 곡선은 **5글 부근에서 이미 포화**된다. 19개를 10개로 줄여도 79.7 → 71.9로 −7.8에 불과하다(누적 투입 곡선이라 제거 곡선과 정확히 같지는 않으나 형태는 시사적이다).

→ **무작위로 몇 개 빼는 것으로는 안 된다. 어떤 글을 빼느냐가 전부다.** 이것이 기여도 산출이 필요한 이유다.

## 3. 그래서 필요한 모델 — 로컬 기여도 엔진

### 핵심 논거 (변경 없음, 이 프로젝트의 척추)

> **프라이버시 위험을 검사한다고 사용자 글을 외부 LLM API로 전송하면, 그 도구 자체가 프라이버시 침해다.**
> 자기모순이다. 그러므로 탐지는 **로컬에서, 작은 모델로** 돌아야 한다.

### "그럼 LLM이 다 하는 것 아닌가?" — 반드시 나올 질문

| | LLM 직접 호출 | 우리 로컬 모델 |
|---|---|---|
| 외부 전송 | 있음 (**자기모순**) | **0** |
| 지연 | 수 초 | **< 300ms** |
| 글 1,000개 비용 | 감당 불가 | **triage로 70%+ 절감** |
| 글별 기여도 산출 | 글 수만큼 재호출(19글 = 19회) | **1회 추론** |

**우리 모델은 LLM을 대체하지 않는다. LLM을 부르지 않아도 되게 만들고, 꼭 불러야 할 때만 부른다.**

### 증류 구조

```
[오프라인] 합성 코퍼스 → LLM 교사가 추론·위험도·기여도 라벨 생성
                       → 로컬 모델이 그것을 예측하도록 증류
[런타임]   사용자 글  → 로컬 모델이 LLM 호출 없이 즉시
                        "이 글 빼면 −18" 산출 → 추천 생성
                      → 정밀 판정이 필요할 때만 2단 LLM (동의 시)
```

기여도를 매번 LLM leave-one-out으로 계산하면 글 수만큼 호출이 필요하다. **그것을 로컬 1회 추론으로 근사하는 것이 이 모델의 존재 이유다.**

## 4. 시스템 — 2단 하이브리드

### 역할 분담 — 경계는 "신호 탐지 vs 속성 추론"

| | 하는 일 | 담당 | 예시 |
|---|---|---|---|
| **1단** | *"여기 위험 **신호**가 있다"* | **우리 로컬 모델** | "'신갈저수지'는 지역 준식별자 / 이 문체는 세대 신호" |
| **2단** | *"따라서 이 사람은 **누구다**"* | **Claude / Codex** | "용인 기흥 거주, 40대 후반 남성" |

1단은 **KoBERT급 인코더**(110M) — 준식별자 스팬 탐지(BIO) · 문체/세대 신호 · 밈 사전 매칭 · 특정성(k-익명성 근사) · **기여도 산출**까지.
2단은 **Qwen3-4B(QLoRA 파인튜닝)** — 조각을 엮은 종합 판정 · 리라이트 생성. **기본은 로컬 Qwen3**, 외부 LLM은 동의 시에만.

**두 모델을 모두 로컬에서 돌리는 것이 "외부 전송 0"의 전제다.** 2단까지 로컬이어야 §2의 자기모순 논거가 실제로 성립한다.

**보안 제품 대응**: 1단 = IDS/EDR 탐지 엔진, 2단 = SIEM 상관분석.

### LLM의 세 가지 역할 — 프라이버시 제약이 각각 다르다

| 역할 | 시점 | 대상 데이터 | 제약 |
|---|---|---|---|
| **① 교사** | 오프라인 | **합성 코퍼스** | 없음 (실존 인물 0) |
| **② 런타임 2단** | 사용자 요청 시 | 실사용자 글 | **명시적 동의 필수** |
| **③ 평가 상한** | 실험 | 합성 코퍼스 | 없음 |

### 입력 — 플랫폼 계층과 분석 계층을 분리한다

> **v2.2 변경** — 입력 경로를 브라우저 확장에서 **자체 가상 SNS 플랫폼**으로 변경. 근거는 [DEC-001](decisions.md) / [MF-001](mentor-log.md).

시스템 입력은 **플랫폼이 아니라 스키마로 정의**한다.

```
[SNS 플랫폼 계층]   사용자의 글이 원래 있는 곳
      │              개발·검증 단계에서는 자체 가상 SNS가 이 자리를 맡는다
      │ 입력 어댑터   (실서비스에서는 네이버·인스타 등이 온다)
      ↓
   { post_id, body, created_at, activity_meta{nickname, geo_tag, post_time} }
      │
[분석 계층]         ← 우리 제품. 사용자 측 실행. 외부 전송 0 (§4 원칙 1)
   1단 스팬 탐지 → 특정성 → 누적·기여도 → 2단 종합 판정 → 조치 추천
```

**이 분리가 §2 자기모순 논거의 성립 조건이다.** 가상 SNS는 *우리가 제공하는 서비스*가 아니라 *사용자 데이터가 존재하는 플랫폼 자리를 대신하는 실험 환경*이며, 분석은 여전히 사용자 측에서 수행된다. 두 계층을 한 서버에 합치면 이 논거가 깨진다.

| 어댑터 | 상태 | 용도 |
|---|---|---|
| **가상 SNS 플랫폼** (⑦) | 개발·시연 주 경로 | 글 작성·목록·프로필·활동 메타. 합성 코퍼스 시딩으로 GT 완전 통제 |
| **수동 업로드** | 최소 기능 | 텍스트·파일 입력. **M4 외적 타당성 검증(§6)이 이 경로로 수행된다** |
| 플랫폼별 수집 확장 | 범위 밖 | 향후 실서비스 이관 시 (§12 제약 참조) |

**왜 자체 플랫폼인가.** ③누적·기여도 엔진은 *"같은 사람의 글 여러 편"*이라는 구조 없이는 학습도 평가도 불가능하다(§6). 특정 플랫폼의 에디터 확장은 **작성 중인 글 외 기존 게시글 접근이 보장되지 않아**, H3 누적 곡선(1편 26.7 → 5편 69.2 → 19편 79.7)과 글 단위 한계 기여도를 시연할 수단이 사라진다. 즉 수집 경로 제약은 편의성이 아니라 **핵심 컴포넌트의 검증 표면**에 관한 문제다.

부수 효과 — 결과물이 특정 플랫폼 전용으로 한정되지 않고, 발표 시연이 외부 서비스의 로그인·네트워크·UI 변경에 의존하지 않으며, 데모용 실계정 운영 부담(구 §6)이 소멸한다.

### 설계 원칙

1. **로컬 우선** — 기본 경로는 외부 전송 0.
2. **외부 LLM은 명시적 동의 시에만, 그 경우에도 가명화 후 전송.**
   ※ v1의 "가명화 후 **or** 동의 시"를 **and**로 수정. 근거: 자체 ablation에서 명시 단서를 지워도 7속성이 그대로 뚫리고 위험도 66~70이 잔존한다. **가명화는 면책이 아니라 최소화 조치다.**
3. **탐지기의 목표는 "맞히기"가 아니라 "놓치지 않기"** — 재현율 중심. 최종 신상을 단정하지 않는 것이 방어 도구답고 오남용도 적다.
4. **밈·유행어는 모델이 아니라 사전(시그니처 DB)** — 파일 교체로 갱신, 재학습 불필요.
5. **민감 속성 미추론** — 학력·지적 수준·정치성향·건강은 대상에서 제외. "직업군 관련 전문 어휘 노출" 정도로 중립화.

### 규제 위험도 체계와의 정렬

원칙 1·2는 취향이 아니다. 개인정보위 **가명정보 처리 가이드라인**은 2026년 4월 **위험도 기반 체계**로 전면 개정되어, *"누가 활용하는지 · 어떤 환경에서 처리되는지"*로 위험도를 구분한다(동일 처리자 내부 = 저위험, 제3자 제공 = 중·고위험). 우리 2단 구조가 이 체계를 그대로 구현한다 — 상세는 §13.2.

## 5. 만들 것 (컴포넌트)

| # | 컴포넌트 | 내용 | 담당 |
|---|---|---|---|
| ① | **준식별자 탐지 모델** | 인코더 파인튜닝. 스팬 탐지(BIO) + 유형 분류. **위험도 회귀는 제외** | B |
| ② | **특정성 엔진** | 행정구역 계층·인구 통계 → k-익명성 근사. **k값이 위험도의 법적 정박점**(§13.1) | C |
| ③ | **누적·기여도 엔진** ⭐ | 사용자별 단서 집합 유지, 글/문장별 **한계 기여도**, 조치 후 재계산 | C·D |
| ④ | **가명화 + 2단 추론 모델** | 치환·복원(②의 역함수), **Qwen3 파인튜닝(QLoRA)** — 구조 판정·리라이터, triage | D |
| ⑤ | **데이터셋·벤치마크** | 합성 코퍼스 생성, 교사 자동라벨, 골드셋 검수 | A |
| ⑥ | **시스템·데모·평가** | 웹앱, 통합, 벤치마크 러너, 발표 | E |
| ⑦ | **가상 SNS 플랫폼 + 입력 어댑터** | 글 작성·목록·본문·프로필·활동 메타를 갖춘 SNS 형태 웹 서비스. 합성 코퍼스 자동 시딩, 수동 업로드 경로, 에디터 실시간 경고 | E |

**⭐ ③이 프로젝트의 얼굴이다.** 글 단위 스팬 탐지는 흔하지만, **사용자 단위 누적 + 한계 기여도**는 드물고 주제와 직결된다. 기술적으로는 leave-one-out / Shapley 스타일의 *marginal contribution to re-identification risk*.

### ①에서 위험도를 분리한 이유

스팬의 위험도는 **문맥 의존적**이다 — "신갈저수지"는 단독으로는 무해하고, "기흥호수"와 결합해야 거주지가 된다. 같은 스팬에 문맥마다 다른 위험도를 라벨하면 일관성이 무너지고 F1이 무의미해진다.

→ **① = "이것은 지역 준식별자다"(문맥 무관, 라벨 일관), ②③ = "이 조합이 몇 명으로 좁히나"(위험도 담당).**

### ②와 ④는 같은 사전을 쓴다

`상도동 → [서울의 특정 동]`(가명화, ④)과 *"이 지명은 몇 명으로 좁히나"*(특정성, ②)는 **동일한 행정구역 계층 사전**을 요구한다. **가명화기 = 특정성 엔진의 역함수.** C·D가 사전을 공유하도록 설계한다.

## 6. 데이터 — 전량 합성

### 왜 수집하지 않는가

1. **위협은 이미 실증됐다** — 다시 증명할 필요가 없다.
2. **무동의 수집은 이루다 사건의 구조** — 개인정보위 과징금·과태료 1억 330만원. 수집도 처리행위(PIPA 제2조 2호)이므로 사후 마스킹으로 치유되지 않는다.
3. **벤치마크를 공개하려면 합성이어야 한다** — 무동의 수집 데이터로 만든 데이터셋은 공개 자체가 이루다의 깃허브 공개와 같은 사안이 된다. `KoPrivacyLeak`을 공개 벤치마크로 낼 수 있느냐가 여기서 갈린다.
4. **GT가 완벽하게 통제된다** — 합성은 설계 시점에 정답이 확정되므로 자동 채점이 가능하다.

### 코퍼스 구성

| 층 | 내용 | 규모 | 용도 |
|---|---|---|---|
| **합성 페르소나** | 1인칭 서사 · 인물당 15~30글 · GT 7속성 | 3,000~5,000글 | 학습·평가 주력 |
| **네거티브 컨트롤** | 신호 없는 일상글 | 전체의 10~15% | 과탐 억제 |
| **명시 PII 보강** | 공개 NER 코퍼스 + 합성 PII 삽입 | 별도 | 명시 레이어 (도메인 무관) |

**교사 라벨은 두 종류다** — 학습 대상 모델이 둘이기 때문이다.

| 라벨 | 내용 | 학습 대상 |
|---|---|---|
| **스팬·위험도 라벨** | 준식별자 스팬 + 유형 + k | **KoBERT**(1단) |
| **종합 판정·리라이트 라벨** | 조각을 엮은 특정 결과 + 리라이트 쌍 | **Qwen3**(2단) |

**필요한 것은 "블로그"가 아니라 구조다**: ① 1인칭 개인 서사 ② 한 사람당 여러 편 ③ GT 속성. ③누적 컴포넌트는 "같은 사람의 글 여러 편"이라는 구조 없이는 학습도 평가도 불가능하다.

생성 기준은 기존 `REALISM_GUIDE.md` + `realism_samples/`(비식별 톤 참조 카드)를 그대로 사용한다.

**순환 편향 방지**: 생성 모델과 추론(교사) 모델을 분리하고, 핵심 단서 배치는 사람이 검수한다.

### 데모 데이터 — 가상 SNS 시딩 (v2.2 변경)

> **구 「데모용 블로그 — 실제 계정 + 합성 내용」을 대체한다.** 팀원 실계정 수동 게시(20편 ≈ 1인 하루), 발행일 소급 불가 대응, 발표 후 비공개 전환 절차가 모두 소멸했다.

발표 시연은 **자체 가상 SNS 플랫폼(⑦)에 합성 페르소나 글을 시딩**해서 진행한다.

| 항목 | 내용 |
|---|---|
| 데이터 | 합성 코퍼스에서 페르소나 1~2명 선별 (실존 인물 0) |
| 게시 방법 | **시딩 스크립트 자동 투입** — 수작업 없음 |
| 작성 시각 | **임의 지정 가능.** 실플랫폼과 달리 소급 제약이 없어 *"작성 시각도 단서"*(심야=육아 등) 항목을 그대로 시연할 수 있다 |
| 활동 메타 | 닉네임·위치태그·작성 시간대를 필드로 보유 → **조치 3종 중 효과 1위인 "활동 메타 관리"를 시연 가능** |
| 발표 후 | 별도 조치 불필요 (외부 공개 계정이 아님) |

**구 설계 대비 이득 2건.** ① 발행일 소급 불가로 약해졌던 *작성 시각 단서*가 복구된다. ② 활동 메타가 조작 가능한 필드가 되어, 실측에서 **위험도 감소 폭 1위였던 활동 메타 관리 조치**를 화면에서 직접 보여줄 수 있다.

**한계는 명시한다.** 가상 플랫폼이므로 *"실제 서비스 환경 그대로"*라는 주장은 하지 않는다. 그 자리는 **수동 업로드 경로 + M4 동의 실블로거 검증**이 맡는다(아래 데이터 원칙).

### 데이터 원칙 — 개발은 전량 합성, 검증만 동의 실데이터 (확정)

| 단계 | 데이터 | 이유 |
|---|---|---|
| **M1~M3 개발·학습** | **전량 합성** | GT 완벽 통제 · 윤리 청정 · 벤치마크 공개 가능 |
| **M4 외적 타당성 검증** | **동의받은 실블로거 10~20명** | *"합성에서만 되는 것 아닌가"*에 직접 답 |

**왜 이 순서인가**

1. **학습에는 수천 글이 필요하지만 검증에는 10~20명이면 충분하다** — 동의 취득 부담이 한 자릿수로 줄어든다.
2. **M4 시점엔 로컬 모델이 완성돼 있다.** 동의자의 글을 **외부 LLM에 보내지 않고 로컬에서만** 처리해 검증할 수 있다 — 시스템이 자기 원칙(§4 원칙 1)을 지키면서 스스로를 검증한다. 개발 초기에 실데이터를 썼다면 불가능했을 방식이다.
3. 개발 전 과정이 합성이므로 **검증이 무산돼도 프로젝트는 그대로 성립한다**(아래 5중 방어).

**검증 프로토콜** (E 담당 · 준비 M3 / 실행 M4 초)

- **모집**: 팀원 지인·학내 커뮤니티. 3년 이상 운영한 공개 블로그 보유자
- **동의**: 서면 동의서 — 목적·범위·보관기간·파기 방법·철회권 명시
- **처리**: **로컬 전용, 외부 API 전송 0**. 발표는 익명·집계만
- **파기**: 분석 종료 즉시 원본·중간산출물 전부
- **일정 분리**: 모집·동의서 준비는 M3(공수 낮음), 수집·분석은 M4 초 — 발표 준비와 겹치지 않게

**얻는 것 — 윤리적 일관성이 곧 주장이 된다**

> 프라이버시 도구를 만들면서 **무동의 개인 데이터를 단 한 건도 쓰지 않았다.**

§13 컴플라이언스와 맞물려 이루다 사건(수집 데이터의 목적 외 이용 → 과징금·과태료 1억 330만원)과 명확히 대비된다. 벤치마크 `KoPrivacyLeak`을 **공개할 수 있는** 것도 여기서 나온다.

**M3까지의 외적 타당성 방어 (검증 무산 시에도 유지)**

M4 검증 전까지, 그리고 검증이 무산될 경우에도 다음 5중으로 방어한다.

| 방어 | 내용 | 상태 |
|---|---|---|
| ① 설계 근거 | 합성 코퍼스는 `REALISM_GUIDE.md` + `realism_samples/`(실제 글 10종의 비식별 분석 카드)에서 **역설계**된 것 — 임의 창작이 아님 | 보유 |
| ② **분포 검증** | 문장 길이·어휘 다양성(TTR)·오타율·이모지 빈도 등 표층 통계를 **공개 한국어 코퍼스와 비교** | **M1 신규** |
| ③ 네거티브 컨트롤 | 신호 없는 글 → 위험도 8.8, 7속성 중 6개 기권 — *"심어둔 걸 찾은 것"*이 아님 | 보유 |
| ④ 암묵-only ablation | 명시 단서 제거해도 7/7 — *"대놓고 쓴 걸 맞힌 것"*이 아님 | 보유 |
| ⑤ 교차모델 | 두 모델이 독립적으로 일치 — 특정 모델의 아티팩트가 아님 | M1 재실행 |

**한계는 먼저 밝힌다.** 합성 코퍼스는 실제 블로그보다 **단서 밀도가 높을 수 있다.** 따라서 위험도의 **절대 수치**는 실제 분포에서 달라질 수 있다. 우리가 주장하는 것은 *"정확히 이만큼 위험하다"*가 아니라 **"결합하면 추론된다는 현상"과 "조치가 위험을 낮춘다는 방향"**이다. 이 한계를 발표에서 선제적으로 명시한다.

|---|---|---|---|
| **A** | 데이터 리드 | **W1~W4** → W8~ 발표·문서 리드 | **합성 생성 파이프라인**, 교사 자동라벨, 라벨 품질관리, 분포 검증 |

| **C** | 특정성·누적 | **W3~W9 (지속)** | 지명 계층 사전, k-익명성, **누적·기여도** |

**PM은 A~E 중 한 자리를 겸한다** — 주 3~4시간의 취합·편집 부하가 더해지고 산출물 주차에는 2배가 된다. 겸임 자리는 *역할 피크와 문서 마감 주차(W1·W2·W4·W8·W10·W11·W12)의 충돌*을 기준으로 팀 합의로 정한다(README 참조).

**M1(W1~W3)은 전원이 A를 돕는다** — 코퍼스 3,000글에 노이즈 70~80%를 유지하려면 페르소나가 100명 이상 필요하고, 이는 1인으로 불가능하다. 배려가 아니라 산술이다.

**C·D는 ②④에서 같은 사전을 공유**하므로 2주차 인터페이스 합의에 함께 들어간다.

**E의 컴플라이언스는 별도 워크스트림이 아니다** — M1에 기준을 한 번 정리해 §13을 확정하고, 이후에는 평가 지표(§10)와 동의 플로우(§4 원칙 2)에 녹아 유지된다. 코딩 부하가 낮아 M1 겸임이 가능하며, k 임계값만 C와 공동으로 정한다.

### GPU — 학습 VRAM과 추론 VRAM은 다른 문제다

**학습 코퍼스가 전량 합성이므로(§6) 학습은 클라우드에서 해도 프라이버시 이슈가 없다.** 로컬이어야 하는 것은 **추론**뿐이다(§2의 자기모순 논거는 *사용자 글*에 관한 것). 따라서 모델 크기를 우리 개발 장비 사양으로 미리 묶을 이유가 없다.

| | 어디서 도는가 | 제약 |
|---|---|---|
| **학습** | 팀 GPU 또는 **클라우드**(Kaggle·Colab) | 합성 데이터 → 외부 실행 가능 |
| **추론** | **사용자 PC** | ← 여기가 진짜 제약 |

**추론 기준 (제품 요구사항)**

| 모델 | 4bit 추론 VRAM | 대상 |
|---|---|---|
| Qwen3-4B | ~3GB | 일반 노트북 |
| Qwen3-8B | ~6GB | 게이밍 PC급 |

**학습 기준**

| 모델 | 담당 | 방식 | RTX 3060 12GB |
|---|---|---|---|
| KoBERT / KoELECTRA (110M) | **B** | full fine-tuning | 여유 (배치 32, 수 시간) |
| Qwen3-4B | **D** | QLoRA (4bit) | 가능 — 8GB 내외 |
| Qwen3-8B | D | QLoRA + gradient checkpointing | 빠듯 — 배치 1, 10~12GB |

- **Qwen3는 full fine-tuning 불가** — 3060에서는 LoRA/QLoRA만 성립하며, 클라우드로 가도 QLoRA가 기본이다.
- **크기는 M1에 측정해서 정한다.** 파인튜닝 전에 **프롬프트만으로 1.7B / 4B / 8B 베이스라인**을 R1~R6에 재고 외부 LLM 상한(이미 6~7/7 · 70~83)과 비교한다. 4B 프롬프트만으로 5/7이 나오면 파인튜닝 후 7/7이 현실적이고, 3/7이면 8B로 상향한다. 판정 기준은 §10의 *"Qwen3 vs 외부 LLM 일치율 ≥ 0.8"*.
- **GPU는 B·D 2대 권장.** 미확보 시 Kaggle 무료 GPU(주 30h × 계정)로 보충하되, 세션 제한 때문에 **체크포인트 저장·재개를 전제로** 설계한다.
- 나머지 3명(A·C·E)은 CPU 작업.

**2단이 소형 모델로 충분할 것이라는 가설**: 2단은 raw text가 아니라 **1단이 뽑아준 스팬·유형·k값**을 받는다. 자유 추론이 아니라 구조화 입력 → 구조화 출력이므로 증류에 유리하다. Qwen3가 전 크기에서 thinking mode를 지원하는 것도 소형에 유리하게 작용한다.
**단, 리라이트 품질과 흩어진 단서의 multi-hop 종합이 먼저 무너질 지점**이므로 가정하지 말고 M1 측정으로 확인한다.

| **조치 효과** | 조치 후 LLM 추론 정확도·위험도 하락 (기존 −54~61% 수준 재현) |
| **선택지별 트레이드오프** | 리라이트/비공개/메타관리 각각 (효과, 부담) 곡선 제시 |

### 모델 지표 (부 지표)

| 항목 | 목표 |
|---|---|
| **기존 도구 대비 추가 탐지율** ⭐ | Presidio·korean-pii가 놓치는 준식별자 중 우리가 잡는 비율 |
| 스팬 탐지 F1 (명시) | ≥ 0.80 |
| 스팬 탐지 F1 (암묵) | ≥ 0.60 — **단, M1 IAA 측정치를 상한 기준으로 재조정** |
| 위험도 상관 (모델 vs LLM 공격 성공률) | Spearman ≥ 0.7 — **단위는 글 또는 윈도우**(페르소나 단위 n≈13은 통계적으로 취약) |
| **위험도의 법적 정박** ⭐ | 점수가 **k-익명성 등급으로 해석 가능**할 것 (k≤2 매우높음 / 3~4 높음 / ≥5 통상 허용) — §13.1 |
| **Qwen3 vs 외부 LLM 일치율** ⭐ | 2단 종합 판정에서 **속성 적중 일치 ≥ 0.8** — 이게 안 나오면 "외부 전송 0"이 성립하지 않는다 |
| Triage 효율 | LLM 토큰 70%+ 절감하며 재현율 ≥ 0.9 |
| 적대적 견고성 | 회피 리라이트 후 재현율 하락 ≤ 15%p |
| 지연 | 글 1건 로컬 탐지 < 300ms (CPU) |

⭐ **모델 트랙의 1순위 숫자.** 문헌상 Presidio류 정규식 기반은 암묵적 식별자를 탐지하지 못하므로, 이 격차가 곧 프로젝트의 존재 이유가 된다.

## 11. 관련 연구와 차별점

| 선행 | 무엇인가 | 우리와의 차이 |
|---|---|---|
| **Staab et al. (ICLR 2024)** | LLM의 속성 추론 위협 실증 | 위협 증명까지. **탐지·완화 시스템 없음** |
| **KDPII** | 한국어 **대화체** PII 비식별 데이터셋 | 대화체 · PII 비식별 · 발화 단위 ↔ 우리는 **1인칭 서사 · 준식별자 추론위험 · 사용자 단위 누적** |
| **TAB** | 직접/준식별자 주석 가이드라인(영어권) | **스키마를 차용**하여 한국어·블로그 도메인으로 확장 |
| **Presidio / korean-pii** | 명시 PII 탐지·마스킹 | 정규식·NER 기반, **암묵 식별자 미탐지** → 우리의 베이스라인 |
| **AgentStealth 등 익명화 연구** | 텍스트 재작성 | 단일 텍스트 대상 ↔ 우리는 **누적 이력 + 기여도 기반 조치 선택** |

**요약**: 위협 실증(Staab)과 PII 비식별(KDPII·Presidio)은 있으나, **"한 사용자의 글 이력 전체에서 결합 위험을 계산하고 최소 조치를 추천하는" 시스템은 없다.**

## 13. 컴플라이언스 — 설계에 내장 (담당: E)

> **원칙**: 컴플라이언스를 사후 점검이나 별도 워크스트림으로 만들지 않는다. **설계 정당화**로 쓴다. M1에 기준을 한 번 정리하고, 이후에는 지표(§10)와 아키텍처(§4)에 녹아 유지된다.

### 13.1 위험도의 법적 정박

자체 가중합 점수(0~100)만으로는 *"왜 76.1이 위험한가"*에 답할 수 없다. ②특정성 엔진의 **k값**을 규제 실무 기준에 대응시켜 **해석 가능한 점수**로 만든다.

| k값 | 의미 | 위험 등급 |
|---|---|---|
| k ≤ 2 | 개인 특정 가능 | **매우 높음** |
| k = 3~4 | 소수로 좁혀짐 | 높음 |
| k ≥ 5 | 집단 내 익명 | 통상 허용 수준 |

근거: 개인정보위 **가명정보 처리 가이드라인**의 적정성 검토 절차(식별 위험성 → 가명처리 방법·수준의 적정성 → 재식별 위험성 검토).

→ 점수가 *"우리가 정한 숫자"*에서 *"규제 기준에 대응하는 숫자"*가 된다.
※ **k 임계값 확정은 C와 공동**(②의 산출물이므로).

### 13.2 아키텍처 = 규제 위험도 체계

가명정보 처리 가이드라인은 2026년 4월 **위험도 기반 체계**로 전면 개정되어, 복잡한 위험요인 나열 대신 *"누가 활용하는지 · 어떤 환경에서 처리되는지"*로 위험도를 구분한다.

| 우리 아키텍처 | 규제상 위치 | 우리 조치 |
|---|---|---|
| **1단 로컬 처리** (외부 전송 0) | 동일 처리자 내부 환경 · **저위험** | 기본 경로 |
| **2단 외부 LLM 전송** | 제3자 제공 · **중·고위험** | **명시적 동의 + 가명화 후** |

§4 설계원칙 2에서 `or`를 `and`로 바꾼 것은 이 체계와의 정렬이다. 그리고 자체 실측이 이를 뒷받침한다 — **가명화만으로는 면책되지 않는다**(명시 단서 제거 후에도 7속성 유지, 위험도 66~70 잔존).

### 13.3 근거 법령

| 조항 | 우리 프로젝트에서의 의미 |
|---|---|
| **PIPA 제2조 1호 나목** | *"다른 정보와 쉽게 결합하여 알아볼 수 있는 정보"* = **준식별자도 개인정보**. 결합 용이성은 **입수 가능성·시간·비용·기술**로 판단 → **LLM이 그 문턱을 무너뜨렸다**는 것이 이 프로젝트의 법적 존재 이유 |
| PIPA 제2조 2호 | **수집도 처리행위** → 사후 마스킹이 무동의 수집을 치유하지 못함 (§6 합성 전량화의 근거) |
| PIPA 제28조의2 | 가명정보 특례 — 추가정보 분리보관·재식별 금지가 전제 |
| PIPA 제33조 | 개인정보 영향평가(PIA) — 기업 의무. 우리 진단 화면은 그 **개인용 버전**(§2) |
| 대법원 2014다235080 | 공개된 개인정보도 **이익형량 대상** — *"공개했으니 써도 된다"*는 성립하지 않음 |

### 13.4 AI 기본법 — 검토 항목 (결론 미정)

「인공지능 발전과 신뢰 기반 조성 등에 관한 기본법」이 **2026년 1월 22일 시행**되었고, 개정법이 7월 21일 시행되었다. 한국은 AI 규제를 전면 시행한 첫 국가다. **고영향 AI·생성형 AI 사업자에 투명성 확보 의무**가 부과된다.

**M1에 검토할 것 — 미리 단정하지 않는다:**
- 우리 시스템이 **고영향 AI**에 해당하는지 (시행령 세부 기준 확인 필요)
- 연구·시제품 단계에서 **사업자 의무**가 적용되는지
- 적용된다면 투명성 의무(판단 근거 설명 · AI 사용 고지)를 UI에 어떻게 반영할지

※ 참고로 우리 시스템은 이미 **근거 문장 제시 + 신뢰도 표기 + 단서 없을 때 기권**을 수행하므로 투명성 요구와 방향이 일치한다(N1 대조군에서 7속성 중 6개 기권 확인).

### 13.5 유지 원칙

- **방어 도구 프레이밍** — 공격 재현이 아니라 셀프 점검. 결과물도 방어 측만 공개.
- **이중용도 통제** — 탐지기(방어)는 공개, **속성 추론기(공격) 가중치는 비공개.**
- **데이터** — 개발·학습 코퍼스는 **전량 합성**(실존 인물 0). **M4 검증 실데이터는 문서화된 서면 동의 + 로컬 전용 처리 + 분석 후 즉시 파기**(§6). 발표는 익명·집계만.
- **민감 속성 미추론** — 학력·지적 수준·정치성향·건강 제외.
