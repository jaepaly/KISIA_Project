## ⭐ 「뒤로 뺀다」가 이 스크립트의 핵심이다

`generate.py` 는 **`post_plan.trap` 을 읽지 않는다.**

```python
# generate.py — classify_posts
for c in persona.get("clue_plan", []):     # clue_plan 만 본다
    if c.get("post"): clues.setdefault(c["post"], []).append(c)
```

`clue_plan` 에 `subject: other` 항목이 없으면 **함정 글이 0편 나오고** 그 자리는 잡담이 된다. `post_plan.trap: 1` 이라고 적혀 있어도 그렇다. 검증기 산술(`noise + ambient + clue + trap == total`)은 그대로 맞아서 통과한다.

그대로 돌리면 **함정을 넣은 뒤 그 인물 글을 통째로 다시 뽑아야 한다.** 인물 하나가 30편이다.

그래서 스크립트가 매번 인물 파일을 읽어 갈라놓는다. **목록을 박아두지 않았다** — 함정이 들어오면 다음 실행에서 자동으로 앞 무리로 넘어간다.

`persona-design.md` §4-4-1 · §8 체크리스트가 요구하는 것과 같은 조건이다.

## 무엇을 보나

돌고 나면 이렇게 나온다.

```
── 결과 ─────────────────────────────────────────────
  글 1257편 · 실패 0건 · 41분 12초

── 코퍼스 합산 (쓴 글만 읽는다) ─────────────────
  인물 47명 · 글 1257편
  단서 282 · 지역 141 · 잡담 834
  노이즈 78% OK
```

| 보는 곳 | 기준 |
|---|---|
| **실패** | 0 이 아니면 사유가 같이 뜬다. 다시 돌리면 그것만 다시 뽑는다 |
| **노이즈** | **70~80%** 밖이면 코퍼스 완료 기준 미달이다 |
| 소요시간 | 첫 10분이면 실제 속도가 나온다. 아래 추정보다 이게 맞다 |

실패 사유가 **`잘림`** 이면 `--max-tokens` 를 올려야 한다. `generate.py` 는 잘린 글을 **저장하지 않는다** — 반쪽 글이 코퍼스에 들어가는 것보다 낫다.

## 속도 — 인물마다 크게 다르다

실측이 갈린다.

```
D09  (짧은 글)        2편 / 25초    12.5초/편
3-way 혼합 6편       112초         18.7초/편 (벽시계)
#16 실측 12편         88초          7.3초/편 (벽시계)
```

**글 길이가 지배한다.** D 몫 안에 장문 인물이 여섯이다.

```
D06  15편 × 3,000자     E10  30편 × 1,550자
D08  26편 × 1,150자     E11  30편 × 1,800자
E09  30편 ×   900자     E15  30편 × 3,000자
```

D 몫 전체가 **약 73만 자**다. 그래서 「1,257편 × 몇 초」로 잡으면 틀린다. **스크립트가 찍는 경과 시간을 보고 판단한다.**

병렬은 **3-way** 다. [#16](../../issues/16) 실측에서 6-way 는 포화라 오히려 느렸다.

## 배선만 확인하고 싶을 때

```bash
GEN_OUT=/tmp/gen bash scripts/generate_w03.sh --echo --smoke
```

`--echo` 는 **더미 텍스트**다. 진짜 코퍼스 경로(`data/corpus/v0/posts`)로는 스크립트가 거부한다 — 실수로 한 번 더미 189개를 만든 적이 있다.

## 넘어져 본 자리

| 무엇 | 어떻게 드러났나 |
|---|---|
| **경로 끝의 CR** | Windows 의 `python print` 가 CRLF 를 쓰고 `readarray -t` 는 LF 만 벗긴다. `--skip-invalid` 와 겹쳐 **「전원 검증 실패 → 건너뜀」으로 조용히 0편**이 됐다. `tr -d '\015'` 로 막았다 |
| **echo 로 합산 재계산** | 끝에 `--provider echo` 로 한 번 더 돌려 코퍼스 합산을 냈더니, 아직 안 돌린 인물(남의 몫·뒤로 뺀 것)에 **더미 글이 그대로 쌓였다**. 지금은 쓴 글을 읽기만 한다 |
| `_summary.json` 덮어쓰기 | 샤드 셋이 같은 파일에 쓴다. 합산을 그 파일에서 읽지 않는 이유다 |
