# 선행 자산 이관 — 출처 감사 로그

> **왜 이 문서가 필요한가.** 계획서 §7은 선행 PoC 자산 이관을 *"약 1개월치 선점"* 이라 명시했고, **12주 일정이 성립하는 근거가 그 한 줄**이다. 그런데 §1 반박표가 교차모델 항목에 *"기존 측정은 제외된 R7~R10 기반"* 이라고 달아, **파생물 오염이 이미 확인**됐다.
>
> 무엇이 R7~R10을 보고 만들어졌는지 확인하지 않은 채로 가져오면, *"프라이버시 도구를 만들면서 무동의 개인 데이터를 단 한 건도 쓰지 않았다"* 는 이 프로젝트의 최대 주장이 깨진다. 벤치마크 공개도 불가능해진다.

## ⚠️ 이관 원칙 3가지

**① `git merge` 를 쓰지 않는다.**
삭제한 파일도 히스토리에 영구히 남는다. R7~R10 파생물이 한 번이라도 히스토리에 들어가면 되돌릴 수 없다. **파일 복사 후 신규 커밋**으로만 가져온다.

**② 파일마다 출처를 3분류한다.**

| 분류 | 처리 |
|---|---|
| `R1~R6 only` | 이관 |
| `R7~R10 derived` | **폐기** |
| `mixed-unknown` | **폐기 또는 M1에 재생성** |

**③ 이 표가 그대로 4주차 설계서 「보안·윤리」 증빙이자 발표 슬라이드 1장이 된다.**

## 3. 이관 범위 — 리얼리즘 자산만

**PM 결정 (W1)**: 선행 PoC에서 가져오는 것은 **리얼리즘 자산으로 한정한다.** 실측치·페르소나 데이터·실험 결과·파이프라인 코드는 이관하지 않는다.

| 대상 | 판정 |
|---|---|
| `REALISM_GUIDE.md`, 분석 카드 | ✅ **이관 완료** (§1) |
| `poc/data/personas/` (R1~R10, N1, P1~P3) | ❌ 이관하지 않음 |
| `poc/results/` (실측 결과·그림) | ❌ 이관하지 않음 |
| `poc/pipeline/`, `poc/experiments/`, `poc/webapp/` | ❌ 이관하지 않음 |
| `HANDOFF.md` | ❌ 이관하지 않음 |

### 근거 — 안 가져오는 편이 오히려 깨끗하다

**M1에 어차피 다시 만든다.** 교차모델 검증은 R7~R10 기반이라 R1~R6로 재실행이 확정됐고(§2), 골드셋도 새 라벨 스키마로 재구축한다. **W3 이후에는 자체 측정치가 생긴다.** 선행 수치는 그때까지의 임시 근거일 뿐이다.

그리고 선행 결과물을 저장소에 두면 **"우리가 측정한 것"으로 오독될 위험**이 있다. 별도 프로젝트의 산출물을 우리 저장소에 두는 것보다, 인용 시 **"선행 PoC 자체 측정"** 으로 표기하고 원 근거는 외부 참조로 두는 편이 경계가 분명하다.

### 대신 지킬 것

- 선행 수치를 인용할 때 **반드시 "선행 PoC 자체 측정"** 을 붙인다 ([glossary.md](glossary.md) 「수치 인용 규칙」)
- **R6는 6/7**이다 (7/7은 R1~R5만)
- 교차모델은 **미완**으로 표기한다 — M1 재실행 전까지
- W3에 자체 측정치가 나오면 **인용을 자체 수치로 교체**한다

### ⚠️ 감수하는 것

12주 일정은 계획서 §7의 *"선행 자산 이관 = 약 1개월치 선점"* 을 전제로 짜였다. 코드·데이터를 가져오지 않으므로 **그 선점분이 줄어든다.** M1(W2~W3)에 처음부터 만드는 부담이 커지고, 이는 [roadmap.md](roadmap.md)의 M1 압축과 겹친다.

**W3 종료 시점에 M1 산출물이 목표에 못 미치면 이 결정을 재검토한다.** 그때는 파이프라인 코드만 선별 이관하는 선택지가 남아 있다.

