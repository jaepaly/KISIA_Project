# 멘토 피드백 원장 (Mentor Feedback Log)

> ## ⭐ 여기에는 **실제로 오간 것만** 적는다
>
> 멘토링은 Q&A가 아니다. **팀이 한 주 동안 한 일을 설명하면 멘토가 그에 대해 평가하거나 방향을 제시하는** 형태로 진행된다.
>
> 그래서 이 원장은 **「보고 → 반응」**을 기록한다. **물어볼 것을 미리 항목으로 만들어 두지 않는다.**
>
> | | 어디에 |
> |---|---|
> | 멘토링에서 **실제로 나온** 발언과 그에 대한 팀 결정 | **여기** |
> | 다음 멘토링에서 **짚고 싶은 것** | [`docs/mentoring/`](mentoring/) |
>
> **왜 나눴나.** W1에 사전 질문 5건을 항목으로 만들어 두었더니, 실제로 그 형태로 오간 적이 없어 「멘토 의견」 칸이 계속 비었다. 그러면 *아직 안 물어본 것*이 *답을 못 받은 미완료 부채*처럼 보인다. 원장이 8주차 「계획 대비 변경사항」의 원자료인 이상, 일어나지 않은 일이 섞이면 안 된다.
>
> **보고 내용이 곧 안건이다.** 방향이 필요한 논점은 질문 슬롯을 기다릴 게 아니라 **그 주 보고 안에 넣어야** 반응이 온다.

> **항목 형식**
>
> ```
> ### [MF-NNN] 제목
> - 어떤 보고에 대한 반응인가   ← 팀이 무엇을 설명했을 때 나왔나
> - 멘토 발언
> - 팀 판단 (근거)
> - 결정 / 수용여부
> - 반영위치 · 담당 · 기한
> ```

> **운영 규칙**
> - 이 파일은 **append-only**다. 기존 항목을 수정할 때는 지우지 말고 `↳ 갱신 YYYY-MM-DD` 줄을 아래에 붙인다.
> - 항목 ID는 `MF-001`부터 순번. 재사용·재번호 금지.
> - **수용여부는 4값만 쓴다**: `수용` / `부분수용` / `보류` / `미수용`.
>   → "미수용"을 쓸 수 있게 열어두지 않으면 미반영 항목이 조용히 사라진다.
> - `보류`·`미수용`에는 **사유와 재검토 예정일을 반드시** 적는다.
> - 관련 커밋 메시지에 `[MF-001]` 태그를 단다. → `git log --grep="MF-"` 한 줄로 반영 이력 전체가 나온다.
> - 이 원장이 **8주차 「계획 대비 변경사항」과 10주차 「중간 점검 이후 개선사항」의 원자료**다. 그 주에 기록하지 않으면 10주 뒤에 복원할 수 없다.

### [MF-002] 프로젝트 주제명 변경

- **제기 주체**: 멘토 지적 + 대안 제시
- **멘토 의견**
  - 제출한 주제 초안이 **길고 서술형 문장**이어서 제목으로 기능하지 않으며, 과제 내용이 명시적으로 드러나지 않는다.
  - 대안으로 「온라인 공개정보의 누적/결합에 따른 개인정보 재식별 위험 평가 및 보호조치 추천 시스템」을 제안. **다만 이 역시 추가로 다듬을 것**을 함께 권고.
- **팀 검토 의견**
  - 제출 초안은 README의 한 줄 소개를 그대로 주제란에 넣은 형태였다. 다른 팀은 모두 `[수식] + [대상] + [기능] + [결과물 형태]` 구조의 명사구를 제출했다.
  - 멘토 제안안은 **우리 안이 놓친 두 가지를 잡고 있다**: ① `결합`(우리 검토안은 누적만 담았으나, 대표 사례 "신갈저수지 + 기흥호수"는 결합이다) ② `공개정보`(PIPA §2조1호나목·대법원 2014다235080과 직결되는 법적 포지셔닝)
  - 따라서 제안안을 채택하되, 권고대로 다듬는다.
- **결정**

  | | 안 | 자수(공백 포함) |
  |---|---|---|
  | 제출 초안 | 개별 글들의 결합에서 발생하는 개인정보 재식별 위험을 탐지하여 정량화하고, 그에 맞는 최소 조치를 추천하는 시스템 개발 | 66 |
  | 멘토 제안 | 온라인 공개정보의 누적/결합에 따른 개인정보 재식별 위험 평가 및 보호조치 추천 시스템 | 48 |
  | **확정** | **개인용 프라이버시 영향평가: 공개 게시글 누적·결합 재식별 위험 진단·완화 시스템** | **45** |

  **제안안을 그대로 쓰지 않은 이유 2가지**
  - **정체성이 안 보인다.** 제안안은 *무엇을 분석하는지*는 명확하나 *누가 쓰는지*가 없다. 본 과제는 이용자 본인의 자기 점검 도구이고, 이는 PIPA §33이 기업에만 부과하는 영향평가를 개인에게 옮긴 것이다 — 계획서 §2가 서비스 정체성으로 규정한 지점이다.
  - **제3자 도구로 읽힌다.** *"공개정보 재식별 위험 평가"* 는 남의 공개정보를 평가하는 도구로도 읽힌다. §13.5 이중용도 통제(방어 도구 프레이밍 / 추론기 가중치 비공개)와 어긋날 여지를 제목 단계에서 없앴다.

  **제안안 구성요소는 전부 유지했다**
  - `공개` — PIPA §2조1호나목 · 대법원 2014다235080과 연결되는 법적 정박점. 제안안에서 가장 값이 큰 요소
  - `누적·결합` — **핵심 기전이자 기존 도구와 갈리는 지점.** 글 1편 26.7 → 5편 69.2(선행 PoC 자체 측정). 글 단위 도구로는 이 전이를 관측할 수 없다. 분석 대상이 *개별 게시글*이 아니라 *게시글의 누적·결합*임을 제목에서 명시해야 한다
  - `재식별 위험` · `진단·완화` — 주 지표가 "목표 위험도 도달에 필요한 최소 조치 수"이므로 조치 제시는 필수
  - **추가한 것은 앞머리의 `개인용 프라이버시 영향평가` 하나**이며, 이것이 위 두 문제의 답이다

### [MF-012] 탐지 성능을 정확도만으로 평가하지 마라

- **어떤 보고에 대한 반응인가**: 합성 데이터 기준으로 탐지 성능을 측정 중이고 기준이 바뀔 수 있다고 설명하는 과정에서.
- **멘토 발언**
  - 탐지 성능을 **단순 정확도만으로 평가하지 않는 것이 좋다.**
  - **F-score 등 다른 평가 기준을 함께** 보면 더 유의미한 결과가 나온다.
- **팀 판단 (근거)**
  - **1단·중단 기준은 이미 그렇게 되어 있다.** `B-detector.md` 가 스팬 F1(partial IoU ≥ 0.5)을 주 지표로 쓰고, W3 게이트도 정확도가 아니라 **미탐율**과 **도달 가능성** 두 축이다 ([#128](../../issues/128)).
  - ⚠️ **정확도로만 판정한 곳이 하나 있다 — `exp05` 모델 크기 결정([DEC-004]).** 「전체 245칸 정확도 93.5% vs 91.0%」로 4B 를 골랐다. 표본 n=35 이고 **클래스 불균형을 안 봤다.** 멘토 지적이 정확히 이 자리에 꽂힌다.
  - W4 QLoRA 평가 지표를 정할 때 **정확도 대신 속성별 F1 + 혼동행렬**로 간다. DEC-004 자체를 뒤집을 필요는 없다(①②③ 다른 축에서도 4B 가 앞섰다).
- **수용여부**: **수용**
- **반영위치**: `D-stage2.md` §7 평가 지표 · `exp05/README.md` 한계 절 · W4 설계서
- **담당**: B(1단) · D(2단)
- **기한**: W3 안에 지표 목록 확정

### [MF-013] 배포는 Vercel 보다 AWS

- **어떤 보고에 대한 반응인가**: 공모전이 **작동하는 서비스 링크**를 요구해서, GitHub Pages·Vercel 로 올리는 방안을 언급하며 무료 범위로 되는지 물었다.
- **멘토 발언**
  - 본인은 **Vercel 보다 AWS 를 직접 쓴다.**
  - Vercel 은 **사용량 제한 · 인프라 관리 · 도메인 · 백엔드/API 서버 운영** 측면에서 불편할 수 있다.
  - 최종 목표가 웹서비스이므로 **AWS 가 적절해 보인다.**
  - 개인 데스크톱에서 서버를 띄우는 방식은 **환경에 따라 장애 가능성**이 있어 심사·데모용으로 부적절하다.
  - **AWS 설정에 도움이 필요하면 지원**할 수 있다.
- **팀 판단 (근거)**
  - 우리 스택이 Flask + SQLite 라 정적 호스팅으로는 애초에 안 된다. **백엔드가 필요하다는 지적이 맞다.**
  - ⚠️ **AI 모델 연동 백엔드의 자원 산정이 안 되어 있다.** 2단이 Qwen3-4B([DEC-004])라 GPU 가 필요한데, 대회 데모에서 그걸 띄울지 API 스탑갭으로 갈지 정해지지 않았다.
  - **AWS 크레딧 금액·사용 조건을 먼저 확인**해야 계획을 세울 수 있다.
- **수용여부**: **수용**
- **반영위치**: `apps/demo/` 배포 계획 (착수 시)
- **담당**: PM · E
- **기한**: W4 (크레딧 조건 확인 후)
