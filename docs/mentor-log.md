### [MF-001] 입력·수집 경로를 브라우저 확장 → 자체 가상 SNS 플랫폼으로 변경

- **제기 주체**: 〔☐ 멘토 지적 / ☐ 팀 제안 후 멘토 동의 — **택1 표시**〕
- **논의 내용**
  - 브라우저 확장으로 네이버 블로그 에디터에 적용할 경우, **현재 작성 중인 글 외에 기존에 작성해둔 글에 접근이 가능한지 불확실**하다.
  - 결과물이 **특정 플랫폼(네이버 블로그)에 한정된 도구로 보일 수 있다.**
- **팀 판단 (근거)**
  - 수집 범위가 작성 중인 글로 한정되면, 본 과제의 핵심 주장인 **사용자 단위 누적 재식별 위험**(글 1편 위험도 26.7 → 5편 69.2 → 19편 79.7, *선행 PoC 자체 측정*)을 **시연·검증할 수 없다.**
  - 즉 편의성 문제가 아니라 **핵심 컴포넌트(③누적·기여도 엔진)의 검증 표면이 사라지는 문제**로 판단.
  - 부수적으로 플랫폼 종속성이 제거되고, 데모 환경의 GT를 완전히 통제할 수 있다.
- **결정**: 입력 경로를 **브라우저 확장 → 자체 가상 SNS 플랫폼(웹 서비스)** 으로 변경한다.

  - `docs/plan.md` §6 「데모용 블로그 — 실제 계정 + 합성 내용」 삭제 → 시딩 스크립트로 교체

### [MF-002] 프로젝트 주제명 변경

- **제기 주체**: 멘토 지적
- **멘토 의견**
  - 당초 주제명 「결합 재식별 위험 탐지·완화 시스템」이 **길고**, **'결합 재식별'이 전문용어**여서 과제의 내용이 명시적으로 드러나지 않는다.
- **팀 검토 의견**
  - '결합 재식별'은 규제·학술 영역의 용어로, 본 과제의 대상인 **일반 이용자에게 전달되지 않는다.**
  - 반면 과제의 핵심은 *"게시글이 누적되면서 개인정보가 드러난다"* 는 현상과 *"이용자가 스스로 점검한다"* 는 성격이므로, 이 두 가지를 주제명에 직접 담는 편이 낫다고 판단.
- **결정**

  | | |
  |---|---|
  | 변경 전 | 결합 재식별 위험 탐지·완화 시스템 |
  | **변경 후** | **게시글 누적 분석 기반 개인정보 노출 자가진단 서비스** |

  - **'누적 분석'** — 글 단위가 아닌 **이용자 단위 분석**이라는 차별점
  - **'자가진단'** — 기업 대상 영향평가(PIPA §33)의 **개인용 대응물**이라는 정체성
- **수용여부**: **수용**
- **반영위치**: 주제선정서 전면 · `README.md` · `docs/glossary.md` · 저장소 문서 일체 · 이후 모든 제출물
- **담당**: PM
- **기한**: **W1 (주제선정서 제출 전)**
