## 0. 이 역할이 없으면 무슨 일이 생기나

**"위험도 76점"이라는 숫자에 아무 근거가 없어진다.** 그리고 *"이 글 3개만 비공개하면 됩니다"* 라는 추천도 만들 수 없다.

B가 "여기 지역 단서가 있다"까지 찾아주면, **그게 얼마나 위험한지 계산하는 게 이 자리**다. 그리고 이 프로젝트에서 가장 독창적인 부분이기도 하다 — 글 하나에서 개인정보를 찾는 도구는 이미 많지만, **한 사람의 글 전체를 놓고 "어느 글이 위험을 만드는가"를 계산하는 건 드물다**([plan.md §11](../plan.md)).

세 사람이 이 자리의 출력을 기다린다.

| 누가 | 내 출력 없이 못 하는 것 |
|---|---|
| **D** 박재현 | 추천 엔진. 글별 기여도가 없으면 "어느 글을 빼라"를 말할 수 없다 |
| **E** 이지희 | 진단 화면의 숫자와 k 등급 배지. §13.1 법적 정박의 실물 |
| **B** 최진필 | 없다 — B는 나에게 주기만 한다. 대신 **내가 늦으면 B의 출력이 아무 데도 안 쓰인다** |

## 2. 핵심 개념 — k-익명성을 처음부터

### k가 무엇인가

**k = "이 조건에 해당하는 사람이 몇 명인가"** 그게 전부다. 논문을 읽을 필요 없다.

원래 k-익명성은 *데이터베이스 한 테이블을 공개할 때, 준식별자 조합이 같은 행이 최소 k개가 되도록 일반화하는 것*이다. 우리는 테이블을 공개하는 게 아니라 **글에서 추출한 조건이 인구를 얼마나 좁히는지**를 잰다. 그래서 정확히는 **k-익명성 그 자체가 아니라 k-익명성 근사**다.

| | 정통 k-익명성 | **우리가 하는 것** |
|---|---|---|
| 대상 | 공개하려는 데이터 테이블 | 한 사람이 쓴 글 묶음 |
| 모집단 | 그 테이블 안의 행 | **대한민국 인구 통계** |
| k의 뜻 | 같은 준식별자 조합을 가진 행 수 | 그 조건을 만족하는 **추정 인구 수** |
| 정확도 | 데이터를 세면 정확 | **추정치다. 오차가 있다** |

> ⚠️ **문서·발표에서 "k-익명성을 적용했다"고 쓰지 않는다.** **"k-익명성 근사"** 로 쓴다. 정확한 표기는 [glossary.md](../glossary.md)의 `특정성 k값`이다.
> 이걸 흐리게 쓰면 심사에서 *"모집단 정의가 뭐냐"* 한 방에 무너진다. 먼저 "추정입니다"라고 말하고 들어가면 오히려 강해진다.

### ✗ 이렇게 이해하면 안 되고 / ○ 이렇게 이해한다

| 항목 | ✗ | ○ |
|---|---|---|
| **k의 성격** | 정확한 사람 수 | **추정 인구 수.** 오차를 안고 등급을 나누는 용도 |
| **모집단** | "인터넷 사용자" 같은 모호한 집합 | **주민등록 인구통계의 특정 시점 스냅샷.** 버전을 박아 기록한다 |
| **조건 결합** | 조건마다 비율을 다 곱한다 | **축 안에서는 곱하지 않는다.** 축 사이만, 그것도 감쇠해서 (§4) |
| **지역·연령·성별** | 전국 비율을 서로 곱한다 | **교차표에서 직접 조회한다.** 독립 가정이 필요 없다 |
| **k와 위험도** | 같은 것 | **다른 출력이다.** k = 법적 등급, 0~100 = 서비스 표시 점수 (§5) |
| **목표** | 실제와 일치하는 정확한 k | **순서가 맞는 k.** 절대값이 아니라 Spearman이 지표다 (§8) |
| **실패 조건** | k가 틀리는 것 | **가정을 숨기는 것.** 가정은 출력에 실어 보낸다 |

### 왜 이게 우리 문제인가 — R1 예시

선행 PoC 자체 측정에서 R1(40대 남·등산/낚시)은 **주소를 한 번도 쓰지 않았다.** 그런데 여러 글에 흩어진 지명이 교집합을 만들었다.

| 조건이 쌓이는 순서 | 남는 인구 (개념) |
|---|---|
| "경기도" | 수백만 명 |
| "용인시" | 수십만 명 |
| "신갈저수지 집 근처" | 수만 명 |
| \+ "퇴근하고 기흥호수" (생활권 교집합) | 수천 명 |
| \+ "40대 후반 남성" | 수백 명 |
| \+ "자녀 고1·중2" | ??? ← **여기가 이 자리의 일** |

마지막 줄의 물음표를 숫자로 바꾸는 것, 그리고 **그 숫자가 어느 글에서 왔는지**를 되짚는 것이 ②③이다.

## 3. 왜 k값을 쓰나 — 법에 정박한다

자체적으로 만든 0~100 점수만으로는 *"왜 76.1이 위험한가"* 에 답할 수 없다. 심사에서 반드시 나오는 질문이다.

그래서 k값을 **규제 실무 기준에 대응**시킨다.

| k값 | 의미 | 위험 등급 |
|---|---|---|
| k ≤ 2 | 개인이 특정된다 | **매우 높음** |
| k = 3~4 | 소수로 좁혀진다 | 높음 |
| k ≥ 5 | 집단 안에 묻힌다 | 통상 허용 수준 |

근거는 **개인정보보호위원회의 가명정보 처리 가이드라인**이다. 여기에는 가명처리가 적절한지 검토하는 절차(식별 위험성 → 가명처리 방법·수준의 적정성 → 재식별 위험성 검토)가 있고, 우리 k는 그 첫 단계와 마지막 단계에 대응한다.

> 이렇게 하면 점수가 *"우리가 정한 숫자"* 에서 *"규제 기준에 대응하는 숫자"* 가 된다.
> **개인정보 트랙에서 우리 팀의 유일한 규제 차별점이다.** ([plan.md §13.1](../plan.md))

**k 임계값의 최종 확정은 E와 함께** 한다 — E가 법령·가이드라인 정리를 맡는다([E-system.md §7](E-system.md)). 내가 하는 것은 *"k를 어떻게 계산하는가"* 이고, E가 하는 것은 *"그 k를 어느 조문에 붙이는가"* 다.

> ⚠️ 등급 경계(2 / 5)는 **내가 튜닝하는 대상이 아니다.** 가이드라인 쪽 숫자다. 상관이 안 나온다고 여기를 건드리면 법적 정박이 사라진다. 튜닝은 §5의 위험도 점수 쪽에서만 한다.

## 4. k를 실제로 어떻게 계산하나 — 붕괴를 막는 4가지 규칙

**여기가 이 역할에서 제일 어려운 지점이고, 제일 많이 물어보게 될 곳이다.**

### 문제 — 조건을 곱하면 k가 0이 된다

가장 순진한 방법은 이렇다.

```
k = 전국 인구 × p(지역) × p(연령) × p(성별) × p(직업) × p(가족) × p(통근)
```

R1에 대충 넣어보면 (비율은 예시다):

```
51,000,000 × 0.00043 × 0.15 × 0.5 × 0.03 × 0.08 × 0.40  ≈  0.6
```

**k가 1보다 작아진다.** 조건 6개면 이미 붕괴한다. 그리고 이건 R1만의 일이 아니라 **누구를 넣어도 그렇게 된다.** 전부 "매우 높음"이 되면 등급이 정보를 잃고, 글별 기여도도 전부 0이 된다(이미 바닥이라 더 안 내려가므로).

**왜 틀렸나.** 독립 가정이 깨져서다. 세 가지가 겹친다.

| 원인 | 예 |
|---|---|
| **포함 관계를 곱했다** | "경기도" ∧ "용인시" ∧ "기흥구" 는 서로 독립이 아니라 **포함 관계**다. 곱하면 세 번 좁힌 셈이 된다 |
| **상관을 무시했다** | "경기 남부 거주" ∧ "제조업 생산관리직" 은 강한 양의 상관이다. 전국 비율을 쓰면 실제보다 훨씬 좁게 나온다 |
| **단서가 사실이 아니라 추정이다** | "무릎이 예전 같지 않네요"가 40대라는 보장은 없다. 확률 1로 곱하면 안 된다 |

### 규칙 4가지

> **이 4개만 지키면 붕괴는 거의 안 난다.** 코드는 [`howto/c-engine.md`](howto/c-engine.md)에 있다.

**규칙 1 — 축을 정의하고, 축 안에서는 곱하지 않는다.**

축은 우리가 다루는 **7속성 그대로**다: `location` `age` `sex` `occupation` `family` `commute` `income`.
(A의 `ground_truth` 키와 같은 이름을 쓴다 — [persona-design.md §4-1](../persona-design.md))

한 축에 단서가 여러 개면 **가장 좁은 것 하나만** 쓴다. "경기도"·"용인시"·"신갈동"이 다 나왔으면 신갈동만. 이 규칙 하나가 붕괴 원인의 절반을 없앤다.

**규칙 2 — 지역 × 연령 × 성별은 교차표에서 직접 조회한다.**

행정안전부 주민등록 인구통계는 **읍면동별 × 연령별 × 성별 인구를 이미 교차로 제공**한다. 그러니 비율을 곱할 이유가 없다. 세 축을 한 번에 조회해서 실측값을 쓴다. **독립 가정이 필요한 축이 7개에서 4개로 줄어든다.**

```
✗  51,000,000 × p(신갈동) × p(40대) × p(남)
○  population.csv 에서 (신갈동, 40-49, M) 행을 그대로 읽는다
```

**규칙 3 — 남은 축은 "신뢰도 가중 + 감쇠" 로만 곱한다.**

```
q  = 1 - confidence × (1 - p)     # 신뢰도가 낮으면 1에 가까워져 덜 깎는다
q' = q ** ALPHA                   # ALPHA = 0.6 (기본값). 상관 중복을 흡수
k  = n_base × Π q'
```

- `confidence` 는 B의 스팬 점수나 단서 등급(`explicit`/`implicit`/`inferential`)에서 온다. `inferential` 은 낮게 잡는다.
- `ALPHA` 는 **튜닝 대상이다.** 1.0이면 감쇠 없음(붕괴), 0에 가까우면 아무것도 안 좁혀짐. **0.6에서 시작해 W7 상관 측정으로 조정한다.**

**규칙 4 — 하한을 두고, 하한이 걸렸다는 사실을 출력에 남긴다.**

```python
floored = k_raw < 1.0
k = max(k_raw, 1.0)
```

`floor_applied: true` 가 출력에 실려야 한다. 이게 없으면 나중에 *"이 k는 진짜 1명이냐, 계산이 터진 거냐"* 를 구분할 수 없다.

### 규칙을 적용한 R1 (예시 — 실제 값은 W5에 측정한다)

| 단계 | 조건 | 순진한 방식 | **규칙 적용** |
|---|---|---|---|
| 시작 | — | 51,000,000 | 51,000,000 |
| 지역 | 신갈동 | 21,930 | 21,930 |
| 연령·성별 | 40대 남성 | × 0.075 → 1,645 | **교차표 조회 → 3,021** |
| 가족 | 자녀 고1·중2 (p=0.08, c=0.8) | × 0.08 → 132 | × 0.450 → **1,359** |
| 직업 | 제조업 생산관리 (p=0.03, c=0.6) | × 0.03 → 3.9 | × 0.593 → **806** |
| 통근 | 자차 출퇴근 (p=0.40, c=0.7) | × 0.40 → **1.6** | × 0.721 → **581** |
| **결과** | | **k ≈ 1.6 → "매우 높음"** | **k ≈ 581 → "통상 허용"** |

**두 숫자 중 뭐가 맞나? 모른다.** 그리고 그걸 아는 게 목표가 아니다(§8). 중요한 건 오른쪽 방식은 **글이 더 쌓이면 계속 내려갈 여지가 있고**, 왼쪽은 이미 바닥이라 **기여도 계산이 전부 0이 된다**는 것이다. ③이 동작하려면 오른쪽이어야 한다.

## 5. 위험도 0~100은 어디서 오나

**k와 위험도는 다른 출력이다.** 헷갈리면 안 된다.

| 출력 | 정의 | 용도 | 튜닝 |
|---|---|---|---|
| `k` + `level` | 조건을 만족하는 추정 인구, 그 등급 | **법적 정박**(§13.1) · 화면 배지 | ✗ 경계는 가이드라인 값 |
| `risk` 0~100 | 7속성이 각각 얼마나 좁혀졌는지의 가중합 | 화면 점수 · 누적 곡선 · 기여도의 기준값 | ○ **여기만 튜닝한다** |

### risk 계산 — 속성별 "해상도"를 점수로

선행 PoC의 0~100 위험도는 *"7속성을 얼마나 맞혔는가 + 신뢰도"* 에서 나왔다. 우리 엔진도 같은 형태로 간다 — **속성마다 얼마나 좁혀졌는지(해상도)를 점수로 바꾸고 평균낸다.**

| 축 | 0 (미상) | 1 | 2 | 3 | 4 |
|---|---|---|---|---|---|
| `location` | 0 | 시도 20 | 시군구 55 | 읍면동 85 | 시설반경 100 |
| `age` | 0 | 세대(20대) 40 | 5세 구간 70 | 생년 100 | — |
| `sex` | 0 | 특정 60 | — | — | — |
| `occupation` | 0 | 산업군 40 | 직군 70 | 직장 특정 100 | — |
| `family` | 0 | 혼인상태 30 | 자녀 유무 55 | 자녀 수·학년 85 | — |
| `commute` | 0 | 수단 40 | 경로·시간대 75 | — | — |
| `income` | 0 | 대략 구간 50 | — | — | — |

```
risk = Σ (w_axis × score_axis) / Σ w_axis        # 기본 w는 전부 1
```

**이 표의 숫자는 전부 초기값이고, W7에 상관을 보고 조정한다.** 근거 없이 정한 게 아니라 *"조정 가능하도록 한 자리에 모아둔 것"* 이다 — 코드 여기저기에 상수가 흩어지면 튜닝을 못 한다.

**말이 되는지 확인** (예시 계산):

| 대상 | 축별 단계 | risk |
|---|---|---|
| R1 19편 | loc 3 · age 2 · sex 1 · occ 2 · fam 3 · com 2 · inc 1 | (85+70+60+70+85+75+50)/7 = **70.7** |
| N1 (네거티브) | 전부 0 | **0** |

선행 PoC 자체 측정은 R1 76.1 / N1 8.8이었다. **절대값은 다르지만 방향과 간격이 맞는다.** 이 정도면 시작점으로 충분하고, W7에 가중치로 좁힌다.

> **왜 k에서 직접 위험도를 뽑지 않나.** k는 결합값 하나뿐이라 *"어느 속성 때문에 위험한가"* 를 화면에 못 보여준다. E의 진단 화면은 7속성을 각각 표시해야 한다([plan.md §2](../plan.md)). 그리고 k 하나에 로그를 씌워 0~100으로 만들면 튜닝 손잡이가 사실상 없다.

## 6. 누적과 기여도 — 이 프로젝트의 얼굴 ⭐

### 왜 이게 얼굴인가

선행 PoC 자체 측정에서 같은 사람의 글이 1편일 때 위험도 26.7이었는데 5편이면 69.2가 됐다(10편 71.9 / 19편 79.7). **글 하나하나는 무해한데 쌓이면 위험해진다.** 그러면 질문은 이거다 — *어느 글을 빼야 가장 효과가 큰가?*

우리 엔진에서는 이게 자연스럽게 나온다. **risk는 글이 아니라 "단서 집합"의 함수**이기 때문이다.

```
글 집합 S  →  S에 실린 모든 단서의 합집합  →  축별 결합  →  k, risk
```

글을 빼면 그 글에만 있던 단서가 사라지고, 축 해상도가 내려가고, risk가 내려간다. **누적 곡선과 기여도가 같은 함수에서 나온다** — 따로 만들 필요가 없다.

### leave-one-out (W5, 기본)

```
19편 전체        위험도 79.7
- b07 제외       위험도 61.7   → b07의 기여도 = 18.0
- b12 제외       위험도 72.1   → b12의 기여도 = 7.6
- b03 제외       위험도 79.2   → b03의 기여도 = 0.5
```

> ⚠️ **위 표는 출력 형식 예시다.** 79.7만 선행 PoC 자체 측정이고, 나머지 값은 W5에 우리 엔진으로 측정한다. 문서·발표에 옮길 때 실측치처럼 쓰지 않는다([RULES-DO-NOT #9](../RULES-DO-NOT.md)).

구현은 20줄이면 된다. 코드는 [`howto/c-engine.md`](howto/c-engine.md).

### ⚠️ 기여도 상위 3개를 그냥 더하면 안 된다

**이게 가장 자주 틀리는 지점이다.**

b07("신갈저수지")과 b12("기흥호수")는 **둘 다 있어야** 생활권 교집합이 만들어진다. 그런데 하나씩만 빼보면 각각의 기여도가 작게 나온다. 반대로 같은 단서가 두 글에 중복되면, 한 글만 빼도 다른 글이 그대로 받쳐서 기여도가 0으로 나온다.

| 경우 | 하나씩 뺐을 때 | 셋을 한꺼번에 뺐을 때 |
|---|---|---|
| **중복** (같은 단서가 여러 글에) | 각각 작게 나옴 | 기대보다 **크게** 떨어짐 |
| **보완** (둘이 있어야 좁혀짐) | 각각 크게 나옴 | 기대보다 **작게** 떨어짐 |

> **그래서 추천은 "상위 n개"가 아니라 그리디로 만든다.**
> 하나 빼고 → **다시 계산하고** → 다음으로 큰 걸 빼고 → 다시 계산. 목표 위험도에 닿을 때까지.
> 이 함수(`greedy_min_set`)를 D에게 넘기는 것이 W9의 몫이다.

**포화도 같은 문제를 만든다.** 선행 PoC 자체 측정의 누적 곡선은 5편 부근에서 이미 포화한다 — 19편을 10편으로 줄여도 79.7 → 71.9로 −7.8밖에 안 된다. **무작위로 몇 개 빼는 걸로는 안 되고, 어느 걸 빼느냐가 전부다.** 기여도 계산이 필요한 이유가 이것이다([plan.md §2](../plan.md)).

### ⭐ LOO는 최종 방법이 아니다 — 증류 타깃이다

**여기가 이 자리에서 가장 중요한 지점이다.** 놓치면 프로젝트의 존재 이유가 무너진다.

[plan.md §3](../plan.md)이 이렇게 못박아 뒀다.

> 기여도를 매번 LLM leave-one-out으로 계산하면 글 수만큼 호출이 필요하다.
> **그것을 로컬 1회 추론으로 근사하는 것이 이 모델의 존재 이유다.**

그리고 §8 M2는 이렇게 되어 있다 — *"③누적·기여도 엔진 v1 — **leave-one-out 기준값 산출 → 증류 타깃 생성**"*.

**즉 LOO는 정답을 만드는 도구이지 런타임에 쓰는 방법이 아니다.**

| | 오프라인 (개발 시) | 런타임 (사용자 앞) |
|---|---|---|
| 무엇 | **LOO 정답 생성기** | **1회 추론 근사기** |
| 방법 | 글 하나씩 빼고 전부 재계산. 19편이면 19회 | 글 전체를 한 번에 넣고 기여도 벡터를 한 번에 출력 |
| 속도 | 느려도 됨 | **< 300ms** |
| 하는 일 | **학습 데이터를 만든다** | 그 데이터로 학습한 모델이 예측한다 |
| 담당 | **C (나)** | 모델 학습은 B, 타깃 제공은 C |

**왜 이렇게 해야 하나.** 계획서 §3의 비교표가 우리 존재 이유다.

| | LLM 직접 호출 | 우리 |
|---|---|---|
| 글별 기여도 산출 | 글 수만큼 재호출 (19글 = **19회**) | **1회 추론** |

런타임에 LOO를 그대로 돌리면 **19회 계산**이 되고, 이 비교표가 무의미해진다. *"우리 모델은 LLM을 부를 필요가 없게 만든다"* 는 주장이 사라진다.

### 그래서 내가 만드는 것이 둘로 나뉜다

```
[W5]  LOO 정답 생성기          data/corpus/v0/gold/contribution/*.jsonl
        입력: 인물 1명의 글 전체 + 각 글의 스팬·k값
        출력: 글마다 delta (이 글을 빼면 위험도가 얼마나 내려가나)
        방법: 글 하나씩 빼고 전부 재계산. 느려도 된다
              ↓  이게 학습 데이터가 된다
[W6~W7] 근사기 검증            1회 추론이 LOO 정답을 얼마나 맞히나
        지표: 순위 상관 (Spearman) + 상위 3개 일치율
        모델 학습 자체는 B가, 타깃과 평가는 내가
```

### 근사 오차를 별도 지표로 둔다

| 지표 | 목표 | 왜 |
|---|---|---|
| **근사기 vs LOO 순위 상관** | Spearman ≥ 0.8 | 순서만 맞으면 "어느 글을 빼야 하나"는 답할 수 있다 |
| **상위 3개 일치율** | ≥ 0.7 | 추천은 상위 몇 개만 쓴다. 꼬리는 틀려도 된다 |
| 근사기 지연 | < 300ms (CPU) | [plan.md §10](../plan.md) [필수] 지표 |

> **폴백이 있다.** 근사가 안 되면 **LOO를 캐시해서 쓴다** — 사용자가 글을 추가할 때만 재계산하면 실사용에서는 견딜 만하다. 다만 그 경우 §3 비교표의 "1회 추론"을 주장할 수 없으므로, **발표에서 한계로 먼저 밝힌다.**

### 상호작용 보정 (W7~W9, 여유 시)

조합 효과를 제대로 다루려면 Shapley value — *"모든 순서로 글을 하나씩 넣어보고 평균 증가분을 그 글의 몫으로 본다"* — 가 필요하다. 정확히 계산하면 2ⁿ이라 불가능하지만, **순열을 200개쯤 무작위로 뽑아 평균내는 몬테카를로 근사**면 CPU에서 몇 초다. 코드는 [`howto/c-engine.md`](howto/c-engine.md).

> **폴백**: Shapley는 [roadmap.md §5](../roadmap.md)의 지표 3계층 어디에도 없다. **못 해도 프로젝트는 성립한다.** leave-one-out + 그리디로 [목표] 지표는 전부 채워진다. 여유가 있을 때만 손댄다.

## 7. 단계적으로 올린다 — "정답이 없는 자리"를 다루는 법

**이 자리에 교과서적 정답이 없는 건 사실이다.** B는 F1이 있고 D는 일치율이 있는데, 나는 *"k를 어떻게 정의하는 게 맞나"* 부터 정해야 한다. 불안한 게 정상이다.

그런데 **그게 결함이 아니라 이 프로젝트가 새로운 이유**다([plan.md §11](../plan.md) — 사용자 단위 누적 기여도를 하는 선행 연구가 없다). 정답이 있었으면 우리가 할 일이 아니었다.

### 판정 기준을 바꿔 잡는다

| ✗ 이걸로 판정하면 영원히 못 끝난다 | ○ 이걸로 판정한다 |
|---|---|
| k가 실제 인구와 일치하는가 | **설명 가능한가** — 심사에서 계산 과정을 한 장으로 보일 수 있는가 |
| 위험도 절대값이 맞는가 | **재현 가능한가** — 같은 입력에 같은 출력이 나오는가 |
| 통계 모델이 엄밀한가 | **순서가 맞는가** — 위험한 글이 위험한 순서로 나오는가 (Spearman) |

**절대값이 틀려도 순서가 맞으면 서비스는 성립한다.** 우리 추천은 *"위험도가 정확히 63.2입니다"* 가 아니라 *"이 글이 제일 위험합니다"* 이기 때문이다.

### 사다리 — 어디서 멈춰도 프로젝트는 선다

| 단계 | 내용 | 언제 | 여기서 멈추면 |
|---|---|---|---|
| **L0** | 동 이름 → 인구수 하나 | **W2 목~금** | 방향 확인만. 발표엔 못 씀 |
| **L1** | 지역×연령×성별 교차표 조회 | W3 | **§13.1 법적 정박 달성.** k와 등급이 나온다 |
| **L2** | 나머지 축 감쇠 곱 + 7속성 risk | W4 | 누적 곡선과 기여도가 나온다. **[필수] 지표 충족** |
| **L3** | 신뢰도 가중 · 시설→지역 매핑 | W5 | 정밀도 향상. 상관 측정 가능 |
| **L4** | Shapley · 조합 탐색 최적화 | W7~W9 | 있으면 가점. 없어도 됨 |

**매주 주간보고에 "지금 L 몇"을 한 줄로 쓴다.** 이게 있으면 진도가 보이고, 없으면 "계속 뭔가 만들고는 있다"로 읽힌다. 8주차 진행률 산정의 근거도 여기서 나온다.

### 가정을 숨기지 않는다

엔진 출력에 `assumptions` 필드를 넣고 거기에 전부 적는다.

```json
"assumptions": [
  "모집단: 주민등록 인구통계 2026-07 기준",
  "지역·연령·성별은 교차표 직접조회, 독립 가정 없음",
  "occupation·family·commute는 전국 비율 × 감쇠(alpha=0.6)",
  "직업 비율은 시도 단위 통계를 전국으로 대용함 — 과소추정 가능"
]
```

> **심사에서 가장 강한 답변은 "정확합니다"가 아니라 "이 가정을 이렇게 두었고, 여기가 한계입니다"이다.** A의 분포 검증 리포트가 같은 논리로 설계됐다([A-data.md §7](A-data.md)).

## 8. 목표 수치

| 지표 | 목표 | 계층 |
|---|---|---|
| **위험도 상관** — 우리 점수 vs LLM 추론 성공률 | Spearman **≥ 0.7** | [목표] |
| **위험도의 법적 해석 가능성** | k값이 위험 등급으로 번역됨 | **절대 사수** ([roadmap.md §6](../roadmap.md)) |
| 조치 3단계 적용 시 위험도 하락 | 선행 PoC 자체 측정 −54~61% 수준 재현 | [필수] |
| 엔진 결정성 | 같은 입력 → 같은 출력 (회귀 테스트 통과) | 내부 |

**상관을 재는 단위에 주의.** 인물 단위로 재면 표본이 10여 개밖에 안 돼 통계적으로 취약하다. **글 또는 윈도우 단위**로 잰다([roadmap.md §5](../roadmap.md)).

**윈도우 만드는 법** (W7):

```
인물별로 글을 시간순 정렬 → 앞에서부터 1, 2, 3, 5, 8, 12, 19편 누적 윈도우
인물 10명 × 윈도우 7개 = 표본 70개
각 윈도우마다  (우리 risk,  교사 LLM의 7속성 적중 수)  한 쌍
```

이러면 표본이 70개가 되고, **누적 곡선 자체가 부산물로 나온다.** 교사 LLM 호출도 70회면 되므로 크레딧 부담이 작다.

```python
from scipy.stats import spearmanr
rho, pval = spearmanr(our_risks, llm_hits)
```

> **0.7이 안 나오면** 가중치(§5 표)를 조정한다. 그래도 안 되면 **한계로 기록한다** — 억지로 맞추면 과적합이고, 이 지표는 [필수]가 아니라 [목표] 계층이다.

## 9. 다른 역할과 주고받는 것

| 상대 | 내가 주는 것 | 내가 받는 것 |
|---|---|---|
| **B** 최진필 | 위험도 계산에 필요한 유형 구분 (축 이름·해상도 단계) | 탐지된 스팬 + 유형 (`span.schema.json`) |
| **D** 박재현 | **지명 사전**(공유), k값, 글별 기여도, `greedy_min_set` 함수 | 가명화 규칙 — 서로 역함수 관계다 |
| **A** 이은선 | 지명 단서를 어느 수준까지 심을지 (사전에 있는 지명만) | 인물별 정답 속성(`ground_truth`), 코퍼스의 지명 목록 |
| **E** 이지희 | 위험도 산출 함수, `steps` 설명 배열 | 화면 표시 형식, k 임계값 법적 근거 |

### ⚠️ D와 같은 사전을 쓴다 — W2의 가장 중요한 일

`상도동 → [서울의 특정 동]`으로 바꾸는 것(D의 가명화)과 *"이 지명은 몇 명으로 좁히나"*(내 특정성 계산)는 **같은 행정구역 사전을 요구한다.** 가명화기는 특정성 엔진의 역함수다([plan.md §5](../plan.md)).

결과물은 `docs/contracts/geo-dictionary.md` — **신정현·박재현 공동 소유.** 30분만 앉으면 정해진다. 정할 것은 넷이다.

| 정할 것 | 권장안 | 왜 |
|---|---|---|
| **키를 무엇으로** | **행정코드 문자열 10자리** (`"4146310100"`) | 동 이름은 전국에서 유일하지 않다("중앙동"·"신흥동"은 여러 시군구에 있다). 그리고 **숫자로 파싱하면 앞자리 0이 날아간다** |
| **계층을 어디까지** | **읍면동까지.** 리는 안 한다 | 리까지 가면 k가 수백 명대로 떨어져 전부 "매우 높음"이 된다 |
| **가명 라벨 형식** | `[시설A·저수지]` `[경기 남부의 특정 동]` `[40대 후반]` | 2단이 **실제 지명을 몰라도** 판정할 수 있어야 한다 |
| **슬롯 규칙** ⭐ | **같은 실제 대상은 항상 같은 슬롯 문자** | `신갈저수지→시설A`, `기흥호수→시설B` 가 사용자 단위로 고정돼야 2단이 *"A와 B가 같은 생활권"* 을 판정할 수 있다. 글마다 슬롯이 바뀌면 결합 추론이 불가능해진다 |

**가명 라벨 대응표 (초안)**

| 원 표현 | 축 | kind | 가명 라벨 | 복원 키 |
|---|---|---|---|---|
| 신갈저수지 | location | `facility` | `[시설A·저수지]` | `{"slot":"A","code":"4146310100"}` |
| 기흥호수 | location | `facility` | `[시설B·호수]` | `{"slot":"B","code":"4146310300"}` |
| 신갈동 | location | `emd` | `[경기 남부의 특정 동]` | `{"code":"4146310100"}` |
| 용인시 | location | `sigungu` | `[경기 남부의 특정 시]` | `{"code":"4146300000"}` |
| 마흔여덟 | age | `age_exact` | `[40대 후반]` | `{"value":48}` |
| 고1·중2 | family | `child_grade` | `[중고생 자녀 2명]` | `{"value":["고1","중2"]}` |

> 복원은 **D의 몫**이다. 나는 사전과 대응 규칙까지만 준다. 다만 **치환 위치(오프셋)를 함께 저장해야 복원이 안 깨진다**는 건 계약에 같이 적는다([D-stage2.md §9](D-stage2.md)).

전체 초안 템플릿은 [`howto/c-public-data.md`](howto/c-public-data.md) 마지막 절에 있다 — **복사해서 D와의 회의에 들고 간다.**

> ⚠️ **세 가지 표기를 E의 계약 규약에 맞춘다** ([E-system.md §3](E-system.md) · [`howto/e-contracts.md §3-2`](howto/e-contracts.md)).
>
> | 항목 | 규약 | 왜 |
> |---|---|---|
> | 등급 값 | `VERY_HIGH` / `HIGH` / `ACCEPTABLE` / `UNKNOWN` | **한글은 코드 값이 아니라 화면 문구다.** "통상 허용"은 E가 매핑해서 띄운다 — 문구를 다듬을 때마다 남의 코드가 깨지면 안 된다 |

>
> **E의 초안(`howto/e-contracts.md §3-2`)에는 `risk` · `risk_by_axis` · `steps` · `assumptions` · `floor_applied` 가 없다.** 진단 화면이 7속성과 계산 과정을 보여주려면 그게 있어야 하므로, **W2 1:1에서 두 초안을 하나로 합친다.** 초안 두 개가 각자 살아남는 것이 최악이다.

> ⚠️ **위 두 예시는 머지된 계약을 통과하는 형태다.** 이전 판은 `user_id`·`level` 등 계약에 없는 이름을 썼다 — 계약은 `user_ref`(가명 `u_…` 형식)·`k_level`·`basis` 다. `top_spans` 는 원문 텍스트가 아니라 `{span_id, text_id}` 객체다(원문을 담으면 가명화 경계가 뚫린다). `residual_risk`(조치 후 잔여 위험)와 `user_scoped`(프로필 등 글 밖 기여분)는 **필수**다. 확인:
>
> ```bash
> check-jsonschema --schemafile docs/contracts/specificity.schema.json <출력>
> ```

> 마지막 `note` 를 계약에 박아둔다. **D가 이걸 모르면 추천 화면에 잘못된 예상치가 뜬다.**
>
> ⚠️ **부호는 `delta` — 이 글을 비공개했을 때의 위험도 변화이고, 내려가면 음수다**([E-system.md §3](E-system.md) · E의 목 엔진도 이 부호로 돌아간다). 기여도를 *"18만큼 기여"* 라는 양수로 주면 **에러 없이 반대로 추천된다.** 화면에 *"−18.0"* 을 어떻게 쓸지는 E가 정한다.
> **`greedy_path`는 E의 초안에 없다** — E의 `recompute`(`removed_post_ids` → `risk_after`)는 한 번의 재계산이고, 그리디 경로는 그 반복이다. 둘 다 필요하므로 W2 1:1에서 합친다.

**형식이 완벽할 필요 없다.** 나중에 바꾸기 어려운 것부터 정한다 — 필드 이름, 좌표 기준(문자 offset), 단위, null 처리([contracts/README.md](../contracts/README.md)). **미정으로 두는 게 제일 나쁘다.**

## 11. 막히기 쉬운 지점

### 개념

| 상황 | 대처 |
|---|---|
| k를 어떻게 정의할지 모르겠다 | **정상이다. 정의부터 만드는 자리다.** §7의 사다리대로 L0부터. 가장 단순한 버전(해당 동 인구수)에서 시작해 조건을 하나씩 추가한다 |
| 논문을 읽어야 할 것 같다 | k-익명성 개념 자체는 §2 한 문단이 전부다. **읽어야 할 논문은 없다.** 시간이 남으면 TAB 주석 가이드라인을 보되, 그건 A·B 쪽 일이다 |
| 통계를 제대로 배운 적이 없다 | 곱셈과 로그면 된다. **엄밀한 통계 모델을 만드는 게 목표가 아니다** — 등급 구분과 순서만 맞으면 된다(§7) |
| 내가 만든 숫자가 근거 없어 보인다 | 근거 없는 게 맞다. 그래서 §7처럼 **가정을 출력에 실어 보낸다.** 숨긴 상수가 근거 없는 것이고, 적어둔 상수는 설계 결정이다 |

### 데이터

| 상황 | 대처 |
|---|---|
| 파일을 열었더니 한글이 깨진다 | 대부분 CP949(EUC-KR)다. `iconv -f CP949 -t UTF-8` 또는 `pd.read_csv(..., encoding="cp949")` |
| 행정코드 앞자리 0이 사라졌다 / 지수표기가 됐다 | **엑셀로 열지 않는다.** pandas에서 `dtype=str` 로 읽는다. 이미 깨졌으면 원본을 다시 받는다 |
| 행정동과 법정동이 안 맞는다 | 인구통계는 **행정동** 기준, 행정표준코드는 **법정동**도 같이 준다. 매핑표를 만들거나, **인구통계 쪽 코드를 정본으로 삼는다**(우리에게 필요한 건 인구다) |
| 같은 동 이름이 여러 개다 | 키를 문자열이 아니라 **코드**로. 문자열 조회는 후보 목록을 반환하고, 상위 지역 단서로 좁힌다 |
| 인구통계 기준월이 파일마다 다르다 | **한 시점으로 고정하고 `dict_version` 에 박는다.** 섞으면 나중에 재현이 안 된다 |
| 시설 위치 데이터가 없다 | **주요 시설만 수동으로 30개쯤 정리해도 된다.** 합성 코퍼스에 나오는 지명은 A가 아는 목록이다 — A에게 지명 목록을 받아 그것만 매핑한다 |
| 직업·가족 비율 통계가 읍면동 단위로 없다 | 없는 게 맞다. **시도 또는 전국 비율로 대용하고 `assumptions` 에 적는다.** 이게 §4 규칙 3의 감쇠가 필요한 이유이기도 하다 |

### 엔진

| 상황 | 대처 |
|---|---|
| 조건을 곱하면 k가 0이 된다 | **§4의 규칙 4개.** 축 내부는 곱하지 않기 / 교차표 직접조회 / 신뢰도+감쇠 / 하한 클램프. 이 순서로 확인한다 |
| 반대로 k가 너무 커서 변별이 안 된다 | ALPHA를 1.0 쪽으로 올린다. 그래도 안 되면 축을 더 쓰거나 해상도 단계를 세분한다 |
| 기여도가 전부 0으로 나온다 | 두 가지 중 하나다. ① k가 이미 하한에 붙어 있다(→ 위 항목) ② 단서가 여러 글에 중복돼 있다(→ 그리디·조합 제거로 확인, §6) |
| 기여도 계산이 너무 느리다 | leave-one-out은 글 수만큼 반복이라 느릴 수 있다. **단서 집합을 키로 캐싱**하면 대부분 해결된다([`howto/c-engine.md`](howto/c-engine.md) §4). **실시간일 필요는 없다** |
| 상관이 0.7이 안 나온다 | 위험도 가중치(§5)를 조정한다. 그래도 안 되면 **한계로 기록한다** — 억지로 맞추면 과적합이고, [목표] 계층 지표다 |
| 같은 입력인데 값이 달라진다 | 딕셔너리 순회 순서·난수 시드·부동소수 누적 순서를 의심한다. **Shapley는 반드시 시드를 고정**한다. 회귀 테스트로 잡는다 |
| A의 코퍼스가 아직 안 왔다 | **선행 페르소나 R1~R6로 먼저 만든다.** 조건 몇 개를 손으로 적어 넣어도 엔진 검증은 된다. A를 기다리지 않는다 |
| D와 사전이 어긋났다 | `docs/contracts/`는 CODEOWNERS가 걸려 **변경에 2명 승인**이 필요하다. 혼자 고치지 말고 계약을 갱신한다 |

## 12. 내 산출물이 성공인지 판정하는 기준

- [ ] 행정구역 계층 사전 완성, **D와 공유됨** (`geo-dictionary.md` 머지)
- [ ] 사용한 공공데이터의 **출처·라이선스·확인일**이 `data/README.md`에 기록됨
- [ ] 지명·조건을 넣으면 k값이 나오고, **`steps` 배열로 계산 과정이 설명됨**
- [ ] k값이 위험 등급(`VERY_HIGH`/`HIGH`/`ACCEPTABLE`/`UNKNOWN`)으로 번역됨 — 한글 문구는 E가 화면에서 매핑
- [ ] 조건을 6개 이상 넣어도 **k가 붕괴하지 않음** (`floor_applied` 로 확인 가능)
- [ ] 7속성 risk가 나오고, **N1(네거티브)에서 15 미만**으로 나옴
- [ ] 글별 기여도가 계산되고, 조치 후 재계산이 됨
- [ ] **회귀 테스트 4종 통과** — 단조성 · 결정성 · 네거티브 · 붕괴 방지 ([`howto/c-engine.md`](howto/c-engine.md) §6)
- [ ] 위험도 상관 Spearman 측정 (**글 또는 윈도우 단위**, 표본 70개 이상)
- [ ] E의 화면에서 "이 글 3개 비공개 → 79.7 → 41" 형태가 뜸
- [ ] `greedy_min_set` 이 D에게 인계됨 (W9 개발 동결 전)
- [ ] 모든 수치에 **측정일 · 데이터 버전 · 엔진 버전**이 붙음
