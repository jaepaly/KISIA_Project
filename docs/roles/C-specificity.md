# C · 특정성·누적 — 작업 매뉴얼

> 담당 컴포넌트 **② 특정성 엔진** · **③ 누적·기여도 엔진** · 담당기간 **W3~W9 (지속)**
> 자원: GPU 불필요 (CPU만)

---

## 0. 이 역할이 없으면 무슨 일이 생기나

**"위험도 76점"이라는 숫자에 아무 근거가 없어진다.** 그리고 *"이 글 3개만 비공개하면 됩니다"* 라는 추천도 만들 수 없다.

B가 "여기 지역 단서가 있다"까지 찾아주면, **그게 얼마나 위험한지 계산하는 게 이 자리**다. 그리고 이 프로젝트에서 가장 독창적인 부분이기도 하다 — 글 하나에서 개인정보를 찾는 도구는 이미 많지만, **한 사람의 글 전체를 놓고 "어느 글이 위험을 만드는가"를 계산하는 건 드물다.**

---

## 1. 두 가지를 만든다

### ② 특정성 엔진 — "몇 명까지 좁혀지나"

같은 정보라도 좁혀지는 정도가 다르다.

| 단서 | 해당 인구 |
|---|---|
| "경기도 거주" | 수백만 명 |
| "용인시 거주" | 수십만 명 |
| "신갈저수지 근처" | 수만 명 |
| + "퇴근하고 들른다" (= 생활권) | 수천 명 |
| + "40대 후반 남성" | 수백 명 |
| + "자녀 고1·중2" | ??? |

이걸 **인구·행정구역 공공데이터로 수치화**한다. 결과값을 `k`라고 부르는데, *"이 조건에 해당하는 사람이 k명"* 이라는 뜻이다.

### ③ 누적·기여도 엔진 ⭐ — "어느 글이 범인인가"

이게 **프로젝트의 얼굴**이다.

우리 실측에서 같은 사람의 글이 1편일 때 위험도 26.7이었는데 5편이면 69.2가 됐다. **글 하나하나는 무해한데 쌓이면 위험해진다.** 그러면 질문은 이거다 — *어느 글을 빼야 가장 효과가 큰가?*

```
19편 전체        위험도 79.7
- b07 제외       위험도 61.7   → b07의 기여도 = 18
- b12 제외       위험도 72.1   → b12의 기여도 = 7.6
- b03 제외       위험도 79.2   → b03의 기여도 = 0.5
```

글마다 이걸 계산해서 *"기여도 높은 3개만 비공개하면 79.7 → 41"* 을 뽑아낸다.

## 2. 왜 k값을 쓰나 — 법에 정박한다

자체적으로 만든 0~100 점수만으로는 *"왜 76.1이 위험한가"* 에 답할 수 없다. 심사에서 반드시 나오는 질문이다.

그래서 k값을 **규제 실무 기준에 대응**시킨다.

| k값 | 의미 | 위험 등급 |
|---|---|---|
| k ≤ 2 | 개인이 특정된다 | **매우 높음** |
| k = 3~4 | 소수로 좁혀진다 | 높음 |
| k ≥ 5 | 집단 안에 묻힌다 | 통상 허용 수준 |

근거는 **개인정보보호위원회의 가명정보 처리 가이드라인**이다. 여기에는 가명처리가 적절한지 검토하는 절차가 있고, 그 안에 재식별 위험성 검토가 들어간다.

> 이렇게 하면 점수가 *"우리가 정한 숫자"* 에서 *"규제 기준에 대응하는 숫자"* 가 된다.
> **개인정보 트랙에서 우리 팀의 유일한 규제 차별점이다.**

k 임계값의 최종 확정은 **E와 함께** 한다 — E가 법령·가이드라인 정리를 맡는다.

## 3. 시작하는 법 — 단순한 것부터

**정답이 정해져 있지 않은 자리다.** 그래서 처음부터 완성형을 노리지 말고 단계적으로 간다.

```
W3  프로토타입    행정구역 + 인구 통계만. "이 동네 인구 몇 명"
W4  사전 구축     시/군/구/동 계층 + 시설·랜드마크 매핑
W5  기여도 v1     leave-one-out — 글 하나씩 빼보고 차이 재기
W7  검증          모델 위험도 vs 실제 추론 성공률의 상관 측정
W9  완성          조치 후 재계산, 최소 조합 탐색을 D에게 제공
```

**W3 프로토타입의 목적은 성능이 아니라 리스크 확인이다.** 이 방향이 아예 안 되는 거라면 3주차에 알아야 방향을 틀 수 있다. 그래서 가장 단순한 버전을 먼저 만든다.

### 필요한 공공데이터

- 행정구역 코드·계층 (시도 → 시군구 → 읍면동)
- 읍면동별 인구 통계 (연령대·성별 분포까지 있으면 좋다)
- 주요 시설·랜드마크 위치 (저수지·공원·역 등)

전부 공개 데이터이고 **출처와 라이선스를 기록해둔다** — 나중에 벤치마크를 공개할 때 필요하다.

## 4. 기여도를 어떻게 계산하나

가장 단순한 방법부터 시작한다.

**① leave-one-out (W5, 기본)**
글을 하나씩 빼고 전체 위험도를 다시 계산한다. 차이가 그 글의 기여도다. 글이 19편이면 19번 계산한다. 직관적이고 구현이 쉽다.

**② 상호작용 보정 (W7~W9, 여유 시)**
문제가 하나 있다. "신갈저수지"와 "기흥호수"는 **둘 다 있어야** 거주지가 좁혀진다. 하나씩 빼면 각각의 기여도가 작게 나오는데, 실제로는 둘 중 하나만 빼도 효과가 크다. 이런 조합 효과를 다루려면 Shapley value 같은 방식이 필요하다 — 다만 계산량이 급증하므로 **여유가 있을 때만** 손댄다.

> **주의**: H3 곡선을 보면 **5편 부근에서 이미 포화**한다. 19편을 10편으로 줄여도 79.7 → 71.9로 −7.8밖에 안 된다. **무작위로 몇 개 빼는 걸로는 안 되고, 어느 걸 빼느냐가 전부다.** 기여도 계산이 필요한 이유가 이것이다.

| 지표 | 목표 |

## 7. 다른 역할과 주고받는 것

| 상대 | 내가 주는 것 | 내가 받는 것 |
|---|---|---|
| **B** | 필요한 유형 구분 | 탐지된 스팬 + 유형 |
| **D** | **지명 사전** (공유), k값, 글별 기여도 | 가명화 규칙 — 서로 역함수 관계다 |
| **A** | 지명 단서를 어느 수준까지 심을지 | 인물별 정답 속성 |
| **E** | 위험도 산출 함수 | 화면 표시 형식, k 임계값 법적 근거 |

> ⚠️ **D와 같은 사전을 쓴다.** "상도동 → [서울의 특정 동]"으로 바꾸는 것(D의 가명화)과 "이 지명은 몇 명으로 좁히나"(내 특정성 계산)는 **같은 행정구역 사전을 요구한다.** 가명화기는 특정성 엔진의 역함수다. 2주차 인터페이스 합의에 D와 함께 들어간다.

## 8. 막히기 쉬운 지점

| 상황 | 대처 |
|---|---|
| k를 어떻게 정의할지 모르겠다 | **정상이다. 정의부터 만드는 자리다.** 가장 단순한 버전(해당 동 인구수)으로 시작해서 조건을 하나씩 추가한다 |
| 조건을 곱하면 k가 0이 된다 | 독립 가정이 틀렸다. 하한을 두거나 로그 스케일로 완화한다. 완벽한 통계 모델을 만들 필요는 없다 — **등급 구분만 되면 된다** |
| 시설 위치 데이터가 없다 | 주요 시설만 수동으로 정리해도 된다. 합성 코퍼스에 나오는 지명은 A가 아는 목록이다 |
| 기여도 계산이 너무 느리다 | leave-one-out은 글 수만큼 반복이라 느릴 수 있다. 캐싱하거나 근사한다. **실시간일 필요는 없다** |
| 상관이 0.7이 안 나온다 | 위험도 가중치를 조정한다. 그래도 안 되면 **한계로 기록한다** — 억지로 맞추면 과적합이다 |
| 논문을 읽어야 할 것 같다 | k-익명성 개념 자체는 어렵지 않다. *"같은 조건을 가진 사람이 k명 이상이면 개인을 특정할 수 없다"* 가 전부다 |
