# 법령·가이드라인 읽는 법 (E 실무)

> **전문을 읽지 않는다.** 조항 5개와 가이드라인의 한 절만 본다. W1~W3에 1회, 이후에는 유지.
> 배경은 [E-system.md §7](../E-system.md).

---

## 0. 왜 읽나 — 목적이 좁다

법을 공부하려는 게 아니다. **우리 설계 결정 하나하나에 근거를 붙이려는 것**이다.

| 우리 설계 | 붙일 근거 |
|---|---|
| 준식별자를 탐지 대상으로 삼는다 | PIPA 제2조 1호 나목 — *"쉽게 결합하여 알아볼 수 있는 정보"* 도 개인정보 |
| 개발 데이터를 전량 합성으로 한다 | PIPA 제2조 2호 — **수집도 처리행위**라 사후 마스킹으로 치유되지 않는다 |
| 2단 외부 전송에 동의 **and** 가명화를 요구한다 | 가명정보 처리 가이드라인의 위험도 기반 체계. ⚠️ 제공(제17조)인지 위탁(제26조)인지는 실질로 갈리고, 해외 모델이면 국외이전(제28조의8)이 별도로 붙는다 — §13.2 |
| k≤2를 "매우 높음"으로 본다 | 같은 가이드라인의 적정성 검토 절차 |
| 진단 화면을 "개인용 영향평가"라고 부른다 | PIPA 제33조 — 영향평가는 **기업 의무**이고 개인용은 없다 |
| *"공개했으니 써도 된다"* 를 인정하지 않는다 | 대법원 2014다235080 — 공개된 개인정보도 이익형량 대상 |

**이 표의 오른쪽 칸을 채우는 것이 전부다.** 왼쪽은 이미 정해져 있다.

> ⚠️ **우리는 변호사가 아니다.** 결론을 단정하지 않는다. *"~에 해당한다"* 가 아니라 *"~에 해당할 수 있어 ~로 설계했다"* 로 쓴다. 이게 방어적으로도 유리하다 — 심사에서 법 해석을 두고 다투게 되지 않는다.

## 1. 어디서 찾나

| 찾는 것 | 어디 | 요령 |
|---|---|---|
| 법률·시행령·시행규칙 조문 | **국가법령정보센터** (law.go.kr) | 조문 단위로 링크가 잡힌다. 그 링크를 문서에 그대로 붙인다 |
| 개인정보 가이드라인 PDF | **개인정보보호위원회** (pipc.go.kr) 자료실 | 검색엔진 결과는 **구버전이 먼저 뜬다.** 반드시 위원회 사이트에서 |
| 판례 | **종합법률정보** (glaw.scourt.go.kr) | 사건번호로 검색. **판결요지만** 읽는다 |
| 시행일·개정 이력 | 국가법령정보센터의 「연혁」 탭 | 어느 시점의 조문인지가 중요하다 |

### ⚠️ 버전을 반드시 확인한다

- **가명정보 처리 가이드라인은 2026년 4월에 위험도 기반으로 전면 개정**되었다. 구버전은 위험요인을 나열하는 방식이라 **우리 §13.2 논리와 안 맞는다**
- **AI 기본법**은 2026-01-22 시행, 2026-07-21 개정 시행이다
- 검색으로 받은 PDF의 **표지 발행일**을 먼저 본다

**모든 항목에 `확인일`을 적는다.** 12주 뒤 발표 때 *"그건 옛날 기준입니다"* 를 듣지 않기 위해서다.

## 2. 조문 하나에서 뽑는 것은 4가지뿐이다

| 뽑을 것 | 예 (PIPA 제2조 1호 나목) |
|---|---|
| ① **정확한 조문 번호** | 개인정보 보호법 제2조 제1호 나목 |
| ② **핵심 문구 한 문장** (원문 그대로) | *"다른 정보와 쉽게 결합하여 알아볼 수 있는 정보"* |
| ③ **우리 설계의 무엇을 정당화하나** | 준식별자도 개인정보 → 우리 탐지 대상이 법적 대상이다 |
| ④ **반박당할 지점과 우리 답** | *"쉽게 결합"의 기준은?* → 같은 조가 **입수 가능성·시간·비용·기술**로 판단하라고 한다. **LLM이 그 문턱을 낮췄다는 것이 이 프로젝트의 존재 이유다** |

**④가 가장 중요하고 가장 자주 빠진다.** ①~③만 있으면 발표에서 질문 한 번에 무너진다.

### 기록 양식 — `docs/compliance-mapping.md`

```markdown
### PIPA 제2조 제1호 나목 — 준식별자도 개인정보다

| | |
|---|---|
| **확인일** | 2026-08-26 |
| **출처** | 국가법령정보센터 (시행 20XX-XX-XX) · <링크> |
| **핵심 문구** | "다른 정보와 쉽게 결합하여 알아볼 수 있는 정보" |

**우리 설계와의 연결**
이름·전화번호가 없는 글도 탐지 대상으로 삼는 근거. 준식별자 탐지가
"과잉"이 아니라 법이 정의한 개인정보의 범위 안에 있다.

**예상 반박 / 우리 답**
> "쉽게 결합"의 기준이 모호하지 않나?
같은 조가 입수 가능성·시간·비용·기술로 판단하라고 한다. LLM은 네 가지를
전부 낮췄다 — 이것이 이 문제가 지금 새로 생긴 이유다.

**미확인**
(없으면 "없음". 있으면 그대로 남긴다)
```

**한 조항에 이 블록 하나. 5개면 끝난다.** A4 두 장을 넘지 않는다.

## 3. 읽는 순서 — 목적조항부터 읽지 않는다

법률은 앞에서부터 읽으면 시간만 간다. 이 순서로 본다.

```
① 정의조항       우리가 다루는 게 법적으로 무엇인지  → 제2조
② 우리 행위에 해당하는 의무조항                    → 제33조(영향평가)
③ 예외·특례                                      → 제28조의2(가명정보)
④ 시행령의 세부 기준   ← 법률 본문에 없는 숫자·기준은 여기 있다
```

**④를 빠뜨리기 쉽다.** 법률에는 *"대통령령으로 정하는"* 이 자주 나오고, 실제 기준은 시행령에 있다. AI 기본법의 **고영향 AI 세부 기준**이 정확히 그 경우다.

## 4. 가이드라인 PDF는 목차부터 본다

가명정보 처리 가이드라인은 100쪽이 넘는다. **다 읽지 않는다.**

1. 목차에서 **「적정성 검토」** 가 들어간 절을 찾는다
2. 그 절에서 **절차 3단계**만 뽑는다 — 식별 위험성 검토 → 가명처리 방법·수준의 적정성 → 재식별 위험성 검토
3. **우리 k 임계값을 이 절차의 어느 단계에 대응시킬지** 한 문단으로 적는다
4. **위험도 기반 체계**를 설명하는 절을 찾아 "누가 활용하는지 / 어떤 환경에서 처리되는지" 축을 확인한다

그다음 §13.2 표의 오른쪽 칸을 채운다.

| 우리 아키텍처 | 규제상 위치 | 우리 조치 |
|---|---|---|
| 1단 로컬 처리 (외부 전송 0) | 동일 처리자 내부 · **저위험** | 기본 경로 |
| 2단 외부 LLM 전송 | **제17조 제3자 제공 / 제26조 위탁 — 실질로 갈린다** · 중·고위험 · 해외 모델이면 **제28조의8 국외이전** 별도 | 명시적 동의 **and** 가명화 후 (법정 최소보다 강한 자율 조치) |

> ⚠️ **「제3자 제공」으로 단정하지 않는다** (2026-09-02 정정 · [#169](../../../../issues/169)).
> 외부 LLM 전송이 제17조(제3자 제공)인지 제26조(위탁)인지는 **계약 명칭이 아니라 실질**로 갈린다 —
> 대법원이 취득 목적·방법, 독자적 이익, 대가, 실질적 감독을 종합 판단한다고 했다.
>
> ```
> 위탁       LLM사가 우리 지시·감독 아래 추론만 하고 독자적으로 이용하지 못한다
> 제3자 제공  입력을 자체 학습·서비스 개선에 쓰거나 독자적 이익·결정권이 있다
> ```
>
> **위탁이면 동의가 아니라 위탁 사실 공개로 갈 수도 있다**(대신 위탁계약 문서화·목적 외 처리 금지·재위탁 통제).
> 그래서 우리의 「동의 **and** 가명화」는 **법이 요구하는 최소치가 아니라 그보다 강한 자율 설계**다 —
> 이 서술이 ④ 예상 반박 칸의 재료가 된다.
>
> ⚠️ **어느 LLM 을 쓸지가 안 정해져서 지금은 판단할 수 없다.** W5 통합에서 모델이 확정되면 그때 정한다.
> 매핑표에는 「검토 대상으로 식별했고 판단은 모델 확정 후」로 적는다 — 미확인을 지어내지 않는다.
>
> ⚠️ **가명정보 특례(제28조의2)는 우리 근거가 아니다.** 통계작성·과학적 연구·공익적 기록보존에
> 해당하지 않으므로 그 면제를 못 쓴다. 다만 그것이 곧 「동의 필수」를 뜻하지는 않는다 —
> 특례는 «동의 없이도 되는 경우를 넓히는» 조항이지 «동의의 근거» 조항이 아니다.
>
> ⚠️ **본인 글이라고 본인 개인정보만 있는 것이 아니다.** 가족·지인의 이름·관계·건강이 함께 실리면
> 다른 정보주체의 개인정보·민감정보도 같이 처리된다. 우리 코퍼스가 인물마다 `subject: other` 함정을
> 심어둔 것이 바로 그 상황이다.


> **k 임계값 자체는 C(신정현)와 공동으로 정한다.** ②특정성 엔진의 산출물이기 때문이다.
> E가 하는 일은 *"이 숫자가 어느 규제 절차에 대응하는가"* 를 붙이는 것이다. 숫자를 혼자 정하지 않는다.

## 5. 판례 — 요지만 본다

**대법원 2014다235080** 하나만 필요하다.

- **사건번호를 정확히 적는다.** 틀리면 신뢰가 통째로 깎인다

## 6. AI 기본법 — 결론을 미정으로 남기는 법

**단정하지 않는 것이 정답이다.** 시행령 세부 기준이 확정되지 않았거나 우리가 확인하지 못한 부분이 있으면 그렇게 쓴다.

검토할 것 3개.

| # | 질문 | 어디를 보나 | 지금 상태 |
|---|---|---|---|
| 1 | 우리 시스템이 **고영향 AI**에 해당하나 | 법률의 고영향 AI 정의 + **시행령 세부 기준** | 미정 |
| 2 | **연구·시제품 단계**에 사업자 의무가 적용되나 | 적용범위·적용제외 조항 | 미정 |
| 3 | 적용된다면 **투명성 의무**를 화면에 어떻게 반영하나 | 투명성 확보 의무 조항 | 방향은 이미 일치 |

3번은 이미 답이 반쯤 나와 있다 — 우리 시스템은 **근거 문장 제시 + 신뢰도 표기 + 근거 없을 때 기권**을 수행한다. 선행 PoC 자체 측정에서 신호 없는 글에 대해 7속성 중 6개를 스스로 기권했다. **투명성 요구와 방향이 일치한다**고 쓸 수 있다.

### 미정을 쓰는 법

```markdown
**AI 기본법 적용 여부 — 미정 (2026-08-26 기준)**

고영향 AI 해당 여부는 시행령의 세부 기준 확인이 필요해 결론을 유보한다.
다만 해당할 경우를 가정해도 투명성 의무(판단 근거 설명·AI 사용 고지)는
현재 설계가 이미 충족하는 방향이다 — 근거 문장 제시, 신뢰도 표기,
근거 부족 시 기권.

→ 멘토 확인 필요 (W3 멘토링 안건)
```

**"미정 + 그래도 이렇게 대비했다"** 가 가장 강한 형태다. 억지 결론보다 낫고, *"검토를 안 했다"* 와도 완전히 다르다.

> 판단이 갈리는 항목은 **멘토링 안건으로 올린다.** 이렇게 묻는다 —
> *"고영향 AI 해당 여부를 저희 선에서 단정하기 어렵습니다. 발표에서 이 부분을 '검토 중'으로 두는 것과 '해당하지 않는 것으로 본다'고 쓰는 것 중 어느 쪽이 안전할까요?"*
> 결론이 아니라 **어떻게 쓸지**를 묻는 것이 답을 받기 쉽다.

## 7. 동의 프로토콜 (W8~W9 준비 · W10 실행)

M4 외적 타당성 검증에 참여할 실블로거 10~20명에게 받을 동의다. **문서 작성은 W8~W9에 하고, W2에는 읽지 않아도 된다.**

### 동의서에 반드시 들어갈 항목

| 항목 | 왜 빠지면 안 되나 |
|---|---|
| **수집·이용 목적** | 목적 외 이용이 이루다 사건의 구조다 |
| **수집 항목** | *"블로그 공개 게시글 본문 및 작성일시"* — 범위를 좁게 특정한다 |
| **보유·이용 기간** | *"분석 종료 즉시 파기"* |
| **파기 방법** | 원본 + **중간 산출물 전부**. 중간 산출물을 빠뜨리기 쉽다 |
| **철회권** | 언제든 철회 가능하고, 철회 시 즉시 파기 |
| **제3자 제공 여부** | *"제공하지 않음. 외부 AI API 전송 없음(로컬 전용 처리)"* ← 우리 차별점이 여기서도 나온다 |
| **결과 공개 방식** | *"익명·집계 형태로만"* |
| **동의 거부권과 불이익 없음** | 지인 대상이라 더 중요하다 |
| **연락처** | 팀 대표 연락처 |

### 절차

```
모집(W9)   →  서면 동의(W10 초)  →  로컬 전용 분석  →  즉시 파기  →  파기 확인서
```

- 실데이터는 `data/consented/` 에만 둔다. **커밋하지 않는다** — 훅과 CI가 막는다
- 분석은 **외부 API 전송 0.** M4 시점엔 로컬 모델이 완성돼 있으므로 가능하다
- 파기 후 **파기 일시와 대상을 기록**한다. 파기했다는 사실 자체가 산출물이다

### ⚠️ 미결 2건 — 우리가 답을 못 정한다

| 미결 | 내용 |
|---|---|
| **IRB(연구윤리심의) 필요 여부** | 학내 규정에 따라 다르다. 소속 기관에 확인이 필요하다 |
| **제3자·미성년 정보** | 동의자의 글에 등장하는 **자녀·지인**의 정보는 본인 동의로 커버되지 않는다 |

두 번째가 특히 까다롭다. 블로그 글에는 자녀 이야기가 반드시 나오는데, 그 아이는 동의한 적이 없다. **가능한 대응** — ① 분석 대상을 본인 속성 7종으로만 한정하고 제3자 언급은 스팬 단계에서 제외 ② 결과 공개에서 제3자 관련 사례를 전부 뺀다.

**둘 다 멘토·지도교수 의견이 필요하다.** [MF-004](../../mentor-log.md)로 등록되어 있다. **W3 안에 한 번은 묻는다** — W10에 물으면 늦는다.
