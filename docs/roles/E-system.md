## 0. 이 역할이 없으면 무슨 일이 생기나

**아무것도 안 보인다.**

A·B·C·D가 만드는 건 전부 부품이다. 데이터, 모델, 계산 엔진 — 심사위원 앞에서 보여줄 수 있는 형태가 아니다. **그걸 화면으로 만들고 하나로 연결하는 게 이 자리**다.

그리고 하나 더 — 개인정보 트랙이라서 **"법적으로 이게 무슨 의미인가"에 답하지 못하면 프로젝트가 반쪽이 된다.** 그 답을 준비하는 것도 이 자리다.

**그리고 W2에는, 이 자리가 막히면 네 사람이 전부 멈춘다.** 인터페이스 계약이 고정되지 않으면 B는 무슨 형식으로 뱉을지 모르고, C는 무슨 형식으로 받을지 모르고, D는 2단 입력을 못 정한다. **다섯 자리 중 유일하게 "남을 기다리게 만들 수 있는" 자리다.**

**코딩 부하는 다섯 자리 중 가장 낮은 편**이다. 대신 계속 조금씩 바쁘고, 문서를 읽는 일이 많고, **네 사람 모두와 매주 이야기한다.**

## 2. ⚠️ 제1원칙 — 두 계층을 분리한다

이걸 어기면 **프로젝트의 핵심 논거가 무너진다.**

```
[가상 SNS 플랫폼]   ← 사용자 데이터가 원래 있는 곳의 "시뮬레이터"
      │                우리 제품이 아니다. 네이버 자리를 대신할 뿐
      │ 입력 어댑터
      ↓  { post_id · body · created_at · activity_meta{nickname, geo_tag, post_time} }
[분석 도구]          ← 이게 우리 제품. 사용자 측 실행. 외부 전송 0
```

**왜 이렇게까지 신경 쓰나.** 이 프로젝트의 주장은 *"프라이버시를 검사한다고 사용자 글을 외부로 보내면 그 도구 자체가 침해다"* 이다. 그런데 우리가 웹 서비스를 만들면서 사용자 글을 우리 서버에 모아두면 — **우리가 그 침해를 저지르는 셈**이 된다.

계획서 v2.1은 *"크롤링 웹서비스 = 데이터가 우리 서버에 = 자기모순 위반"* 이라고 **우리 손으로 써 두었다.** 그 서술을 그대로 둔 채 웹 서비스를 만들면 논리가 정면 충돌한다. 그래서 v2.2에서 **"플랫폼 자리 ↔ 분석 계층" 분리로 논거를 재구성**했다([DEC-001](../decisions.md)). **그 재구성이 실제로 성립하게 만드는 것이 이 자리의 일이다.**

### 판단 기준은 하나다

> **"사용자 글의 원문이 우리 분석 서버로 넘어가나?"** 넘어가면 잘못된 설계다.

### ✗ 이렇게 하면 안 되고 ○ 이렇게 한다

| | ✗ | ○ |
|---|---|---|
| **프로세스** | 한 서버가 SNS와 분석을 다 한다 | **다른 프로세스 · 다른 포트** (SNS 3000 / 분석기 8000) |
| **저장** | 분석기가 글을 DB에 저장하고 결과를 캐시한다 | 분석기는 **어떤 DB도 갖지 않는다.** 세션 메모리에서 처리하고 버린다 |
| **접근** | 분석기가 `sns.db`를 직접 읽는다 (빠르니까) | **`GET /api/export/<user_ref>` 만** 본다. 계약에 없는 건 못 본다 |
| **방향** | 분석기가 SNS의 글을 비공개로 바꾼다 | 분석기는 **"이걸 비공개하라"까지.** 실행은 사용자가 SNS 화면에서 |
| **외부 호출** | 필요한 곳마다 API를 부른다 | **`apps/analyzer/external.py` 한 파일에서만.** `ALLOW_EXTERNAL_LLM` 게이트를 통과 |
| **업로드 파일** | 임시 디렉터리에 저장 후 처리 | **메모리에서 읽고 버린다.** M4 실블로거 글이 디스크에 남으면 안 된다 |

### 코드로 확인하는 법

```bash
# 분석기가 SNS 내부를 건드리지 않는지 — 0줄이어야 한다
grep -rn "sns\.db\|apps\.sns\|apps/sns" apps/analyzer/ || echo "OK: 경계 유지"
```

이 한 줄을 `scripts/check_boundary.sh` 로 만들어 PR마다 돌린다. **말로 하는 원칙은 3주 뒤에 무너지고, 스크립트는 안 무너진다.**

### 조치를 누가 실행하나 — W2에 정할 것

*"이 글 3개를 비공개"* 를 누가 실제로 누르는가. **분석기에 버튼을 달면 편하지만 계층 경계가 흐려진다.**

| | 분석기가 실행 | **사용자가 SNS에서 실행** ← 권장 |
|---|---|---|
| 데모 편의 | 좋다 | 클릭이 한 번 늘어난다 |
| 실서비스 정합성 | **성립 안 함** (네이버에 쓰기 권한이 없다) | 실제와 같다 |
| 계층 경계 | 분석기 → 플랫폼 쓰기 경로가 생긴다 ⚠️ | 단방향 유지 |

**권장: 분석기는 조치를 "가정한 재계산"까지만 하고, 실제 반영은 SNS 화면의 공개/비공개 토글로 한다.** 재스캔하면 위험도가 실제로 내려가므로 시연 효과는 같다. 정하고 나면 [`decisions.md`](../decisions.md)에 남긴다.

> **발표 때 결정타**: 스캔을 돌리면서 브라우저 개발자도구의 네트워크 탭을 열어 **외부로 나가는 요청이 0건**임을 보여준다. 말로 설명하는 것보다 훨씬 강하다.
> **W5부터 매번 확인하고 캡처를 `docs/evidence/`에 남긴다.** 마지막 주에 처음 확인하면 그때는 못 고친다. 절차는 [`howto/e-integration.md §5`](howto/e-integration.md).

## 3. 인터페이스 계약 — W2의 전부

### 왜 이게 이번 주의 중심인가

계획서 §12의 리스크 목록에 **「인터페이스 미정으로 상호 대기」** 가 올라 있다. 대응은 한 줄이다 — *"2주차까지 데이터 스키마 + 모듈 입출력 계약 고정"*. **그 한 줄이 이 자리의 W2다.**

그리고 W1을 주제·역할 확정에 썼기 때문에 **M1 실질 기간이 W2~W3 2주로 압축됐다.** 여기서 한 주를 흘리면 회복할 곳이 없다.

### 계약 4종 — E 가 주도한 JSON Schema

> 팀 전체 계약은 **6종**이다 — 이 4종에 라벨 스키마(A·B)와 지명 사전(C·D)을 더한 것. 아래 「4종」은 E 소유의 스키마 4개를 가리킨다.

| 계약 | 주는 쪽 | 받는 쪽 | 담는 것 |
|---|---|---|---|
| `span.schema.json` | **B** 최진필 | C·D·E | 탐지된 구간 — 위치·유형·등급·점수 |
| `specificity.schema.json` | **C** 신정현 | D·E | k값 입출력 |
| `contribution.schema.json` | **C** 신정현 | D·E | 글별 기여도, 조치 후 재계산 |
| `stage2-io.schema.json` | **D** 박재현 | E | 종합 판정, 추천 조합, 리라이트 |

**계층 경계도 여기 명시한다** — 플랫폼과 분석기가 무엇을 주고받는지, **무엇은 절대 넘기지 않는지.**

### 무엇부터 정하나 — 순서가 있다

**나중에 바꾸기 어려운 것부터.**

| 순위 | 정할 것 | 왜 나중에 못 바꾸나 |
|---|---|---|
| 1 | **필드 이름** | 네 사람의 코드에 문자열로 박힌다 |
| 2 | **좌표·단위 기준** | 이미 만든 데이터가 전부 무효가 된다 |
| 3 | **부호 방향** ⚠️ | 반대여도 **에러가 안 난다.** 조용히 반대로 추천한다 |
| 4 | **값 목록(enum)** | 학습 라벨이 여기 묶인다 |
| 5 | null·빈 값 처리 | 늦게 정해도 고칠 수 있다 |
| 6 | 선택 필드 추가 | **언제든 추가해도 된다** |

시간이 모자라면 5·6을 버리고 1~4에 쓴다.

### ✗/○ — 자주 어긋나는 네 가지

| | ✗ | ○ |
|---|---|---|
| 스팬 위치 | "글에서 몇 번째쯤" / 토큰 인덱스 | **문자 offset**, `end` 미포함, `body[start:end] == text` |
| k 산출 불가 | `0` | **`null`.** 0은 "해당자 없음"이라 위험도 최대로 읽힌다 |
| 기여도 부호 | "이 글의 기여도" | `delta` = **비공개했을 때의 변화**. 내려가면 **음수** |
| 등급 표기 | `"매우 높음"` (한글을 코드에) | `"VERY_HIGH"` + **화면 문구는 E가 따로 매핑** |

### 🔴 지금 저장소에 이미 충돌이 하나 있다

7속성의 필드 이름이 **두 가지로 공존한다.**

| 출처 | 표기 |
|---|---|
| [`persona-design.md`](../persona-design.md) §4-1 `ground_truth` | `age` `sex` `location` `occupation` `family` `commute` `income` |
| [`README.md`](../../README.md) A 항목 페르소나 예시 | ~~`gt`: `age` `gender` `residence` `job` …~~ → **W2에 위 표기로 정렬함** |

**목요일 전에 하나로 못 박고 `decisions.md`에 남긴다.** 어느 쪽이든 상관없지만 하나여야 한다.

> **권장 = `persona-design` 쪽**(`sex` `location` `occupation`). 이유 셋 —
> ① A의 채점 정답(`ground_truth`)이 이 표기이고, ② C의 `specificity.schema.json` 초안이 이미 이 축 이름으로 돌아가고 있으며([C-specificity.md §9](C-specificity.md)), ③ *"화면에 쓰기 좋다"* 는 이유는 **위 ✗/○ 표의 마지막 줄(값 ≠ 표기)과 정면으로 어긋난다** — 화면 문구는 어차피 E가 매핑한다.
> **정하면 `[DEC-002]`로 남긴다.** 이 줄이 없으면 3주 뒤에 또 갈린다.

### ⭐ 스키마가 팀 규칙을 강제하는 장치가 된다

계약을 잘 쓰면 [RULES-DO-NOT](../RULES-DO-NOT.md)이 문서가 아니라 **검사기가 잡는 것**이 된다.

| 스키마의 장치 | 강제되는 규칙 |
|---|---|
| `stage2-io`의 입력에 `body`가 **없다** (`pseudonymized_body`만) | #2 — 2단에 원문을 넘기지 않는다 |
| `attr` enum에 **학력·건강·정치성향이 없다** | #4 — 민감 속성 미추론 |
| `abstained`가 **required** | #5 — 근거 없으면 기권. 필드가 없으면 기권을 표현할 방법이 없다 |
| `verdict`의 설명이 *"범위만 쓴다"* | #5 — 신상 단정 금지 |

**문서에 적어둔 규칙은 잊히고, 스키마에 박은 규칙은 명령어가 잡는다.** 이 자리가 할 수 있는 가장 값싼 방어다.

### 빠뜨리기 쉬운 필드 4개

| 필드 | 없으면 |
|---|---|
| `schema_version` | 계약을 고쳤을 때 어느 버전인지 알 수 없다. **전 계약에 넣는다** (✅ W2 완료) |
| `abstained` | 기권을 표현 못 한다 — *신호 없는 글에서 7속성 중 6개 기권*(선행 PoC 자체 측정)을 화면에 못 보여준다 |
| `basis` (k의 출처·기준일) | *"이 숫자 어디서 나왔나"* 에 답 못 한다 |
| `top_spans` / `evidence_post_ids` | 조치 화면에 **이유를 못 쓴다.** 근거 없는 추천은 안 눌린다 |

### 1:1은 넷을 모아서 하지 않는다

모으면 자기 것만 말하다 끝나고 남의 필드에는 아무도 의견을 안 낸다. **30분씩 따로 만난다.**

| 시간 | 할 일 |
|---|---|
| 0~5분 | 초안을 화면에 띄운다. 설명하지 말고 **보여준다** |
| 5~20분 | 질문 목록 순서대로. 답이 나오면 **그 자리에서 파일을 고친다** |
| 20~25분 | **예시 JSON 1개를 같이 채운다.** 여기서 오해가 드러난다 |
| 25~30분 | 미정 항목에 **내가 기본값을 박는다.** "이의 없으면 목요일 확정" |

> **회의록을 쓰지 않는다. 상대가 보는 앞에서 스키마 파일을 고치고 커밋한다.**
> 회의록은 아무도 다시 안 읽지만 파일은 코드가 읽는다.

**상대별 질문 목록(B 7개 · C 8개 · D 9개)과 "모르겠다"고 할 때 박을 기본값은 [`howto/e-contracts.md §4`](howto/e-contracts.md)에 있다.**

### 목요일 — 머지만으로는 게이트가 아니다 🔒

`docs/contracts/`는 [`CODEOWNERS`](../../.github/CODEOWNERS)에 걸려 있다 — **그 줄은 W2 에 활성화됐고**(✅), PR 로 열면 코드오너 리뷰가 자동 요청된다. ⚠️ 승인 요건은 「2명」이 아니라 **코드오너 1명**이고, **관리자의 직접 push 는 이 게이트를 타지 않는다** — 계약 변경은 반드시 PR 로 연다.

⚠️ 전제 2개가 안 되면 GitHub가 규칙을 **조용히 무시한다.**

1. 네 사람이 **Collaborator로 초대·수락**되어 있을 것
2. 적은 핸들이 **실제로 존재**할 것 (없는 계정 하나가 파일 전체를 무효로 만든다)

**확인법 (2분)**: `docs/contracts/` 안의 파일에 공백 하나를 고쳐 PR을 연다 → **리뷰어가 자동 지정되면 켜진 것**. 안 붙으면 PM에게 초대 상태를 확인한다.

**이걸 확인하지 않으면 "계약이 고정되었다"가 사실이 아니다.**

## 4. 가상 SNS — 무엇을 만드나

글을 쓰고 올리는 SNS 형태의 웹 서비스. 네이버 블로그·인스타그램 자리를 대신하는 **실험 환경**이다.

| 기능 | 왜 필요한가 | 주차 |
|---|---|---|
| 글 작성 · 목록 · 본문 조회 · 프로필 | 기본. 글 이력이 있어야 누적 위험을 시연할 수 있다 | W3 |
| **내보내기 API** (`/api/export/<user_ref>`) | ⭐ **계층 경계가 여기다.** 분석기는 이것만 본다 | W3 |
| **합성 코퍼스 자동 시딩** | A가 만든 글을 스크립트로 밀어넣기. **수작업 금지** | W4 |
| **수동 업로드 경로** | 텍스트 붙여넣기·파일. **M4 실블로거 검증이 이 경로로 돈다** | W5 |
| **활동 메타** — 닉네임·위치태그·작성시각 | ⭐ 선행 PoC 자체 측정에서 **「활동 메타 관리」가 위험도 감소 폭 1위**였다. 이 필드가 없으면 핵심 메시지를 시연 못 한다 | **W3 저장·표시**(스펙 §4 필수 — 데이터 모델에 처음부터 있다) · **W6 토글·관리 UI** |
| **공개/비공개 토글** | 조치 ③을 시연하려면 필요하다. 삭제로 보여주면 리허설을 두 번 못 한다 | W6 |
| 에디터 실시간 경고 | 글 쓰는 중에 *"이 표현이 이전 글의 ○○와 결합합니다"* | W9 |

**CRUD 수준이면 충분하다.** 화려할 필요 없고, 실제 SNS가 가진 구조(글 목록 / 본문 / 작성 / 프로필 / 메타)만 있으면 된다.

### 만들지 않는 것

로그인·회원가입·비밀번호 · 좋아요·댓글·팔로우 · 반응형·다크모드 · React/SPA · 배포/도커.

> ⚠️ **비밀번호를 다루지 않는 것이 설계다.** 인증을 붙이면 계정·비밀번호라는 개인정보가 생기고, 개인정보 트랙 팀이 그걸 SQLite에 평문으로 두는 그림이 된다. 작성자는 드롭다운으로 고른다.

### 데이터 모델 — 테이블 2개

```sql
users   (user_ref, nickname, bio, joined_at)
posts   (post_id, user_ref, title, body, created_at,
         geo_tag, visibility, source)
photos  (post_id, seq, caption)          -- photo_caption:N 은 (post_id, seq) 로 복원
```

> ⚠️ 식별자는 **`user_ref`** 다(`sns-minimal-spec.md` §2, 형식 `u_…`). `author_id` 같은 별칭을 만들면 export 가 계약과 어긋난다. 그리고 **`photos` 테이블이 없으면 계약 텍스트 채널 4개 중 `photo_caption:N` 이 구조적으로 빈다** — 생성기가 이제 캡션을 만들고(#112) 골드셋에 캡션 스팬이 생긴다.

| 필드 | 없으면 |
|---|---|
| `nickname` · `geo_tag` · `created_at` | **조치 ②「활동 메타 관리」를 시연할 수 없다** — 실측 1위 조치가 화면에서 사라진다 |
| `visibility` | **조치 ③「비공개」를 시연할 수 없다** |
| `source` (`seed`/`manual`) | 시딩된 글과 시연 중 쓴 글이 섞인다 |

**`post_time`은 컬럼으로 만들지 않는다.** `created_at`에서 파생시킨다 — 같은 사실을 두 곳에 저장하면 한쪽만 고쳐졌을 때 조용히 어긋난다.

**전체 스키마 SQL · 라우트 · `app.py` 골격 · 시딩 스크립트는 [`howto/e-sns.md`](howto/e-sns.md).**

### 작성 시각을 직접 입력받는다

실제 SNS에는 없는 기능이지만 여기서는 있어야 한다. *"이 사람은 새벽 2시에 글을 자주 쓴다 → 육아 또는 교대근무"* 를 시연하려면 시각을 흩뿌려야 하기 때문이다. 외부 플랫폼은 발행일 소급이 불가해 이 항목을 포기했었고, **자체 플랫폼이 되면서 복구된 것**이다([DEC-001](../decisions.md)).

### 기술 스택 — 30분 안에 정한다

**권장**: Python + Flask(SNS) + FastAPI 또는 Flask(분석기) + SQLite + 생 SQL(ORM 없음).
**폴백**: 익숙한 스택이 있으면 그걸 쓴다. **조건은 2개뿐** — ① 분석기는 파이썬(모델을 직접 부른다) ② SNS와 분석기는 **다른 프로세스·다른 포트**.

> **디렉터리 표기** — ⑥⑦의 실행 코드는 `apps/analyzer/` · `apps/sns/`에 둔다. **계층 분리를 폴더로 보이게 하려는 것**이고, `.github/CODEOWNERS`에 `/apps/` 줄이 이미 준비되어 있다. [glossary.md](../glossary.md)의 `c6_system`·`c7_sns`는 **문서·브랜치·커밋 스코프 표기**로 계속 쓴다(`feat(c7): …`, `E/c7/sns-v0`). 엔진 래퍼처럼 `src/kopl/` 아래 들어가는 파일만 `c6_system` 경로를 쓴다.

## 5. 분석 웹앱 — 3화면

```
스캔                    진단                       조치
내 글 불러오기    →    "AI가 추정한 당신"    →    무엇을 어떻게 되돌릴지
위험도 0~100          7속성 + 근거 + 신뢰도       추천 + 사용자 선택
```

| 화면 | 보여줄 것 | 어느 계약에서 오나 |
|---|---|---|
| **스캔** | 글 목록, 진행률, 최종 위험도 0~100 | 어댑터 + `contribution.baseline_risk` |
| **진단** | 7속성별 판정·근거 문장·신뢰도, **기권한 속성**, 특정성 k값 + 출처 | `stage2-io.findings` + `specificity` |
| **조치** | 추천 1개(+대안 2개), 글별 기여도 순위와 이유, **조치 후 예상 위험도** | `contribution` + `stage2-io.recommendation` |

### 화면 문구가 규칙에 묶여 있다

| 규칙 | 화면에서 |
|---|---|
| [#5](../RULES-DO-NOT.md) 신상을 단정하지 않는다 | ✗ *"용인 기흥에 사는 48세 남성"* → ○ ***"거주지가 동 단위로 특정 가능"*** |
| 근거 없으면 기권 | 빈칸이 아니라 ***"근거 부족 — 판단 보류"*** 로 명시 |
| k 산출 불가 | ***"산출 불가"***. `0명`으로 표시되면 안 된다 |
| 선택지를 늘리면 선택이 부담이 된다 (§2) | **추천을 먼저 보여주고**, 바꾸기는 그다음 |

### 조치 화면이 이 프로젝트의 얼굴이다

*"이 글 3개만 비공개하면 79.7 → 41"* 이 나오는 화면이다. 여기에 **왜 그 3개인지**가 같이 나와야 한다(`top_spans`). 이유 없는 추천은 아무도 안 누른다.

> 참고로 무작위로 몇 개 빼는 것으로는 안 된다 — 누적 곡선은 5편 부근에서 이미 포화한다(1편 26.7 → 5편 69.2 → 10편 71.9 → 19편 79.7, *선행 PoC 자체 측정*). **어떤 글을 빼느냐가 전부**이고, 그래서 기여도 산출이 필요하다.

## 6. 통합 — 남을 기다리지 않는 법

원래 W8이던 통합을 **W5로 앞당겼다**([roadmap.md §1](../roadmap.md)). M3가 −53%로 압축되어 부채를 뒤로 미룰 수 없기 때문이다.

그런데 W5에는 B의 모델도 C의 엔진도 D의 2단도 완성이 아니다. **그래서 가짜로 먼저 붙인다.**

> **계약이 있으면 상대의 코드가 없어도 그 자리에 가짜를 놓을 수 있다.**
> 계약을 목요일에 고정하는 진짜 이유가 이것이다. 계약은 문서가 아니라 **빈자리의 모양**이다.

```
ENGINE_MODE=mock   # 기본값. 아무것도 없어도 3화면이 끝까지 돈다
ENGINE_MODE=real   # 실제 모델. 한 번에 하나씩 교체
```

**목의 유일한 요구조건: 계약 스키마를 통과할 것.** 숫자는 아무래도 좋다. 목이 계약을 어기면 목의 형식에 맞춰 화면을 만들게 되고, 실제 모델이 오는 날 화면을 다시 짜게 된다.

**목에 비정상 케이스를 하나씩 심어둔다** — 기권한 속성, `k: null`, 스팬 0개인 글, 글 0편인 작성자. 목이 성공만 주면 실제 모델이 기권했을 때 화면이 빈칸으로 뜬다.

**W5의 목표는 "스캔이 한 번 끝까지 돌아가는 것"이다. 숫자가 맞는 것은 목표가 아니다.**
금요일에 숫자가 전부 가짜여도 W5는 성공이다. **파이프가 뚫린 것이 산출물이다.**

목 코드·교체 순서·어댑터 2종·네트워크 0건 검증은 [`howto/e-integration.md`](howto/e-integration.md).

## 7. 컴플라이언스 — 무엇을 정리하나

**별도 워크스트림이 아니다. 설계를 정당화하는 근거로 쓴다.** W1~W3에 한 번 정리하고, 이후에는 지표와 아키텍처에 녹아서 유지된다.

**목적이 좁다** — 법을 공부하는 게 아니라 **우리 설계 결정 하나하나에 근거를 붙이는 것**이다. 전문을 읽지 않는다. **조문 5개 + 가이드라인의 한 절**이면 끝난다.

### 조문 하나에서 뽑는 것은 4가지뿐

① 정확한 조문 번호 · ② 핵심 문구 한 문장(원문) · ③ 우리 설계의 무엇을 정당화하나 · ④ **반박당할 지점과 우리 답**

**④가 가장 중요하고 가장 자주 빠진다.** ①~③만 있으면 발표에서 질문 한 번에 무너진다.

**찾는 곳 · 읽는 순서 · 기록 양식은 [`howto/e-legal.md`](howto/e-legal.md).**

### ① k값을 법적 기준에 대응시키기 (C와 공동)

| k값 | 의미 | 위험 등급 |
|---|---|---|
| k ≤ 2 | 개인 특정 가능 | **매우 높음** |
| k = 3~4 | 소수로 좁혀짐 | 높음 |
| k ≥ 5 | 집단 내 익명 | 통상 허용 수준 |

근거: 개인정보보호위원회 **가명정보 처리 가이드라인**의 적정성 검토 절차(식별 위험성 → 가명처리 수준의 적정성 → 재식별 위험성).
→ 점수가 *"우리가 정한 숫자"* 에서 *"규제 기준에 대응하는 숫자"* 가 된다.

> **k 임계값 자체는 C의 산출물이다.** E가 하는 일은 *"이 숫자가 어느 규제 절차에 대응하는가"* 를 붙이는 것이다. 숫자를 혼자 정하지 않는다.

### ② 아키텍처가 규제 체계와 정렬됨을 보이기

가명정보 처리 가이드라인은 **2026년 4월 위험도 기반 체계로 전면 개정**되어, *"누가 활용하는지 · 어떤 환경에서 처리되는지"* 로 위험도를 구분한다.

| 우리 구조 | 규제상 위치 | 우리 조치 |
|---|---|---|
| 1단 로컬 처리 (외부 전송 0) | 동일 처리자 내부 · **저위험** | 기본 경로 |
| 2단 외부 AI 전송 | 제3자 제공 · **중·고위험** | 명시적 동의 **and** 가명화 후 |

`or`가 아니라 `and`인 이유 — 자체 ablation에서 **명시 단서를 지워도 7속성이 그대로 뚫리고 위험도 66~70이 잔존**했다(*선행 PoC 자체 측정*). **가명화는 면책이 아니라 최소화 조치다.**

> ⚠️ **구버전 가이드라인을 인용하지 않는다.** 검색엔진에는 개정 전 PDF가 먼저 뜬다. 개정 전은 위험요인을 나열하는 방식이라 위 표와 안 맞는다. **위원회 사이트에서 받고 확인일을 적는다.**

### ③ 근거 법령 5개

| 조항 | 우리 프로젝트에서의 의미 |
|---|---|
| **개인정보보호법 제2조 1호 나목** | *"다른 정보와 쉽게 결합하여 알아볼 수 있는 정보"* = **준식별자도 개인정보**. 결합 용이성은 **입수 가능성·시간·비용·기술**로 판단 → **AI가 그 문턱을 무너뜨렸다**는 것이 이 프로젝트의 법적 존재 이유 |
| 제2조 2호 | **수집도 처리행위** → 사후 마스킹이 무동의 수집을 치유하지 못함 (전량 합성의 근거) |
| 제28조의2 | 가명정보 특례 — 추가정보 분리보관·재식별 금지 |
| 제33조 | 개인정보 영향평가 — **기업 의무**다. 개인에게는 그런 도구가 없다 → **우리 진단 화면이 그 개인용 버전**이고, 이것이 주제명의 근거다 |
| 대법원 2014다235080 | 공개된 개인정보도 **이익형량 대상** — *"공개했으니 써도 된다"* 는 성립하지 않음 |

### ④ AI 기본법 검토 (결론은 미정으로 둬도 된다)

인공지능 기본법이 2026-01-22 시행, 2026-07-21 개정 시행되었다. 검토할 것 3개 — 우리 시스템이 **고영향 AI**에 해당하는지 / **연구·시제품 단계**에 사업자 의무가 적용되는지 / 적용된다면 투명성 의무를 화면에 어떻게 반영할지.

> 참고로 우리 시스템은 이미 **근거 문장 제시 + 신뢰도 표기 + 근거 없을 때 기권**을 수행하므로 투명성 요구와 방향이 일치한다.

**"미정 + 그래도 이렇게 대비했다"가 가장 강한 형태다.** 억지 결론보다 낫고, *"검토를 안 했다"* 와도 완전히 다르다. 판단이 갈리면 **멘토링 안건으로 올린다** — 결론이 아니라 *"어떻게 쓸지"* 를 물으면 답을 받기 쉽다.

### 동의 프로토콜 (준비 W8~W9 / 실행 W10)

실블로거 10~20명 대상 외적 타당성 검증용.

- **모집**: 3년 이상 운영한 공개 블로그 보유자. 팀원 지인·학내 커뮤니티
- **동의서**: 목적·수집항목·보관기간·파기방법·철회권·제3자 제공 여부·결과 공개 방식·거부권
- **처리**: **로컬 전용, 외부 전송 0.** M4 시점엔 로컬 모델이 완성돼 있으므로 가능하다
- **파기**: 분석 종료 즉시 **원본 + 중간 산출물 전부.** 중간 산출물을 빠뜨리기 쉽다
- 실데이터는 `data/consented/` 에만. **커밋하지 않는다**

> ⚠️ **미결 2건** — ① 연구윤리심의(IRB)가 필요한지 ② 동의자 글에 등장하는 **제3자·미성년 정보**(자녀·지인)를 어떻게 다룰지. 본인 동의로 커버되지 않는 영역이다.
> **W3 안에 멘토에게 한 번은 묻는다.** W10에 물으면 늦는다. (한때 MF-004 로 등록했으나 **그 번호는 원장 정리 때 뺐다** — 지금은 [mentor-log.md](../mentor-log.md) 하단 미결 2건과 README 「현재 미결」로 추적한다. 이번 주 목요일 멘토링 안건 ③이다.)

## 8. 지표와 게이트 — 이것도 이 자리가 관리한다

지표를 1주차에 최대치로 선언하면 같은 결과물이 10주차에 "미달"이 된다. 그래서 **3계층 + 갱신 경로**를 미리 선언했다([roadmap.md §5](../roadmap.md)).

| 게이트 | 시점 | 내용 | E의 몫 |
|---|---|---|---|
| **G1 선언** | W1 주제선정서 | [필수]/[목표]/[도전] 3계층 + 갱신 경로 문장 | 완료 |
| **G2 조정** | W4 설계서 | M1 실측 반영, **멘토 승인 하에 1회 갱신** | 각 역할 실측치를 모아 갱신안 작성 |
| **G3 확정** | W8 중간점검 「계획 대비 변경사항」 | 최종 확정. 이후 변경 시 사유 필수 | **취합·확정** |

**G2에서 갱신하지 않으면 W8에 못 고친다.** 예를 들어 스팬 F1(암묵) 목표는 *"M1 IAA 측정치의 80% 이상"* 으로 걸려 있는데, A가 W3에 IAA를 재고 나면 **그 숫자를 넣어 목표를 확정해야 한다.** 이 연결을 챙기는 사람이 없으면 목표가 공중에 뜬 채로 10주차를 맞는다.

**중단 기준도 여기 걸려 있다** — W3에 측정하는 「기존 도구 대비 추가 탐지율」이 유의미하지 않으면 W4 설계서에서 주제 재검토를 판정한다. E는 그 판정이 **문서에 기록되게** 한다.

### exp8 축약판 (W7) — 왜 E가 하나

8주차 중간점검 양식이 「현재 성능 또는 결과 — 수치·표·그래프」를 **강제**한다. 그런데 서비스 지표(조치 효과 곡선)는 원래 M3 산출이라 그 시점에 없다. **그래서 축약판을 W7에 미리 뽑아 그 칸을 메운다.**

- 범위: **조치 곡선 1종**. 페르소나 1명, 조치 유형별 (효과, 부담) 점 몇 개
- 산출: **그래프 1장 + `experiments/exp08-actions/results/metrics.json`**
- 전체판은 W9에 C가 한다. 여기서는 *"측정 방법이 돌아간다"* 를 보이는 것이 목적이다

## 9. 발표 리스크 — 폴백 사다리를 미리 만든다

계획서 §12에 **「발표장 네트워크 실패」** 가 리스크로 올라 있고, *"데모는 라이브 기본 + 캐시 자동 폴백"* 이 대응으로 적혀 있다. **선행 PoC 웹앱은 캐시가 기본이라 반대로 뒤집어야 한다.**

| 단계 | 무엇 | 준비 시점 |
|---|---|---|
| **라이브** | SNS(3000) → 분석기(8000) 전 경로를 실제로 돌린다 | W9 |
| **폴백 1** | 미리 뽑아둔 `export` JSON을 **수동 업로드 경로**로 투입 | W10 |
| **폴백 2** | **시연 영상 재생** | W10 녹화 |

**리허설에서 폴백 2단까지 실제로 눌러본다.** 준비만 하고 안 눌러보면 그 자리에서 안 눌린다.

> **시연 영상은 발표장 사고 대비용이 아니라 공식 결과물이다.** W10에 녹화한다 — 그때가 시스템이 가장 온전한 시점이고, W11·W12에는 시간이 없다.

**모델 가중치를 미리 받아두고 오프라인 모드로 로드한다** (`HF_HUB_OFFLINE=1`). 시연 PC에서 처음 돌리면 모델 다운로드가 시작되고, 그건 네트워크 탭에 **외부 요청으로 찍힌다.** 발표 중에 그게 뜨는 것이 최악이다.

## 12. 막히기 쉬운 지점

| 상황 | 대처 |
|---|---|
| 웹 개발을 많이 안 해봤다 | CRUD 수준이면 충분하다. **W2는 코딩이 아니라 문서**고, 구현은 W3부터다. [`howto/e-sns.md`](howto/e-sns.md)에 `app.py` 골격이 통째로 있다 |
| 뭘 정해야 할지 모르겠다 | **바꾸기 어려운 것부터.** 필드 이름 > 좌표·단위 > 부호 > enum > null > 선택 필드 |
| 상대가 "아직 모르겠다"고 한다 | **내가 기본값을 박고 통보한다.** 미정으로 두는 게 제일 나쁘다. 기본값 목록이 [`howto/e-contracts.md §4`](howto/e-contracts.md)에 있다 |
| 두 사람이 다른 이름을 고집한다 | 동전을 던져서라도 정한다. **어느 쪽인지보다 하나인 것이 중요하다.** 근거를 `decisions.md`에 남기면 논쟁이 끝난다 |
| 목요일까지 4종이 안 된다 | **`span`과 `stage2-io` 2종을 먼저.** 이 둘이 3화면의 양 끝이다. 나머지는 금요일 |
| 계약을 고쳐야 할 일이 생겼다 | 숨기지 말고 바꾼다. `schema_version`을 올리고 PR 본문에 한 줄. **계약은 못 바꾸는 게 아니라 몰래 못 바꾸는 것이다** |
| 다른 사람 산출물이 안 와서 통합을 못 한다 | **가짜 데이터로 먼저 붙인다.** 형식만 맞으면 나중에 교체된다. **기다리지 않는 게 핵심** |
| 실제 모델을 붙였더니 화면이 멈춘다 | 서버 시작 시 모델을 **한 번만** 로드한다. 스캔은 글 단위 진행률을 보여준다 — 진행률 없는 10초는 멈춘 것으로 보인다 |
| 스팬 하이라이트가 한 글자씩 밀린다 | `end` 포함/미포함이 어긋난 것이다. 분석기에서 `body[start:end] == text` 를 assert하고, 틀린 예시를 그대로 B에게 보낸다 |
| 두 계층 분리가 헷갈린다 | 판단 기준 하나: **"사용자 글의 원문이 우리 분석 서버로 넘어가나?"** 넘어가면 잘못된 설계다. `grep` 한 줄로 확인한다(§2) |
| 법령 문서가 너무 길다 | 전문을 읽지 않는다. **조항 5개 + 가이드라인의 「적정성 검토」 절**만. 조문 하나에서 뽑는 건 4가지뿐이다 |
| 법 해석이 확실하지 않다 | **단정하지 않는다.** *"~에 해당할 수 있어 ~로 설계했다"*. 미정은 미정으로 두고 멘토에게 묻는다 |
| 후반에 일이 몰린다 | 가상 SNS를 W3~W6에 앞당겨 배치한 게 그 대비다. **W6까지 플랫폼을 끝내두면** 후반이 훨씬 가볍다 |
| 발표장에서 데모가 안 돌까 봐 불안하다 | **폴백 사다리 3단**(§9)을 만들고 리허설에서 2단까지 눌러본다. 시연 영상이 최종 안전망이다 |
