# B · 1단 탐지 모델 — 작업 매뉴얼

> 담당 컴포넌트 **① 준식별자 탐지 모델** · 담당기간 **W3~W7** → W8~ 성능 측정
> 자원: **GPU 필요** (RTX 3060 12GB급)

---

## 0. 이 역할이 없으면 무슨 일이 생기나

**"외부 전송 0"이라는 주장이 무너진다.**

이 프로젝트의 논리는 이렇다 — 프라이버시 위험을 검사한다고 사용자 글을 외부 AI에 보내면 그 도구 자체가 침해다. 그래서 탐지는 사용자 컴퓨터 안에서 돌아야 하고, 그러려면 **작고 빠른 모델**이 필요하다. 그게 이 자리에서 만드는 모델이다.

그리고 하나 더 — **이 자리가 프로젝트의 존재 이유를 숫자로 증명한다.** 기존 개인정보 탐지 도구가 놓치는 걸 우리가 얼마나 잡는지, 그 격차를 재는 게 여기다.

---

## 1. 무엇을 만드나

글을 넣으면 **신상 단서가 있는 구간에 밑줄을 긋고 종류를 붙여주는 모델**이다.

```
입력:  "집 근처라 자주 가는 신갈저수지 조황입니다. 마흔여덟 되니…"

출력:  신갈저수지 → [지역·시설]
       마흔여덟   → [나이]
       집 근처    → [거주 관계어]
```

| 산출물 | 언제 |
|---|---|
| **베이스라인 3종 측정 결과** ⭐ | W3 |
| 학습 파이프라인 (데이터 로더 · 학습 · 평가) | W4 |
| **1단 탐지 모델 v1** | W5~W7 |
| 성능 리포트 (스팬 F1, 지연 시간) | W7 |
| 벤치마크 러너 — 전체 성능을 한 번에 재는 스크립트 | W8~W10 |

---

## 2. ⭐ W3의 베이스라인 3종 — 프로젝트의 중단 기준

**이게 가장 먼저 할 일이고, 가장 중요하다.** 학습보다 먼저 한다.

같은 데이터에 세 가지를 돌려서 비교한다.

| 베이스라인 | 무엇 | 역할 |
|---|---|---|
| **규칙 기반** | 정규식으로 전화번호·주민번호 등 찾기 | 성능의 **하한** |
| **기존 도구** | Microsoft Presidio, korean-pii 등 공개 개인정보 탐지기 | **우리가 이겨야 할 대상** |
| **LLM 직접** | 좋은 AI에게 그냥 물어보기 | 성능의 **상한** |

**핵심 질문은 하나다.** *기존 도구가 놓치는 준식별자 중 우리가 잡을 수 있는 게 얼마나 되는가?*

> ⚠️ **이 숫자가 0에 가까우면 프로젝트의 존재 이유가 없다.** 그래서 4주차 설계서에서 주제 재검토 여부를 판정한다. 팀 전체가 이 결과를 기다린다 — W3 안에 반드시 낸다.

**왜 격차가 있을 거라고 보나.** 기존 도구는 *형식이 있는 것*을 찾는다 — 숫자 패턴, 이메일 모양, 사전에 등록된 이름. 그런데 "신갈저수지"는 그냥 지명이고, "마흔여덟"은 숫자도 아니다. 우리 실측에서 **명시적 개인정보를 전부 지워도 신상 7속성이 그대로 추론됐다.**

---

## 3. 모델과 학습 방법

| | 내용 |
|---|---|
| **모델** | KoELECTRA-base (약 1.1억 파라미터) |
| **방식** | full fine-tuning — 모델 전체를 우리 데이터로 다시 학습 |
| **작업 형태** | 토큰마다 태그를 붙이는 방식(BIO). 문장 분류가 아니다 |
| **비교 후보** | KLUE-RoBERTa, KoBERT — 여유가 있으면 |
| **소요** | RTX 3060 12GB에서 배치 32로 **수 시간** |

**KoELECTRA를 주력으로 정한 이유**: 한국어 개체명 인식 벤치마크에서 우세하다는 문헌이 있고, 4주차 설계서에 모델을 확정해서 써야 하는데 비교 실험을 기다릴 시간이 없다. 비교는 여유 시에 한다.

**GPU가 없거나 부족하면**: 학습 데이터가 전부 합성이라 **클라우드에서 돌려도 문제없다.** 로컬이어야 하는 건 *사용자 글을 다루는 추론*이지 학습이 아니다. AWS 크레딧을 주력으로, Kaggle 무료 GPU(주 30시간)를 백업으로 쓴다. Kaggle은 세션이 끊기므로 **중간 저장 후 이어서 학습**하는 구조로 짠다.

---

## 4. ⚠️ 위험도는 학습 대상이 아니다

가장 헷갈리는 지점이라 먼저 짚는다.

**이 모델은 "이게 위험하다"를 배우지 않는다.** "이건 지역 단서다"까지만 배운다.

왜냐면 **같은 표현의 위험도가 문맥마다 다르기 때문**이다. "신갈저수지"는 단독으로는 무해하다. "기흥호수"와 함께 나와야 거주지가 된다. 같은 단어에 문맥마다 다른 위험도를 라벨하면 정답이 일관되지 않고, 그러면 성능 지표 자체가 무의미해진다.

| 누가 | 무엇을 담당 |
|---|---|
| **B (나)** | "이 구간은 지역 단서다" — **문맥과 무관하게 일관된 라벨** |
| C | "이 조합이면 몇 명으로 좁혀지나" — 위험도 계산 |
| D | "따라서 이 사람은 어디 산다" — 종합 판정 |

## 5. 주차별 할 일

| 주 | 할 일 | 완료 기준 |
|---|---|---|
| **W1~W2** | A의 라벨링 지원 · **라벨 스키마를 A와 함께 확정** · 학습 환경 세팅 | GPU에서 KoELECTRA가 돌아가는 것 확인 |
| **W3** | ⭐ **베이스라인 3종 측정** · 기존 도구 대비 추가 탐지율 산출 | 숫자 확정, 팀 공유 |
| **W4** | 학습 파이프라인 구축 · 첫 파인튜닝 착수 | 학습이 끝까지 돌아감 |
| **W5** | 모델 v1 학습 · 하이퍼파라미터 조정 | F1(명시) 측정 |
| **W6** | 연휴 — **학습 잡은 비동기**로 걸어두면 된다 | — |
| **W7** | **1단 F1 확정** · 지연 시간 측정 · 성능 리포트 | 중간점검보고서에 들어갈 수치 |
| **W8** | 중간점검용 수치 제공 | — |
| **W9~W10** | 벤치마크 러너 · 전체 성능 + ablation | 최종 성능표 |

**W6은 오히려 유리하다.** 연휴 주간(근무일 3일)이지만 학습은 사람이 대기할 필요가 없다. 학습을 걸어두고 쉬면 된다.

---

## 6. 목표 수치

| 지표 | 목표 | 계층 |
|---|---|---|
| 스팬 F1 (**명시** 단서) | **≥ 0.80** | 필수 |
| 글 1건 탐지 지연 (CPU) | **< 300ms** | 필수 |
| 스팬 F1 (**암묵** 단서) | **사람끼리 일치도의 80% 이상** | 목표 |
| 기존 도구 대비 추가 탐지율 | **> 0** | 목표 ⭐ |

**암묵 F1에 고정 숫자를 쓰지 않는 이유**: "무릎이 예전 같지 않네요"가 나이 단서인지는 **사람 둘이도 갈린다.** 사람이 0.55밖에 못 맞추는 문제에서 모델에게 0.60을 요구하는 건 말이 안 된다. 그래서 A가 W3에 측정하는 **사람끼리의 일치도(IAA)를 상한으로 놓고** 그 80%를 목표로 삼는다.

**지연 시간을 CPU로 재는 이유**: 사용자 컴퓨터에 GPU가 있다고 가정할 수 없다. 실제 사용 환경 기준으로 잰다.

---

## 7. 다른 역할과 주고받는 것

| 상대 | 내가 주는 것 | 내가 받는 것 |
|---|---|---|
| **A** | 라벨 스키마 의견 (같이 정한다) | 라벨된 코퍼스, 골드셋, blind 200, IAA 수치 |
| **C** | 탐지된 스팬 + 유형 | 어떤 유형 구분이 위험도 계산에 필요한지 |
| **D** | 스팬·유형 (2단의 입력이 된다) | — |
| **E** | 모델 파일 + 추론 함수 | 통합 인터페이스 규격 |

**출력 형식은 2주차에 고정한다.** C와 D가 내 출력을 입력으로 쓰므로, 형식이 늦게 정해지면 셋이 서로 기다리게 된다.

## 8. 막히기 쉬운 지점

| 상황 | 대처 |
|---|---|
| 학습이 안 돌아간다 (메모리 부족 등) | 배치 크기를 줄이고 gradient accumulation. 그래도 안 되면 클라우드 |
| 암묵 단서 F1이 너무 낮다 | **정상일 수 있다.** IAA와 비교해서 판단한다. 사람도 못 맞추는 문제면 목표를 낮추는 게 맞다 |
| O 태그(단서 없음)만 잔뜩 맞힌다 | 데이터의 70~80%가 노이즈라 당연히 불균형하다. class weight 조정 또는 문장 단위 샘플링 |
| 기존 도구 대비 격차가 안 보인다 | **즉시 팀에 알린다.** 숨기면 안 된다. 프로젝트 방향 판정이 여기 걸려 있다 |
| Kaggle 세션이 끊긴다 | 중간 저장 → 이어서 학습 구조를 처음부터 전제로 짠다 |
| 파인튜닝을 해본 적이 없다 | HuggingFace 토큰 분류 예제가 거의 그대로 쓰인다. 데이터 형식만 맞추면 나머지는 정형화되어 있다 |

## 9. 내 산출물이 성공인지 판정하는 기준

- [ ] W3에 **베이스라인 3종 수치** 확정 및 팀 공유
- [ ] 기존 도구 대비 추가 탐지율이 숫자로 나옴
- [ ] 스팬 F1(명시) **≥ 0.80**
- [ ] 글 1건 CPU 추론 **< 300ms**
- [ ] 암묵 F1이 IAA 대비 몇 %인지 산출됨
- [ ] 모든 수치에 **측정일 · 데이터 버전 · 모델 버전**이 붙음
- [ ] E가 내 모델을 불러 쓸 수 있는 추론 함수 제공
- [ ] W7까지 성능 리포트 완료 (중간점검보고서 마감이 W8)
