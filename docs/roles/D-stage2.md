## 0. 이 역할이 없으면 무슨 일이 생기나

**"위험을 알려주는 앱"으로 전락한다.**

B가 단서를 찾고 C가 위험도를 계산해도, 그것만으로는 사용자가 할 수 있는 게 없다. *"당신 신상이 이만큼 노출됐습니다"* 는 화면은 불안만 준다.

**사람이 실제로 움직이게 만드는 건 "그래서 뭘 하면 되는데"에 대한 답**이고, 그게 이 자리에서 나온다. 프로젝트 이름이 "탐지"가 아니라 "탐지·**완화**" 시스템인 이유다.

## 1. 네 가지를 만든다

### ① 가명화 — 실제 값을 떼어낸다

```
원문   집 근처라 자주 가는 신갈저수지 조황입니다. 마흔여덟 되니…
              ↓
가명   집 근처라 자주 가는 [시설A·저수지] 조황입니다. [40대 후반] 되니…
```

**이 시점부터 실제 지명과 나이는 사라진다.** 나중에 외부 AI를 쓰게 되더라도(사용자 동의 시) 나가는 건 이 형태다. 결과는 다시 원래 표현으로 되돌린다(복원).

### ② 2단 추론 — 조각을 엮는다

가명 상태라 모델은 "용인 기흥"을 모른다. 대신 **무엇이 특정 가능한지**를 판정한다.

```
[시설A]와 [시설B]가 같은 생활권으로 묶이고
"집 근처" · "퇴근하고"가 거주·통근 관계를 지시함
    → 거주지가 시설 반경 수준으로 좁혀짐
```

> **이게 방어 도구다운 지점이다.** 우리 시스템은 신상을 알아낼 필요가 없고 실제로 산출하지도 않는다. **위험이 존재한다는 판정까지가 우리 몫이다.**

### ③ 리라이터 — 문장 수정안

> "신갈저수지" → "동네 저수지"

의미는 살리고 단서 표현만 바꾼다.

### ④ 추천 엔진 ⭐ — 최소 조치 조합

> "이 글 3개를 비공개하면 위험도 79.7 → 41. 부담 대비 효과가 가장 큽니다"

C가 계산한 글별 기여도를 받아서, **가장 적은 부담으로 목표 위험도에 도달하는 조합**을 찾는다.

## 2. 조치는 세 가지, 부담 순으로 제시한다

| 조치 | 예 | 사용자 부담 | 확실성 |
|---|---|---|---|
| **비공개 / 부분 비공개** | 기여도 높은 글만 골라서 | **낮음 — 고르기만** | **가장 확실** |
| **활동 메타 관리** | 닉네임 · 위치태그 · 활동 시간대 | 중간 | 높음 |
| **리라이트** | 단서 표현 교체 | 높음 — 글이 바뀜 | 잔존 단서 가능 |

> ⭐ **선행 PoC 자체 측정에서 "활동 메타 관리"가 위험도 감소 폭 1위였다.** 글을 고치는 것보다 활동 흔적을 정리하는 쪽이 효율이 높았다. 사용자 부담도 더 낮다. **서비스가 반드시 전달해야 할 메시지**이니 추천 로직에 반영한다.

> **네 번째가 하나 더 있다 — 삭제 권고.** [plan.md §2](../plan.md)의 조치 메뉴 ④다. **리라이트로도 신상이 남는 글에만** 띄우고, 기본 추천에는 올리지 않는다(되돌릴 수 없다). 위 3종이 「조치 3단계」로 묶여 지표에 쓰이는 것들이고([roadmap.md §5](../roadmap.md) [필수] −54~61%), 삭제는 그 바깥의 예외 경로다.

**선택지를 늘리면 선택 자체가 부담이 된다.** 프라이버시 UX의 고전적 실패 지점이다. 그래서 **먼저 추천하고, 그다음 사용자가 바꾸는** 구조로 만든다.

## 3. 모델과 학습 방법

| | 내용 |
|---|---|
| **모델** | Qwen3-4B |
| **방식** | QLoRA (4bit) — 모델 전체가 아니라 **작은 어댑터만** 학습 |
| **학습 데이터** | 합성 코퍼스 + 교사 AI가 만든 종합 판정·리라이트 라벨 |
| **VRAM** | 학습 약 8GB / 추론 약 3GB |

**QLoRA를 쓰는 이유**: 40억 파라미터를 통째로 학습하려면 개인 GPU로는 불가능하다. QLoRA는 모델을 4bit로 압축해 얼려두고 **작은 어댑터만 학습**하는 방식이라 3060에서도 돌아간다.

**증류 구조**: 좋은 AI(교사)가 만든 답을 작은 모델이 흉내 내도록 학습시킨다.

```
[오프라인] 합성 코퍼스 → 교사 AI가 판정·리라이트 라벨 생성
                       → Qwen3-4B가 그걸 예측하도록 학습
[실행 시]  사용자 글  → 로컬 Qwen3가 외부 호출 없이 즉시 판정
```

> ⚠️ **실행 시 외부 AI 정책 — 헷갈리기 쉬우니 정확히.**
>
> | 경우 | 대상 데이터 | 외부 AI |
> |---|---|---|
> | **기본 경로** | 사용자 글 | **쓰지 않는다.** 로컬 Qwen3만 |
> | 정밀 판정 (선택) | 사용자 글 | **명시적 동의 `+` 가명화 후**에만. `or`가 아니라 `and` |
> | 교사 라벨 (오프라인) | 합성 코퍼스 | 제약 없음 (실존 인물 0) |
> | 평가 상한 (실험) | 합성 코퍼스 | 제약 없음 |
>
> 기본 경로에서 외부로 보내면 *"검사한다고 외부로 보내면 그 도구가 침해"* 라는 이 프로젝트의 척추가 부러진다.
> 동의 경로를 만들 때도 **가명화가 면책이 아니다** — 명시 단서를 지워도 7속성이 그대로 뚫린다는 게 우리 실측이다. 가명화는 최소화 조치일 뿐이고, 근거는 **동의**다.
> `.env`의 `ALLOW_EXTERNAL_LLM=false` 를 기본값에서 바꾸지 않는다.

**폴백**: QLoRA 학습이 잘 안 되면 **파인튜닝 없이 프롬프트만으로** 돌린다. 성능은 떨어져도 "로컬 2단" 구조 자체는 유지된다. 이 안전망이 있으니 학습 실패를 두려워할 필요는 없다.

### ⚠️ 2단 어댑터 가중치는 공개하지 않는다 — 이중용도 통제

[plan.md §13.5](../plan.md)와 [RULES-DO-NOT #6](../RULES-DO-NOT.md)이 정한 것이다.

| 모델 | 성격 | 공개 |
|---|---|---|
| 1단 탐지기 (B) | 방어 측 | private → **M4에 public** |
| **2단 추론기 (나)** | **공격 측(속성 추론)** | **비공개 유지** |

**탐지기를 잘 만들면 그게 곧 추론기다.** 우리는 방어 측만 공개한다. 실무로는 —
어댑터·체크포인트를 **repo에 커밋하지 않고**(`.gitignore`가 막는다), [`models/registry.md`](../../models/registry.md)에 **포인터와 학습일·데이터 버전·지표만** 적는다. 발표·논문에는 방법과 수치만 싣는다.

## 4. W3에 먼저 할 일 — 모델 크기 결정

**학습보다 먼저 한다.** 파인튜닝을 하기 전에, **프롬프트만으로** 1.7B와 4B가 얼마나 하는지 잰다.

| 결과 | 판단 |
|---|---|
| 4B 프롬프트만으로 7속성 중 5개 적중 | 파인튜닝 후 7/7이 현실적 → **4B 확정** |
| 3개 이하 | 크기를 올리거나 접근을 바꿔야 함 |

**측정 설계** (README 가 W3 에 확정): **n≥20** · 입력은 생성 글이 아니라 **인물 `clue_plan` 문장**(글은 화~수에나 나온다) · 판정 우선순위 ① R1~R6 7속성 적중 수 ② 근거 스팬 정확도 ③ 형식 준수율 ④ 토큰·지연(동률일 때만). W2 스모크 테스트(표본 1건, #121)에서 나온 두 가지가 측정 축이다 — `think:false` 미작동(`/no_think` 시 형식 붕괴 → 토큰 예산 반영), 1.7B 의 근거 인용이 더 좁음(크기가 크다고 유리한 축이 아니다).

> R1~R6 는 선행 PoC 인물이라 **저장소에 없다.** 조건 몇 개를 손으로 적어 넣는다.

비교 기준은 외부 AI의 성능이다(**선행 PoC 자체 측정** — R1~R5는 7/7, R6는 6/7 · 위험도 70.0~83.0). **4주차 설계서에 모델 크기를 확정해서 써야 하므로 W3 안에 낸다.**

> 8B는 후보에서 뺐다. 추론에 6GB VRAM이 필요한데 일반 노트북 기준을 벗어난다.

**소형 모델로 충분할 거라는 근거**: 2단은 원문이 아니라 **1단이 정리해준 스팬·유형·k값**을 받는다. 자유 추론이 아니라 구조화된 입력 → 구조화된 출력이라 작은 모델에 유리하다. 다만 **리라이트 품질과 흩어진 단서를 엮는 능력이 먼저 무너질 지점**이니 가정하지 말고 측정으로 확인한다.

## 5. triage — 비용을 줄이는 장치

글 1,000개를 전부 2단에 넣으면 느리고 비싸다. 그래서 **1단 결과를 보고 "2단까지 갈 필요가 있는 글"만 고른다.**

목표: **AI 처리량 70% 이상 절감하면서 놓치는 비율은 10% 이하.**

이게 되면 *"우리 모델은 큰 AI를 대체하지 않는다. 부를 필요가 없게 만들고, 꼭 불러야 할 때만 부른다"* 는 논거가 숫자로 뒷받침된다.

## 7. 목표 수치

| 지표 | 목표 | 계층 |
|---|---|---|
| **Qwen3 vs 외부 AI 속성 적중 일치율** | **≥ 0.8** | 목표 ⭐ |
| 조치 3단계 적용 시 위험도 하락 | **선행 PoC 자체 측정** −54~61% 수준 재현 | 필수 |
| 추천 품질 — 추천 조치 vs 최적해의 격차 | ≤ 15% | 목표 |
| triage 효율 | 70%+ 절감 / 재현율 ≥ 0.9 | 도전 |
| 의미 보존 (리라이트 전후) | 임베딩 유사도 + 가독성 평가 | 목표 |

> **일치율 0.8이 핵심이다.** 이게 안 나오면 *"외부 전송 0"* 이 성립하지 않는다 — 로컬 모델로 충분하다고 말할 수 없기 때문이다.

> ⚠️ **정확도 계열 지표를 단독으로 쓰지 않는다** [MF-012 · 2026-09-02].
> 멘토 피드백: 「탐지 성능을 단순 정확도만으로 평가하지 마라. F-score 등을 함께 보라.」
>
> exp05 재채점에서 그 이유가 확인됐다 — **클래스 불균형(양성 73.1%) 때문에 다수 클래스로만
> 찍는 더미가 이미 73.1%** 였다. 두 모델의 실질 차이는 정확도가 아니라 **특이도**(.803 vs .712)에
> 있었고, 정확도는 그걸 흐렸다.
>
> **2단 평가에 함께 쓸 지표**
>
> | 지표 | 왜 |
> |---|---|
> | **속성별 F1 + 혼동행렬** | 어느 속성이 약한지가 보인다. 총계는 안 보여준다 |
> | **특이도 / FPR** | 우리 실패는 미탐이 아니라 **오탐**이다 (FN 3 · FP 13) |
> | **MCC** | 불균형 이진 분류의 단일 요약치 |
> | **McNemar (대응표본)** | 모델 비교에서 「차이가 우연인가」를 답한다 |
> | 인물 단위 cluster bootstrap | 칸이 인물 안에 군집돼 있어 독립 가정이 깨진다 |
>
> **위 「일치율 ≥ 0.8」도 정확도 계열이다.** W4 설계서에서 macro F1 기준으로 바꿀지
> B(1단 지표 소유)와 함께 정한다 — 이 수치가 「외부 전송 0」 주장의 근거라 혼자 바꾸지 않는다.

## 8. 다른 역할과 주고받는 것

| 상대 | 내가 주는 것 | 내가 받는 것 |
|---|---|---|
| **C** | 가명화 규칙 (사전 공유) · 복원 시 오프셋 저장 규약 | **지명 사전**, k값, 글별 기여도(`delta`, 음수), **`greedy_min_set` 함수**(W9 인계) |
| **B** | — | 탐지된 스팬 + 유형 (2단의 입력) |
| **A** | 필요한 라벨 형식 | 리라이트 학습용 문장 쌍 |
| **E** | 판정 결과, 추천 조합, 리라이트 문장 | 화면 표시 형식, 에디터 경고 연동 |

> ⚠️ **C와 같은 사전을 쓴다.** 내 가명화("상도동 → [서울의 특정 동]")는 C의 특정성 계산("이 지명은 몇 명으로 좁히나")의 **역함수**다. 사전이 어긋나면 복원이 깨진다. 2주차 인터페이스 합의에 C와 함께 들어간다.

## 9. 막히기 쉬운 지점

| 상황 | 대처 |
|---|---|
| QLoRA 학습이 안 된다 | **폴백이 있다.** 프롬프트만으로 돌려도 구조는 유지된다. 혼자 붙잡지 말고 팀에 알린다 |
| VRAM이 부족하다 | gradient checkpointing, 배치 1. 그래도 안 되면 클라우드 — 학습 데이터가 합성이라 외부 실행에 문제없다 |
| 복원이 깨진다 (가명 → 원문 매핑 실패) | 치환 시 **위치 정보(오프셋)를 함께 저장**한다. 문자열 치환만으로 되돌리려 하면 반드시 깨진다 |
| 리라이트가 의미를 망가뜨린다 | 문장 전체를 다시 쓰지 말고 **단서 구간만** 교체하도록 제약한다 |
| 추천 조합 탐색이 느리다 | 전수 탐색 대신 기여도 상위부터 그리디로. **최적해일 필요는 없다** — 목표는 격차 15% 이내 |
| 모델이 신상을 단정해버린다 | 의도적으로 막아야 한다. 출력 형식을 *"~가 특정 가능함"* 으로 고정하고, 실제 지명·이름을 산출하지 않게 한다 |
| 파인튜닝을 해본 적이 없다 | QLoRA는 라이브러리가 대부분 처리한다. 데이터 형식과 프롬프트 템플릿만 맞추면 나머지는 정형화되어 있다 |
