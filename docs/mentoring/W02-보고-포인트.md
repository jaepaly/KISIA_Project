## 🔴 이번 주 안에 방향이 나와야 하는 것

### 0. 본 생성 경로를 정할 근거가 아직 없다 ⭐ **가장 급함**

> 2026-08-26 수요일에 새로 생긴 논점이다. 아래 넷보다 먼저 꺼낸다 — **W3가 M1 판정 주간이라 다음 주에 말하면 늦는다.**

#### 어디까지 왔나

오늘까지 나온 것은 **인물 2명 · 글 17편**이다. 그리고 **이건 시범 물량으로는 계획대로다** — [#16](../../issues/16)이 수요일 시범을 **20편**으로 잡았다.

> ⚠️ `README` M1 표는 아직 「W2 수요일 200편」이다. #16에서 20편으로 낮추면서 README를 안 고쳤다. **PM 정리 사항이고 A의 실적 문제가 아니다.** 이 문서를 근거로 A를 평가하지 않는다.

#### 막는 것이 토큰이 아니라 요청 횟수였다

A의 실측(#44, 이틀 연속)이 이렇게 나왔다.

```
RPD  하루 20회에서 429           ← 여기서 막힌다
TPM  9.06K / 250K = 3.6%         ← 토큰은 27배 여유
편당 1,785 토큰 / 14초
```

**토큰은 남는데 호출 횟수에서 막힌다.** 무료 등급이 그렇게 걸려 있다.

그래서 **계정을 늘리는 것이 개인 결제 없이 처리량을 올리는 유일한 방법**이고, W2 주간회의(08-25)에서 그렇게 정했다.

| | |
|---|---|
| 인물 JSON 작성 | A 20명 + **B·C·D·E 각 20명** |
| **생성 실행** | **A·B·C·D가 각자 자기 계정으로** 같은 파이프라인을 돌린다 |

A가 `llm.py`에 호출부를 갈아끼울 수 있게 만들어둬서(#16 §4-①) **경로만 바꿔 쓴다.**

```bash
python -m kopl.c5_corpus.generate --provider cli --cli-cmd "codex exec -"
```

#### 그런데 그 경로의 처리량을 아직 모른다

**Codex는 API가 아니라 구독 사용량으로 제한된다.** RPD와 성격이 달라서, Gemini 측정치를 그대로 못 쓴다.

```
총량      3,000편 × 1,785토큰  ≈  5.4M 토큰
4인 분담  1인당 약 1.3M 토큰 · 750편
W3 금까지 근무일 7일  →  1인당 하루 107편
```

**하루 107편이 각자 계정에서 나오는지가 M1 성패를 가른다.** 지금 그 숫자가 없다.

**측정은 오늘 밤에 된다** — 파이프라인이 이미 있고 넷 다 계정이 있다. 한 시간씩만 돌려보고 편수·소요시간을 적으면 목요일 보고에 실제 숫자가 들어간다.

#### 3,000이 무엇에 묶여 있나 — 임의 숫자가 아니다

```
노이즈 70~80%          →  단서 있는 글은 20~30%
3,000 × 20~30%         =  600~900편
                          여기서 골드셋 600~700 스팬이 나온다
```

즉 **코퍼스를 줄이면 골드셋이 같이 줄고**, 골드셋이 줄면 **B의 F1과 IAA 신뢰구간이 넓어진다.** 그리고 그 F1이 논점 1의 「기존 도구 대비 추가 탐지율」을 재는 잣대다. **0번과 1번이 같은 숫자에 걸려 있다.**

#### 모자랄 때의 예비 수단

| | 수단 | 상태 | 걸리는 것 |
|---|---|---|---|
| ① | AWS Bedrock 오픈웨이트 | **크레딧 미도착** | 나오면 가장 깨끗하다. **팀 자원이라 개인 계정 부담이 없다** |
| ② | Kaggle 무료 GPU + Gemma | 미검증 | 주 30h 무료. `plan.md` §9에 이미 있다 |
| ③ | 유료 구독 분담 | — | **개인 결제는 하지 않기로 했다** |
| ④ | **인물당 글 수를 하한으로** | 언제든 | 물량 자체를 줄이는 유일한 «선언된 범위 안» 조정 |

#### PM 제안 — 오늘 밤 측정, ④를 안전판으로

**측정이 먼저다.** 넷이 한 시간씩만 돌려보면 목요일 보고에 감이 아니라 숫자가 들어간다.

**④는 물량이 모자랄 때의 안전판이다.** `plan.md` §5가 인물당 **15~30글**이라고 이미 적어뒀으니 하한을 쓰는 건 계획 변경이 아니다.

```
인물 100명 × 15글  =  1,500편        (3,000 → 절반)
```

**인물 수는 그대로 둔다.** 노이즈 비율도, 생활권·소재 다양성도, k값 분포도 전부 **인물 수**에서 나온다. 줄여야 한다면 글 수지 인물 수가 아니다.

누적 곡선은 견딘다 — 선행 PoC 실측이 **1편 26.7 → 5편 69.2 → 19편 79.7**이라, 15편이면 곡선의 대부분이 그려진다.

#### 멘토께 여쭐 것

**하나.** 무료 등급 한도 때문에 **팀원이 각자 개인 계정으로 코퍼스를 생성하는 구조**가 됐습니다. 개인 결제 없이 가는 전제는 지켰지만, **개인 구독으로 만든 산출물을 프로젝트 결과물로 제출하는 것**이 문제가 되지 않는지 확인이 필요합니다. 아니면 지금 협회에 **생성용 자원을 따로 요청**하는 편이 나은지도요.

**둘.** 물량이 모자라면 **「코퍼스 3,000편」을 1,500으로 낮추려 합니다**(인물 수는 유지, 인물당 글 수를 하한으로). 이게 성공 기준 문구에 들어가 있어서, 8주차 중간점검에서 **계획 미달로 볼지 조정으로 볼지**가 갈립니다. 지금 합의해두는 편이 안전하다고 판단했는데 맞습니까.

> ⚠️ **노이즈 비율(70~80%)은 건드리지 않습니다.** 그걸 낮추면 편수는 벌지만 **우리가 「현실적인 글」을 다룬다는 주장 자체가 약해집니다.** 그건 조정이 아니라 전제를 버리는 것입니다.

### 1. 「기존 도구 대비 추가 탐지율」을 중단 기준으로 두는 것

**왜 이번 주가 마지막인가 — M1 판정이 다음 주(W3)다.**

Presidio·korean-pii가 놓치는 준식별자 중 우리가 잡는 비율을 모델 지표 1순위로 두고, **W3에 이 값이 유의미하게 나오지 않으면 주제를 재검토**하는 중단 기준(kill criterion)으로 삼으려 한다.

합의되지 않은 중단 기준을 다음 주에 마주하면, 수치가 나쁠 때 *"기준이 잘못됐다"* 와 *"주제가 잘못됐다"* 를 구분할 수 없다.

**보고에 얹는 법**: W3 계획을 설명하면서 *"베이스라인 3종을 재는데, 이 수치를 중단 기준으로 쓰려 합니다"* 로 꺼낸다.

- 담당: B(측정) · E(지표 정의)
- 반영위치: 주제선정서 「지표」 [목표] 계층 · M1 베이스라인 3종 실험 설계

동의받은 실블로거 10~20명 대상 외적 타당성 검증을 계획하고 있다. 두 가지가 걸린다.

### 3. 12주 압축 시 스코프 컷 우선순위

원 계획(4개월 ≈ 17.4주)이 12주로 압축되어 M3에 −53%의 부채가 몰린다. 팀 판단 순서는 —

> 적대적 회피 루프 1라운드로 축소 → 노이즈 견고성 삭제 → 에디터 실시간 경고 스코프 아웃

**⚠️ 이 순서는 재산정이 필요하다.** [MF-001](../mentor-log.md)로 ⑦이 브라우저 확장에서 자체 가상 SNS로 바뀌면서 **에디터 실시간 경고는 자체 에디터라 난이도가 오히려 내려갔다.** 마지막에 자를 후보가 아닐 수 있다.

**이번 주 수행계획서 12행 그리드가 이 우선순위 위에 서 있다.** 목요일에 초안을 보이면서 함께 짚는다.

- 담당: PM
- 반영위치: W2 수행계획서 「주차별 수행 계획」

### 4. 지표 3계층 + W4 갱신 게이트

[필수]/[목표]/[도전] 3계층으로 선언하고, [목표] 수치는 M1(W3) 실측 후 **W4 설계서에서 멘토 승인 하에 1회 갱신**하는 방식.

**이 항목이 10주차 「당초 목표 / 목표값」 열로 되돌아온다.** 여기서 합의해두면 W4·W8 조정이 *"말 바꾸기"* 가 아니라 *"계획대로"* 가 된다.
