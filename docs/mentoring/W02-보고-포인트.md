## 🔴 이번 주 안에 방향이 나와야 하는 것

### 0. 코퍼스 3,000편이 산술로 안 나온다 ⭐ **가장 급함**

> 2026-08-26 수요일에 새로 생긴 논점이다. 아래 넷보다 먼저 꺼낸다 — **W3가 M1 판정 주간이라 다음 주에 말하면 늦는다.**

**사실부터 말한다.**

| | 계획 (`README.md` M1 코퍼스) | 실적 (08-26 18:00) |
|---|---|---|
| **W2 수요일까지** | 인물 **10명** · 글 **~200편** | 인물 **2명** · 글 **17편** |
| | | 인물 20% · **글 8.5%** |

**원인은 추측이 아니라 실측이다.** A가 생성 파이프라인 v2(#44)에서 **이틀 연속** 확인했다.

```
gemini-3.6-flash 무료 한도  RPD 20
편당 1,785 토큰 / 14초
20편을 넘기면 429
```

**남은 산술.**

```
W3 금(09-04)까지 근무일                        7일
5인이 «각자» 계정으로 돌릴 때   20 × 5 × 7  =  700편
목표                                         3,000편
                                             → 23%

3,000을 맞추려면 1인당 하루 86편  =  실측의 4.3배
```

**5인이 전원 붙어도 4분의 1이다.** 이건 노력이나 배분으로 메우는 차이가 아니다.

#### 3,000이 무엇에 묶여 있나 — 임의 숫자가 아니다

```
노이즈 70~80%          →  단서 있는 글은 20~30%
3,000 × 20~30%         =  600~900편
                          여기서 골드셋 600~700 스팬이 나온다
```

즉 **코퍼스를 줄이면 골드셋이 같이 줄고**, 골드셋이 줄면 **B의 F1과 IAA 신뢰구간이 넓어진다.** 그리고 그 F1이 논점 1의 「기존 도구 대비 추가 탐지율」을 재는 잣대다. **0번과 1번이 같은 숫자에 걸려 있다.**

#### 선택지와 각각이 깨뜨리는 것

| | 안 | 얻는 것 | 깨지는 것 |
|---|---|---|---|
| ① | 유료 전환 | 한도 해소 | 비용. **지원받기로 한 범위는 Claude API·AWS 뿐이고 Gemini는 없다** |
| ② | 모델 교체 (코덱스, [#16](../../issues/16)) | 무료 한도가 다를 수 있다 | 재측정 시간 · 문체 특성이 달라 프롬프트를 다시 잡아야 한다 |
| ③ | 목표 하향 3,000 → 1,000 | 일정 준수 | 골드셋 200~300 스팬. **추가 탐지율의 신뢰구간이 넓어진다** |
| ④ | 노이즈 비율 하향 | 같은 편수로 더 많은 스팬 | 🔴 **리얼리즘이 깨진다.** 노이즈 70~80%가 이 프로젝트의 전제다 |
| ⑤ | **인물당 글 수를 하한으로** | 인물 다양성은 유지 | 누적 곡선이 짧아진다 |

#### PM 제안 — ⑤를 먼저, 그다음 ①을 며칠

**⑤가 유일하게 «선언된 범위 안»의 조정이다.** `plan.md` §5가 인물당 **15~30글**이라고 이미 적어뒀다. 하한을 쓰면 이렇게 된다.

```
인물 100명 × 15글  =  1,500편        (3,000 → 절반)
```

**인물 수를 그대로 두는 게 중요하다.** 노이즈 비율도, 생활권·소재 다양성도, k값 분포도 전부 **인물 수**에서 나온다. 줄여야 한다면 글 수지 인물 수가 아니다.

누적 곡선은 견딘다 — 선행 PoC 실측이 **1편 26.7 → 5편 69.2 → 19편 79.7**이라, 15편이면 곡선의 대부분이 그려진다.

**그래도 1,500 ÷ 7일 ÷ 5인 = 43편/일/인으로 실측의 2.1배가 남는다.** 여기서 ①(유료 며칠) 또는 W4로 일부 이월이 필요하다.

#### 멘토께 여쭐 것

**「코퍼스 3,000편」이 성공 기준 문구에 들어가 있는데, 이걸 1,500으로 낮추면 8주차 중간점검에서 어떻게 설명해야 합니까.**

계획을 못 지킨 것으로 볼지, **실측에 근거해 조정한 것으로 볼지**가 갈립니다. 후자로 인정받으려면 지금 이 자리에서 합의해두는 것이 안전하다고 판단했습니다.

그리고 **③과 ④ 중에서는 ③이 맞다고 보는데** — 노이즈 비율을 낮추면 편수는 벌지만 **우리가 「현실적인 글」을 다룬다는 주장 자체가 약해집니다.** 이 판단이 맞는지 봐주시면 좋겠습니다.

### 1. 「기존 도구 대비 추가 탐지율」을 중단 기준으로 두는 것

**왜 이번 주가 마지막인가 — M1 판정이 다음 주(W3)다.**

Presidio·korean-pii가 놓치는 준식별자 중 우리가 잡는 비율을 모델 지표 1순위로 두고, **W3에 이 값이 유의미하게 나오지 않으면 주제를 재검토**하는 중단 기준(kill criterion)으로 삼으려 한다.

합의되지 않은 중단 기준을 다음 주에 마주하면, 수치가 나쁠 때 *"기준이 잘못됐다"* 와 *"주제가 잘못됐다"* 를 구분할 수 없다.

**보고에 얹는 법**: W3 계획을 설명하면서 *"베이스라인 3종을 재는데, 이 수치를 중단 기준으로 쓰려 합니다"* 로 꺼낸다.

- 담당: B(측정) · E(지표 정의)
- 반영위치: 주제선정서 「지표」 [목표] 계층 · M1 베이스라인 3종 실험 설계

### 2. M4 실블로거 검증 — IRB와 제3자·미성년 정보

동의받은 실블로거 10~20명 대상 외적 타당성 검증을 계획하고 있다. 두 가지가 걸린다.

1. **IRB(연구윤리심의)가 필요한지.** 신속심의도 2~4주라 12주 일정과 충돌한다.
2. **동의자 글에 등장하는 제3자·미성년 정보**(자녀·지인)를 어떻게 다루는지. 참여자 본인 동의로는 커버되지 않는다.

`plan.md` §12가 M4 검증을 **「보너스 구조」**로 규정했으므로 무산돼도 프로젝트는 성립한다. 다만 **하려면 지금 착수해야** 일정에 들어간다.

- 담당: E
- 반영위치: `plan.md` §6 검증 프로토콜 · §13.5 · W4 설계서 「보안·윤리」

### 3. 12주 압축 시 스코프 컷 우선순위

원 계획(4개월 ≈ 17.4주)이 12주로 압축되어 M3에 −53%의 부채가 몰린다. 팀 판단 순서는 —

> 적대적 회피 루프 1라운드로 축소 → 노이즈 견고성 삭제 → 에디터 실시간 경고 스코프 아웃

**⚠️ 이 순서는 재산정이 필요하다.** [MF-001](../mentor-log.md)로 ⑦이 브라우저 확장에서 자체 가상 SNS로 바뀌면서 **에디터 실시간 경고는 자체 에디터라 난이도가 오히려 내려갔다.** 마지막에 자를 후보가 아닐 수 있다.

**이번 주 수행계획서 12행 그리드가 이 우선순위 위에 서 있다.** 목요일에 초안을 보이면서 함께 짚는다.

- 담당: PM
- 반영위치: W2 수행계획서 「주차별 수행 계획」

### 4. 지표 3계층 + W4 갱신 게이트

[필수]/[목표]/[도전] 3계층으로 선언하고, [목표] 수치는 M1(W3) 실측 후 **W4 설계서에서 멘토 승인 하에 1회 갱신**하는 방식.

특히 **암묵 스팬 F1을 절대 숫자(0.60)가 아니라 「M1 IAA 측정치의 80% 이상」이라는 상대 기준**으로 두는 것.

**이 항목이 10주차 「당초 목표 / 목표값」 열로 되돌아온다.** 여기서 합의해두면 W4·W8 조정이 *"말 바꾸기"* 가 아니라 *"계획대로"* 가 된다.

- 담당: E(지표 주도) · PM(문서)
