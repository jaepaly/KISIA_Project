# 행정구역·인구 사전 자료구조

> 담당: C · 특정성·누적  
> 작업: W2 화~수 — 사전 자료구조 설계  
> 기준월: 2026-07  
> `dict_version`: `geo-2026-07`

이 문서는 W2에서 구축할 **행정구역 + 인구 사전의 자료구조**를 고정한다.

이번 주에는 **행정구역과 인구까지만** 다룬다.  
시설·랜드마크는 W4에 `facilities.json`으로 추가한다.

---

## 1. 이번 주 산출물

기존 C 역할 문서의 산출물 이름과 경로를 그대로 따른다.

```text
data/dict/admin/
├── README.md
├── regions.json
└── population.csv
```

- `regions.json`: 행정구역 코드·이름·계층·총인구
- `population.csv`: 읍면동 × 5세 연령구간 × 성별 인구

원본 데이터와 재현 스크립트의 저장 위치는 실제 구축 단계에서 정리한다.

## 2. 논리 자료구조

행정구역 사전은 다음 계층으로 본다.

```text
시도
└─ 시군구
   └─ 읍면동
      ├─ 총인구
      └─ 5세 연령구간
         └─ 성별
            └─ 인구수
```

실제 2026-07 자료 예시:

```text
서울특별시 (1100000000)
└─ 성동구 (1120000000)
   └─ 성수1가제1동 (1120065000)   총인구 14,748
      ├─ 40-44
      │  ├─ M → 558
      │  └─ F → 515
      └─ ...
```

시설·랜드마크는 이번 주 구조에 포함하지 않는다.

---

## 3. 지역 코드 기준

프로젝트의 지역 코드 정본은 **주민등록 인구통계에서 사용하는 행정구역 코드**다.

- 코드값은 **10자리 문자열**로 저장한다.
- `geo-dictionary.md`와 동일한 `geo_code` 체계를 사용한다.
- 법정동코드는 인구 조회의 직접 키로 사용하지 않는다.

예:

```text
신갈동 법정동코드       4146310100
신갈동 행정구역 코드    4146351000  ← 프로젝트에서 사용하는 geo_code
```

글에서 법정동 이름 또는 법정동코드가 들어오는 경우에는
행정안전부의 법정동↔행정동 대응자료를 이용해 행정구역 `geo_code`로 변환한 뒤 조회한다.

```text
법정동 이름/코드
      ↓
법정동 ↔ 행정동 대응
      ↓
행정구역 geo_code
      ↓
regions.json / population.csv
```

하나로 확정할 수 없는 경우에는 임의로 하나를 선택하지 않고
`ambiguous=true`와 `candidates`를 사용한다.

세부 규칙은 `docs/contracts/geo-dictionary.md`를 따른다.

## 4. `regions.json`

### 역할

`regions.json`은 **행정구역 계층 사전**이다.

다음 정보를 담당한다.

- 행정구역 코드 ↔ 이름
- 상위·하위 행정구역 관계
- 기준월 총인구
- 동일 지명에 대한 후보 코드 목록

### 목표 구조

```json
{
  "schema_version": "1.0",
  "dict_version": "geo-2026-07",
  "source": "행정안전부 주민등록 인구통계 2026-07",
  "regions": {
    "1120065000": {
      "code": "1120065000",
      "name": "성수1가제1동",
      "full_name": "서울특별시 성동구 성수1가제1동",
      "level": "emd",
      "parent": "1120000000",
      "sido": "서울특별시",
      "sigungu": "성동구",
      "population": 14748,
      "aliases": ["성수1가제1동"]
    }
  },
  "name_index": {
    "성수1가제1동": ["1120065000"]
  }
}
```

### 지역 레코드

| 필드 | 의미 |
|---|---|
| `code` | 주민등록 인구통계 기준 행정구역 코드 |
| `name` | 행정구역의 짧은 이름 |
| `full_name` | 시도부터 포함한 전체 이름 |
| `level` | 행정구역 단계 (`sido`, `sigungu`, `emd`) |
| `parent` | 바로 위 행정구역 코드 |
| `sido` | 시도명 |
| `sigungu` | 시군구명 |
| `population` | 2026-07 기준 총인구 |
| `aliases` | 지명 검색에 사용할 별칭 |

`population`은 주민등록 인구 및 세대현황의 **공식 총인구 값**을 사용한다.

### `name_index`

같은 이름의 동이 전국에 여러 개 있을 수 있으므로,
이름 하나를 코드 하나에 고정하지 않고 **코드 배열**로 저장한다.

```json
{
  "중앙동": [
    "4113352500",
    "4122051000",
    "4146151000"
  ]
}
```

조회 흐름:

```text
"중앙동"
   ↓
name_index
   ↓
후보 코드 배열
   ↓
상위 지역 단서로 후보 축소
```

후보가 하나로 좁혀지지 않으면 `geo-dictionary.md`의
`ambiguous + candidates` 규칙을 따른다.

## 5. `population.csv`

### 역할

`population.csv`는 **읍면동의 연령·성별 인구 교차표**다.

특정성 계산에서 사용하는 기본 조회 키는 다음 세 축이다.

```text
(geo_code, age_band, sex)
```

### 목표 형식

```csv
geo_code,age_band,sex,population
1120065000,40-44,M,558
1120065000,40-44,F,515
4146351000,40-44,M,1312
4146351000,40-44,F,1138
```

| 컬럼 | 의미 |
|---|---|
| `geo_code` | 주민등록 인구통계 기준 읍면동 행정구역 코드 |
| `age_band` | 5세 단위 연령구간 |
| `sex` | `M` 또는 `F` |
| `population` | 해당 조건에 속하는 인구수 |

### 연령구간

연령구간은 다음 21개 값으로 고정한다.

```text
0-4
5-9
10-14
15-19
20-24
25-29
30-34
35-39
40-44
45-49
50-54
55-59
60-64
65-69
70-74
75-79
80-84
85-89
90-94
95-99
100+
```

개방 구간은 `100+` 하나만 사용한다.

### 성별

```text
M = 남성
F = 여성
```

원본의 `계` 열은 `population.csv`에 중복 저장하지 않는다.

## 6. `regions.json`과 `population.csv`의 관계

### 지역만 있는 경우

```text
입력: "성수1가제1동"
        ↓
regions.json / name_index
        ↓
geo_code = 1120065000
        ↓
regions["1120065000"].population
        ↓
14,748
```

따라서 W2 목~금의 가장 단순한 프로토타입은 다음 조회가 되면 된다.

```python
specificity("성수1가제1동")
# → {"k": 14748, "k_level": "..."}
```

### 연령·성별까지 있는 경우

```text
geo_code = 1120065000
age_band = 40-44
sex = F
        ↓
population.csv
        ↓
515
```

연령·성별 조건을 실제 k 계산에 결합하는 것은 다음 단계에서 진행한다.

## 7. 사용 데이터

2026-07 기준으로 확보한 자료는 다음과 같다.

1. **주민등록 연령별 인구현황**
   - 읍면동
   - 5세 단위
   - 남/여 구분
   - `population.csv`의 주 원본

2. **주민등록 인구 및 세대현황**
   - 행정구역별 총인구
   - `regions.json`의 총인구 및 검산에 사용

3. **행정안전부 `jscode20260701.zip`**
   - `KIKmix.20260701`
   - 행정기관(행정동) ↔ 관할 법정동 대응에 사용

4. **법정동코드 전체자료**
   - 법정동 이름·코드 확인 보조

기준월은 **2026-07**로 고정한다.

출처·라이선스·확인일은 `data/README.md`의 라이선스 표에 별도로 기록한다.

## 9. 화~수 자료구조 설계 완료 기준

다음 구조를 기준으로 실제 파일을 구축한다.

- `regions.json` = 행정구역 코드·이름·계층·총인구
- `population.csv` = 읍면동 × 5세 연령구간 × 성별 인구
- 지역 코드 정본 = 주민등록 인구통계의 행정구역 코드
- 코드 저장형 = 10자리 문자열
- `population.csv` 조회 키 = `(geo_code, age_band, sex)`
- 동명이면 `name_index`에서 후보 코드 배열 반환
- 법정동코드는 행정구역 `geo_code`로 변환한 뒤 사용
- 시설·랜드마크는 이번 주 제외

이 구조가 W2 **화~수 — 사전 자료구조 설계의 확정안**이다.

## 10. 재현 방법

행정안전부 주민등록 인구통계에서 기준월 `202607`의 다음 CSV 두 개를
읍면동 단위·5세 구간으로 내려받는다. 원본은 CP949 인코딩이며 저장소에는
커밋하지 않는다.

- `202607_연령별인구현황_월간.csv`
- `202607_주민등록인구및세대현황_월간.csv`

저장소 루트에서 아래 명령을 실행한다.

```bash
python scripts/data/build_admin_population.py \
  --age "202607_연령별인구현황_월간.csv" \
  --total "202607_주민등록인구및세대현황_월간.csv"
```

스크립트는 `regions.json`과 `population.csv`를 UTF-8로 다시 만들고 다음을
검사한다.

- `(geo_code, age_band, sex)` 조회 키 중복 여부
- 읍면동별 21개 연령구간과 남녀 합계
- 두 원본의 읍면동 총인구 일치 여부
- 시도 합산 전국 총인구와 교차표 합계 일치 여부

2026-07 자료에서 연령별 원본에 없는 0명 읍면동 5개는 `regions.json`에는
포함하고 `population.csv`에서는 제외한다. 해당 지역의 총인구가 0이 아니면
스크립트가 실패한다.
