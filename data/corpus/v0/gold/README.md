# 골드셋 — 사람이 검수한 정답표

**W3 산출.** 600~700 스팬. **blind 200 은 C 단독이고 나머지 넷이 검수를 나눈다.**

```
data/corpus/v0/gold/<persona_id>_spans.jsonl          검수분      예: A11_spans.jsonl
data/corpus/v0/gold/blind/<persona_id>_spans.jsonl    blind 분    C 만
```

한 줄에 스팬 하나. JSONL 이다.

> ⚠️ **인물 단위로 나눈다. 작업자 이니셜로 나누지 않는다** (`label-schema` §8).
> 생성 산출물이 이미 인물 단위(`posts/A11.jsonl`)라 1:1 로 대응시키면 병합·재생성·부분 재라벨이 파일 하나 단위로 끝난다. 이니셜로 나누면 인물이 여러 파일에 흩어져 재생성 때 추적이 어렵다.

## ⭐ 누가 무엇을 하나 — 섞으면 blind 가 무효가 된다

| 누가 | 무엇을 | 얼마나 | 언제 |
|---|---|---|---|
| **C 신정현** | **blind 200 — 교사 라벨을 보기 전에** | 200 | **화~수** |
| A · B · D · E | 교사 라벨 검수 | 각 100~125 | 수~금 |

`A-data.md` §5 가 이유까지 적어 못박았다.

> 원래는 blind 200을 마지막에 뒀었다. **그러면 blind가 성립하지 않는다.** ⑤ 검수를 한 사람은 교사 출력을 전량 본 뒤이고, 그 사람이 "정답을 안 보고" 매길 수는 없다.
>
> **blind 200은 C가 맡고, C는 `data/corpus/v0/gold/`(검수분)와 교사 라벨 원본에 접근하지 않는다.**

**C 는 검수를 하지 않고, 나머지 넷은 blind 를 하지 않는다.**

blind 표본은 **골드셋과 겹치지 않는 별도 글**에서 **층화 무작위**로 뽑는다. ⚠️ **층화 단위는 스팬이 아니라 글이다** — 스팬 등급으로 층화하려면 라벨이 이미 있어야 해서 blind 가 성립하지 않는다. 층화 키는 인물 JSON `clue_plan[].level` 분포를 쓴다. 추출 스크립트(`scripts/sample_gold.py` — 저장소에 없다, A 가 월요일에 만든다)와 seed 를 커밋하고 **커밋 해시를 리포트에 적는다.**

## 레코드 형식 — `label-schema` §8-1

```json
{"span_id": "S01_b07_s02", "text_id": "body", "start": 12, "end": 17, "text": "신갈저수지", "type": "LOC_FACILITY", "level": "inferential", "subject": "self"}
```

**붙는 필드는 이 8개까지.** ⚠️ `blind` 같은 필드를 새로 만들지 않는다 — **blind 분은 디렉터리로 가른다.**

| 필드 | 무엇 |
|---|---|
| `span_id` | **안정 식별자.** `<인물>_<글>_s<번호>` — D 의 판정 근거가 이 값을 가리킨다 |
| `text_id` | offset 의 기준 텍스트. `title` · `body` · `photo_caption:N` · `profile_bio` 넷 (§5-3) |
| `start` `end` | ⚠️ **문자 offset.** 바이트나 토큰 인덱스가 아니다 |
| `text` | 그 구간의 문자열. `start`/`end` 가 맞는지 눈으로 확인하는 용도 |
| `type` | `LOC_FACILITY` `AGE` `JOB` `FAMILY` `COMMUTE` `INCOME` `SEX` `REL_WORK` … |
| `level` | `explicit` / `implicit` / `inferential` (§4-1) |
| `subject` | `self` / `other` / `unknown` (§4-2) |

프로필 스팬은 `text_id: "profile_bio"` 이고 `post_id` 가 `<인물>_profile` 이라 `span_id` 는 `A11_profile_s01` 형태가 된다.

## ⚠️ 자주 틀리는 것 넷

### ① 겹치는 스팬은 금지 — 최장 우선

BIO 표기가 겹침을 표현하지 못한다.

```
○  (0,4) 집 근처  +  (5,10) 신갈저수지          겹치지 않으면 둘 다
✗  (0,10) 집 근처 신갈저수지 + (5,10) 신갈저수지   겹친다. 긴 쪽만
```

### ② `level` 은 **표기 형식과 무관**하다

`explicit` 은 「값이 그대로 적힘 · 단독으로 값이 나온다」이다. **한글 수사도 `explicit`** 이다.

```
explicit       마흔여덟 · 34살 · 2호선
implicit       완성차 공장 출장 · 원두 발주       ← 단독으로 업종이 거의 확정
inferential    신갈저수지 · 집 근처               ← 다른 스팬과 묶여야 좁혀진다
```

> 「시험이 일주일 남았다」에는 **나이 값이 없다.** `explicit` 이 아니라 `inferential` 이다.

### ③ `subject` 는 **그 스팬의 주체**이지 글 전체의 시점이 아니다

「처남이 광교 살아서 거기 저수지에서 봤다」에서 광교에 사는 사람은 처남이다 → `subject: "other"`. **글의 나머지가 내 이야기여도 그렇다.**

### ④ 밈과 세대 신호는 **스팬으로 잡지 않는다** (§7)

| 무엇 | 어디로 |
|---|---|
| 밈·유행어 (손민수 · 정병 · 에바) | `flags.meme_hits` |
| 세대 신호 (「무릎이 예전 같지 않네요」) | `flags.gen_signal` |

**스팬에 넣으면 라벨러끼리 갈린다.** B 의 암묵 F1 목표치가 IAA 에 묶여 있어서, 갈리는 항목을 넣으면 **목표치까지 같이 깎인다.**

## IAA 파일럿 — A·C 만, 목요일

⚠️ **blind 와 다른 작업이다.** 여기서만 A 와 C 가 **같은 글 20편**을 각자 매긴다.

정의는 `A-data.md` 가 확정했다.

| 항목 | 확정 |
|---|---|
| 지표 | **pairwise 스팬 F1** — 한 명을 정답, 다른 한 명을 예측으로 두고 양방향 평균 |
| 경계 일치 | **overlap** (부분 일치 허용) |
| 유형 일치 | **필수** — 구간이 겹쳐도 유형이 다르면 불일치 |
| 산출 단위 | `explicit` / `implicit` / `inferential` **등급별로 따로** ⭐ |

> ⚠️ **전체 평균만 내면 안 된다.** B 가 쓰는 값은 **암묵 단서 IAA** 다. 명시 단서의 높은 일치도가 섞이면 B 의 목표치가 부풀려진다.

계산은 `scripts/iaa.py` (C 가 이번 주에 만든다).
