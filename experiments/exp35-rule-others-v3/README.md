## 2. 판정 (사전 등록 · exp34 §2 와 같다)

패턴마다 ① 정답 문장 재현율 ≥ 0.75 ② A 가 맞힌 반례를 R 이 틀리는 수 ≤ 1 → 통과한 패턴만 남긴다. 남긴 규칙 전체로 ③ 반례 새 오답 합 ≤ 3 · R 정답 ≥ A ④ 골드 사람 검수 lost ≤ 1 · 전체 lost ≤ 5 · R 일치 ≥ A ⑤ 단위 테스트 · 최악 시간 ≤ 0.05초. 채점은 `score.py`(exp34 와 같은 코드).

- 이번에도 떨어진 패턴은 동결 전에는 접는다(판정셋을 또 만들어 맞추는 일을 끝없이 하지 않는다)

### 판정 뒤 Codex 검토 반영 (사후 · 좁히기만)

- Codex 가 배포판(P3 만)에서 실행으로 찾은 것: ① 「설레는 마음은 ⟦서른⟧인 지금도」 → other(실제 나이) ② 「방년 ⟦스물셋⟧입니다. 오늘도 웃음 가득한」 → other(다른 문장의 「웃음」을 농담 단서로 봄) ③ 공백 압축(`_squeeze`)은 스위치와 무관하게 늘 적용된다
- ① 은 「나이 + 인 · 이 된 · 넘은 + 지금 · 올해 · 나 …」를 실제 나이로 보고 막았고(`_AGE_REAL_NOW`), ② 는 농담 단서를 같은 문장에서만 찾게 했다. 둘 다 P3 를 **좁히기만** 한다
- 같은 판정셋으로 다시 재면(사후 · 판정 아님) P3 23/30 그대로 · 반례 새 오답 1 → **0**(N2-P3-025 가 ① 과 같은 꼴) · 골드 변화 0 · 최악 0.003초. 대가로 「방년 스물둘! 이라고 하면 다들 웃더라」(exp34 개발셋)는 다시 self 가 된다 — 느낌표에서 문장이 끊긴다
- ③ 은 **남긴다** — main 이 긴 공백에서 느린 것(구현자 실측 5,000자 2.3초)을 막는 성능 수정이고, 바뀌는 판정은 공백이 두 칸 이상일 때 한 칸과 같게 읽는 것뿐이다(「그  사람은 [부산]에 산다」 main self → other · 한 칸일 때와 같다). 골드 변화 0
- 단위 테스트의 「넷 다 켜기」는 규칙 테스트에만 걸고, 기본값 검사는 모듈을 따로 불러 확인한다(Codex)

### 코퍼스 전수 확인 (사후 · 10/17 밤 · PM 「합성데이터들 대상으로 확인해본 거지?」)

- 판정셋은 짧은 합성 문장이라, **실제 1단이 긴 글에서 잡은 스팬**에 규칙을 대 보았다 — exp30 · 31 · 32 에서 받아 둔 1단(A0) 결과 중 test 밖 **2,481편 · 스팬 2,569개(AGE 97)**. 골드 라벨이 없는 1단 오탐 스팬도 들어간다
- **배포판(P3 만): main 과 달라진 스팬 0.** 코퍼스 본문에 나이 관용구가 사실상 없다 — 「마음만은 · 정신연령 · 이팔청춘 · 방년」 0회, 「속은 아직 · 입맛은 · 마음은 아직」 6회는 모두 나이가 아닌 말(「땅속은 아직 차갑다」 「입맛은 있나」)
- (참고) P1 · P2 까지 켜면 1개가 바뀐다 — 「옆집 살던 새댁이 ⟦목포로⟧ 이사 간다고」 self → other(골드와 맞는 쪽)
- 뜻: 생성 코퍼스에서 **해는 0 이지만 효과도 잴 수 없다**. P3 의 효과 근거는 합성 판정 문장뿐이다. 실제 글에 「마음만은 청춘」류가 얼마나 나오는지는 모른다
