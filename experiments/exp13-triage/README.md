# exp13-triage: 2단에 보낼 글을 골라도 판정이 유지되는가 — [도전] Triage

## 1. 무엇을 재나

roadmap §5 [도전] 「Triage — LLM 토큰 70%+ 절감하며 재현율 ≥ 0.9」. 1단 결과를 보고 2단까지 보낼 글만 고른다 (D-stage2.md §5).

**전제가 바뀐 점** — 목표를 세울 때는 LLM 이 원문을 읽는 구조였다. 지금 2단(Qwen3-4B v1)은 원문이 아니라 **가명 스팬 목록**만 받는다. 스팬이 없는 글은 원래 2단 입력이 거의 0 이라, 글을 골라도 줄어드는 몫이 작다. 그래서 비용을 두 가지로 센다.

| 비용 | 정의 |
|---|---|
| **2단 입력 토큰** (본 지표) | 2단 system + user prompt **내용**의 Qwen 토큰 수 (chat template 역할 토큰 제외 — 정책 간 비교용) |
| 원문 토큰 (참고) | 같은 글들의 원문(제목·본문·캡션) 토큰 수 — LLM 이 원문을 읽는 구조였다면의 비용 |

## 2. 설계

| 항목 | 값 |
|---|---|
| 표본 | 최상위 골드가 모든 글을 덮는 인물 92명 · 2,472편 (전체 이력 — 글이 많아야 triage 가 의미 있다). Qwen 은 그중 무작위 15명 · 418편 (seed 20261004) |
| 스팬 | 골드 본인(self) 스팬 — 1단 오차가 빠진 조건 |
| 정책 | **all** 모든 글 · **span** 본인 스팬이 1개 이상인 글 (계약 `triage_reason: span_density`) · **anchor** 속성마다 판정을 정하는 대표 글의 합집합 — 가장 높은 수준의 본인 스팬이 있는 글 1편, 그 수준이 inferential 이면 서로 다른 글 2편 (#279 판정 기준상 규칙 verdict 가 그대로 남는다 · 최소 집합은 아니다) |
| 2단 | Qwen3-4B 4bit + v1 어댑터 · greedy · `max_new_tokens` 1600 (`src/kopl/c4_stage2/infer.py`) |
| 측정일 | 2026-10-04 · RTX 3060 8GB |

## 3. 결과

### 비용 · 규칙 판정 (92명 · 2,472편)

| 정책 | 보내는 글 | 2단 입력 토큰 절감 | 원문 토큰 절감 (참고) | 규칙 판정 유지 |
|---|---|---|---|---|
| span | 49.5% | 12.1% | 46.7% | 100% (644/644) |
| **anchor** | **19.9%** | **51.9%** | **78.5%** | 100% (644/644) |

규칙 verdict 100% 는 anchor 정의상 당연한 값이다 (자기참조). verdict 외 필드는 바뀐다 — anchor 에서 규칙 판정의 `evidence` 293칸 · `cross_post` 103칸이 달라졌다 (근거 글이 줄어서).

### Qwen 2단 (15명 · 418편)

| 정책 | 보내는 글 | 2단 입력 토큰 절감 | 1명당 시간 | 파싱 실패 | **Qwen ↔ 규칙 판정 일치** | 규칙 비기권 칸 재현 | Qwen(all) 판정 대비 재현율 |
|---|---|---|---|---|---|---|---|
| all | 418 | — | 105.2초 | 1/15 | **0.653** (64/98) | 0.575 (46/80) | — |
| span | 197 | 12.9% | 88.5초 | 0 | 0.743 (78/105) | 0.686 (59/86) | 0.847 (61/72) |
| **anchor** | **81** | **52.6%** | **44.4초** | 0 | **0.752** (79/105) | 0.698 (60/86) | 0.722 (52/72) |

「Qwen(all) 대비 재현율」 = all 에서 기권이 아니었던 칸 중 같은 verdict 로 남은 비율 (all 이 파싱된 14명).

### 해석

1. **[도전] 목표는 정의한 그대로는 미달이다.** 2단 입력 토큰 절감은 anchor 52.6% 로 70% 에 못 미치고, Qwen(all) 판정 대비 재현율 0.722 로 0.9 에 못 미친다. 원문 토큰으로 세면 78.5~81.7% 지만 지금 2단은 원문을 읽지 않으므로 본 지표로 쓰지 않는다.
2. **다만 「all 대비 재현율」은 기준이 흔들리는 비교다.** 전체 이력을 다 넣으면 Qwen v1 이 규칙 판정과 0.653 만 맞는다 — v1 은 검수 글(인물당 10~30%)로 학습해 이렇게 긴 입력을 거의 보지 못했다. 처음 생성 한도 700 에서는 all 의 절반(6/12)이 출력이 잘려 파싱되지 않았다.
3. **이 실험에서는 글을 골라 보내자 Qwen 이 규칙 판정에 더 가까워지고 평균 추론 시간이 줄었다** — 규칙 일치 all 0.653 → anchor 0.752 (all 이 파싱된 같은 14명으로 맞추면 64/98 → 74/98) · 105초 → 44초. 규칙 verdict 는 보존되지만 근거 목록·cross_post 는 줄어든다. 골드 스팬 · 15명 · 학습 인물 중복 조건이라, 제품 2단 앞에 anchor triage 를 둘지는 실제 1단 예측으로 다시 잰 뒤 정한다.

## 4. 한계

- **골드 스팬** — 1단 오차가 빠졌다. 실제 1단 예측으로는 anchor 가 잘못된 글을 고를 수 있다
- **15명** · 단일 실행 (greedy 라 반복 변동은 없지만 표본이 작다)
- 규칙 판정은 독립 정답이 아니다 — 2단 학습 타깃이라 「Qwen ↔ 규칙」은 「학습한 규칙을 얼마나 재현하나」다
- 15명 중 일부는 SFT 학습 데이터에 다른 글(검수 글)로 나왔다 — all/anchor 를 같은 인물로 비교하므로 정책 간 차이에는 영향이 작다
- anchor 는 계약 `triage_reason` enum 에 없는 기준이다 (가장 가까운 값은 `span_density`) — 제품에 넣으려면 계약 PR

## 5. 재현

```bash
export PYTHONIOENCODING=utf-8 PYTHONPATH=src
python experiments/exp13-triage/run.py --rules-only                          # 비용·규칙 판정 (GPU 없이)
python experiments/exp13-triage/run.py --n 15 --batch 5 --max-new 1600       # Qwen — 5명씩 · 세 번 실행 (메모리 부족 중단 대비, 끝난 인물은 건너뜀)
```

결과: `results/metrics.json` · Qwen 판정 `results/model_runs_mx1600.jsonl` (가명 스팬 기준 판정만 · 원문 없음). 생성 한도 700 첫 실행분은 `model_runs.jsonl` (12명 · 비교용).
