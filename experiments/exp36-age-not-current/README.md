# exp36-age-not-current: 「지금 내 나이가 아닌 나이」 — 괄호 속 남의 나이 · 과거 나이

**왜** (10/17 밤 · PM 「①부터 ㄱㄱ」): 실제 글 3편(친구가 테스트용으로 준 글 · 원문은 저장소에 넣지 않는다) 중 2편에서 1단이 **지금 내 나이가 아닌 나이**를 글쓴이 나이(AGE self · explicit)로 셌다. 명시 나이는 사람을 가장 강하게 좁히는 단서라, 틀린 나이 하나가 같은 조건 사람 수(k)를 크게 어긋나게 한다.

| 패턴 | 실제 글에서 본 꼴 (패턴 설명만) | 지금 | 바꿀 판정 |
|---|---|---|---|
| **Q1 괄호 속 남의 나이** | 「(아이돌 애칭)(14살) ♥ 나(27살)」 — 괄호 앞 사람의 나이 | self | **other** |
| **Q2 과거 나이** | 「오늘 기어코 15살의 (내 이름)로 돌아갔다」 — 학창 시절 회상 | self | **unknown** |

- Q2 는 **PM 결정(10/17)으로 unknown** 을 쓴다 — 내 나이이긴 하지만 지금 나이가 아니라 「문장만으로 (지금 나이를) 판단 불가」(계약 subject `unknown`). 엔진은 절반 가중 · 화면은 점선이다. **골드 관례와 어긋난다** — 교사 라벨 골드에 과거 나이를 self 로 단 예가 있다(「… 시작한 게 [스물셋]이었는데」). 이 실험은 그 관례를 바꾸는 제안이다
- 이 문서 · `score.py` · 판정셋은 **규칙 구현 결과를 보기 전에** 커밋한다

## 2. 판정 (사전 등록 · exp35 와 같은 틀 + 코퍼스)

A = main · R = 이 브랜치. 패턴마다:
1. H-pos 정답 비율 **≥ 0.75**
2. A 가 맞힌 반례를 R 이 틀리는 수 **≤ 1**

통과한 패턴만 남기고(패턴별 스위치), 남긴 규칙 전체로:
3. 반례 새 오답 합 ≤ 3 · R 정답 ≥ A
4. 골드 — 사람 검수 lost ≤ 1 · 전체 lost ≤ 5 (Q2 가 골드 과거 나이를 self → unknown 으로 바꾼 것도 lost 로 센다 — 관례 변경의 비용을 그대로 보인다)
5. **코퍼스 1단 전수** — R 이 바꾼 스팬을 D 가 전부 읽고 「틀리게 바꿈」 ≤ 2
6. 단위 테스트 · 최악 시간 ≤ 0.05초

- 떨어진 패턴은 판정셋을 본 뒤 다시 맞추지 않는다

### 판정셋 확정 (결과 전 · 10/17 밤)

- H-pos 60줄(Q1 · Q2 각 30) · D 검토 제외 2(H-Q1-01 · H-Q2-01 — 구현자 지시문에 예로 준 문장과 같다) → 58

## 5. 제품 미채택 (10/19 · PR #382 닫음)

**결론: 실험은 통과했지만 앱에는 넣지 않는다.** 규칙 코드는 `rule.patch`(main 기준 `src/kopl/c1_span` diff)로만 남긴다. 위 숫자를 다시 재려면 이 패치를 적용한 뒤 `score.py` 를 돌린다.

**B 리뷰 (#382 · 변경 요청)**
1. 반례: 「오늘 ⟦서른 살⟧에 처음 운전면허를 땄다」 「오늘 ⟦스물셋⟧에 처음 취업했다」가 unknown 이 된다. 원인은 `에 처음` 분기다
2. 관례: subject 는 「누구의 정보인가」(label-schema §4-2)를 뜻한다. 본인의 과거 나이는 누구 것인지가 불분명한 정보가 아니므로 unknown 으로 두는 것은 맞지 않다. 귀속과 시점(현재 나이 계산에 넣는가)은 나눠야 한다. 게다가 지금 unknown 은 c2 에서 confidence 만 절반으로 내리고 `age_exact` 조건과 resolution 기반 `risk_total` 은 그대로 남긴다. 그래서 「현재 나이 계산에서 뺀다」와는 효과가 다르다

**Codex 검토 (10/19 · 사후 민감도 · 판정 아님)**
- `에 처음` 분기를 통째로 빼면 Q2 는 17/29 = 0.59 로 기준에 못 미친다. 바로 앞에 「오늘」이 있을 때만 예외로 두면 22/29 를 유지하면서 B 반례 둘이 self 로 돌아온다. 다만 판정셋을 본 뒤 고른 예외라 새 판정이 아니다
- B 의 2번을 풀려면 subject 는 self 로 두고 시점 정보를 c2 · 추천 · LOO · 조치 시뮬레이션 · 화면 두 곳으로 따로 넘겨야 한다. 계약 밖 요청별 맵으로 만들 수는 있지만 B · C · E 코드가 함께 바뀐다
- 효과 크기: 바뀌는 스팬은 골드 2,194개 중 1개, 코퍼스 2,569개 중 1개(B07_b13)다. 그 글의 k 는 928,637 → 1,544,488(+66%)이고 `risk_total` 은 그대로다

**판단 (PM 10/19)**: 시점 분리는 맞는 방향이다. 하지만 B · C · E 코드를 함께 바꿔야 하는 데 비해 관측 이득이 작고, 마감(10/28 새 기능 마감)과 시험기간이 겹친다. 그래서 동결 뒤 후속 과제로 넘긴다. 정리서 · 발표자료의 「미해결 사항」에 다음을 적는다: 과거 나이가 현재 나이 계산에 들어가는 문제 · 관측 빈도(코퍼스 1/2,569) · subject 와 시점을 나눠야 함 · 실제 글에서의 빈도는 확인하지 못함.
