# exp32-loc-gate: 학생 판정을 장소 유형에만 쓰기 (H) — 새 판정셋 D1e · 사람 검수 골드 D2

**왜** (10/17 · PM 결정 「가'」): exp31 의 학생 S2 는 함정 오탐을 줄였지만 subject 뒤집힘(15 ~ 17%)에서 떨어졌다. 뒤집힘의 큰 몫은 **SEX · FAM 호칭**이고, 함정의 큰 몫(매체 속 장소 · 여행지)은 **장소**다. 그래서 학생 판정을 **LOC_ADMIN · LOC_FACILITY 후보에만** 쓰고 나머지 유형은 1단 subject 규칙을 그대로 두는 혼합안(H)을 시험한다.

**이 안은 exp31 결과를 보고 골랐다.** 이미 본 D1d · D5 로 사후 계산했을 때 H 는 뒤집힘 2.7 · 4.0% · 함정 오탐 12 · 10/64 · 역함정(유형 일치) 5 · 3/28 이었다(판정 아님). 그래서 **새 판정셋 D1e** 와, 이 학생 · 이 안을 만들 때 쓰지 않은 **사람 검수 골드 D2** 로 잰다.

이 문서 · 스크립트 · D2 목록은 **D1e 생성 · 학생 적용 · 결과 전에** 커밋한다.

## 1. 학생 · 교사 — 다시 학습하지 않는다

- 교사(참고): 프롬프트 v3 그대로(해시 `9822388808d1`)

## 4. 지표 · 판정 (사전 등록)

지표는 exp31 과 같다. **V 는 유형 일치 정의(V_typed)로 판정한다** — 역함정 자리에 **같은 유형**의 self 스팬이 남아야 보존(exp31 §8 에서 등록 정의의 빈틈을 찾았다). 등록 정의 V 도 함께 적는다.

H 의 각 seed 통과 = 모두 만족:
1. **Ta** ≤ A0 의 절반 (D1e)
2. **V_typed** 손실 ≤ 3자리 (D1e)
3. **R** ≥ A0 − 2 (D1e)
4. **G 버림** ≤ 3% (D2)
5. **G 뒤집힘** ≤ 5% (D2)
6. **L** 글당 중앙 ≤ 1초

- **채택 후보 = H 의 두 seed 가 모두 통과.** 한 seed 만 통과하면 「불안정」 · 채택하지 않는다
- 채택 후보가 나와도 **앱 반영은 별도 PM 결정**이다(동결 10/25 전). 반영하면 GPU 서버 분석기에 학생 모델을 올리는 작업이 따로 든다
- 함정을 종류별(매체 · 여행 · 남 · 부모 · 유행어)로도 적는다 — H 는 LOC 함정만 고칠 수 있으므로 남 · 부모 · 유행어 함정은 A0 와 같을 것으로 **예상**한다

## 8. 결론

- **H(학생 S2 판정을 장소 후보에만)는 사전 등록 기준으로 채택 후보다.** 새 판정셋 D1e 와 사람 검수 골드 D2 에서 두 seed 모두 통과했다
- 무엇을 얻나: 글 속 매체(드라마 · 유튜브 · 다큐)에 나온 곳 · 여행 간 곳을 「내 장소」로 경고하는 오탐이 합성 함정에서 거의 사라진다. 무엇을 잃나: 사람 골드에서 **본인 장소 23자리 중 2 ~ 5자리(9 ~ 22%)** 가 unknown 으로 바뀐다(전체 유형 기준 0.6 ~ 1.5%)
- **이득은 합성 글에서만, 손실은 사람 골드에서 쟀다.** D2 에는 장소 함정이 거의 없어 이득이 보이지 않는다 — 실제 글의 매체 · 여행 장소 빈도를 모르면 득실을 견줄 수 없다
- **한계**: H 는 exp31 결과를 보고 골랐다(§5). D1e 는 합성 글이고 함정 밀도가 실제 글보다 훨씬 높다 — 실제 글에서 매체 · 여행 장소가 얼마나 나오는지 모르므로 이득의 크기는 모른다. V_typed 기준이 seed 23 에서 문턱에 걸렸다(3/20). 교사를 장소에만 쓴 TH 는 이번 셋에서 역함정 보존 · D2 subject 보존이 학생 H 보다 좋았다(둘 다 0). Ta 는 H-23(6)이 TH(7)보다 낮았고 지연은 비교하지 않았다. 교사는 앱에서 돌릴 수 없다(지연 · 외부 호출)
- **앱 반영은 별도 PM 결정**이다(§4). 반영하면 GPU 서버 분석기에 학생 모델(KoELECTRA-base 분류기 1개)을 1단 뒤에 붙이고, 장소 후보에만 판정을 적용하는 코드가 든다. 지연은 글당 중앙 0.007 → 0.014초
