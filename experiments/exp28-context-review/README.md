# exp28-context-review: 1단 문맥 보정 — 큰 모델이 원문을 읽고 1단을 고치나 · 대신하나 · 모델 크기가 차이를 만드나

**왜** (10/16): 동의받은 실제 블로그 글을 앱으로 점검해 보니(저장소 · 이 실험의 데이터에는 넣지 않는다) 1단(KoELECTRA · 약 1억 파라미터 · 합성 글로만 학습)이 문맥을 못 읽어
- **오탐** — 영상 제목 밈을 장소로, 글쓴이의 아버지를 글쓴이 성별로
- **누락** — 생일 날짜 · 반려동물 이름 같은 강한 단서(지금 단서 유형에 칸이 없다) · 돌려 말한 직업
결론이 「약 6.6만 명 중 한 명 · 추천 없음」으로 나왔다. 규칙 보강(#378)은 본 꼴의 오탐만 줄이고 누락은 그대로다(결론이 오히려 7.9만 명으로).

**2단으로는 못 고친다** — 2단(Qwen3-4B v2)은 원문을 보지 않고 1단이 뽑은 단서의 가명 토큰만 본다(exp22b §2). 1단이 틀리면 그대로 믿고, 놓치면 아예 모른다. 그래서 고칠 곳은 **1단**이다.

**무엇을**: 원문을 읽는 **자체 호스팅 큰 모델(외부 전송 0 — 지금 1단과 같은 서버 안)** 을 1단에 넣는 두 방식을 비교한다.
- **보정(A)** — 1단(KoELECTRA + 규칙) 결과를 받아 ① 문맥상 단서가 아닌 스팬 버리기 · 누구 정보인지(subject) 고치기 ② 놓친 단서 찾기
- **대체(B)** — KoELECTRA 없이 큰 모델이 혼자 단서를 찾는다(명시 규칙만 같이)

모델 크기(4B · 8B · 14B)를 같은 조건으로 비교한다. 흐름: `글 → 1단 [+ 보정 | 대체] → 2단(가명 추론) → k · 추천`

이 문서의 정의 · 기준은 **결과를 보기 전에** 적고 커밋한다(DEC-011 · exp22b · exp27 과 같은 원칙).
