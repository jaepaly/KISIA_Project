## 3. 추천 vs 최적해 격차

- **최적해**: 위 메뉴 안에서 **위험 ≤ 40 에 닿는 최소 부담** 조합. 동률이면 위험이 낮은 쪽
- **추천**: `recommend()` 가 낸 조치 — 부담은 같은 점수표로 센다(비공개 글 수 × 1 + 위치태그 2 + 리라이트 글 수 × 3)
- **격차** = (추천 부담 − 최적 부담) / 최적 부담 — 인물별
- 인물 분류
  - 기준 위험 ≤ 40 → **제외**(조치가 필요 없다)
  - 최적해도 40 에 못 닿음 → **제외 · 수만 적는다**
  - 최적해는 닿는데 추천은 못 닿음 → **추천 실패**
  - 둘 다 닿음 → 격차를 잰다

**판정 (둘 다 만족해야 「목표 달성」)**
1. 둘 다 닿은 인물의 **격차 중앙값 ≤ 15%**
2. **추천 실패율 ≤ 10%** — 실패 인물 수 ÷ (최적해가 닿는 인물 수)

격차는 「둘 다 닿은 인물」에 대한 조건부 지표라는 점을 결과에 함께 적는다. 평균 · 분포 · 격차 0 인 인물 수도 적는다.

**글별 상태** — 글 하나마다 세 벡터를 만든다: 원래 스팬 전체로 `_app_conditions` → `risk_by_axis`(7축 점수) · 명시 스팬을 지운 스팬 전체로 다시 `_app_conditions` → `risk_by_axis`(관계 수식자 REL_WORK 의 commute condition 처럼 같은 글의 다른 조건이 함께 바뀌는 것을 반영 — 스팬별 조건을 빼는 방식이 아니다) · 위치태그 condition(`location` 축 한 항목 · 글이 비공개면 함께 사라짐). 계정 위험 = 축마다 공개 글 상태 · 남은 태그의 최댓값의 평균.

**최적해 계산** — 위험도는 축마다 「가장 구체적인 단서 하나」의 점수의 평균이다. 그래서 축별 상한 조합(축마다 가능한 점수 단계의 곱 · 많아야 수천 가지)을 하나씩 정하면, 각 글이 그 상한을 지키는 데 필요한 최소 조치(그대로 · 리라이트 · 비공개)가 바로 정해진다. 비공개는 k편 제한이 있으므로 「리라이트로는 안 되는 글」을 먼저 비공개하고, 남은 자리는 리라이트 대신 비공개해 부담을 줄인다. 필수 비공개가 k 를 넘는 상한 조합은 버린다. 위치태그는 「뗌 · 안 뗌」 두 경우를 다 본다.

**정확성 확인 (테스트)** — 입력 계정은 모두 12편 이상이라, 대조용 작은 계정을 따로 만든다: ① 인물 10명(post_id 순 앞에서부터 10명)의 test 아닌 글을 post_id 순으로 앞 7편씩 자른 부분 이력 ② 손으로 만든 합성 사례(REL_WORK 로 commute 가 바뀌는 글 · 태그만 위치 단서인 글 · 비공개 k 경계). 단순 전수 탐색(비공개 ≤ k 부분집합 × 태그 2 × 리라이트 부분집합)과 **세 가중치 모두에서** 최소 부담 · 그때의 위험이 같아야 한다.

## 4. 조치 곡선 (골드 스팬 · 위험 40 넘는 인물)

기준선에서 **한 유형만** 적용했을 때의 위험(인물 평균 · 중앙값)과 부담.

| 유형 | 강도 | 대상 순서 |
|---|---|---|
| 비공개 | 0 ~ k편 | C3 LOO 탐욕 경로 순서(추천 엔진과 같다 · `max_greedy_remove=k`). 경로가 k 전에 멈추면(더 내려가는 글이 없음) 그 뒤 강도는 마지막 값을 그대로 두고 부담도 늘리지 않는다 — 멈춘 인물 수를 함께 적는다 |
| 리라이트 | 0 ~ 명시 단서 있는 글 전부 | 그 글 하나만 리라이트했을 때 위험이 가장 많이 내려가는 순서 (동률은 post_id) |
| 위치태그 | 뗌 · 안 뗌 두 점 | — |

추천 엔진의 누적 결과(비공개 → 위치태그 → 리라이트)도 같은 그림에 점으로 찍는다.

## 5. 실제 바꿔 쓰기를 적용한 효과

exp10 의 −58.8% 는 「명시 단서를 지운 글」을 가정한 모사다. 앱이 실제로 내는 바꿔 쓰기 후보를 적용하면 얼마나 내려가는지 **같은 계정 · 같은 대상**에서 짝지어 잰다.

- 계정: §1 의 87명 전체 이력(test 제외) · 위험은 **세 경우 모두 1단 v2 앱 경로 탐지 스팬**으로, §1 의 앱 위험 경로로 계산한다
- 대상: **본인(self) 명시 스팬** — 앱의 바꿔 쓰기 후보(`rewrites_for`)가 self 명시만 다루므로. §2~4 의 리라이트(subject 무관)와 대상이 다르다는 점을 결과에 적는다
  - **원래**: 원문 탐지
  - **모사**: 원문 탐지에서 본인 명시 스팬을 지움 (같은 글의 나머지 스팬으로 조건을 다시 만든다)
  - **실제**: 본인 명시 스팬마다 `rewrite.suggest(span, 채널 원문)[0]` — 앱이 먼저 보여 주는 첫 후보 — 로 원문을 바꾼 뒤 → 1단 v2 로 **다시 탐지**. 후보는 **바꾸기 전 NFC 원문과 원래 offset** 으로 한 채널의 것을 모두 먼저 만든다
- 후보 적용 규칙: 후보가 없는 스팬은 그대로 둔다 · 겹치는 스팬은 start 가 앞선 것만(같으면 긴 것) · 한 채널 안에서 뒤쪽부터 바꿔 offset 이 밀리지 않게 한다 · 바꾼 자리는 **최종 문자열 좌표**로 다시 계산해 둔다
- 적는 것: 인물별 위험 하락률(모사 · 실제)의 평균 · 중앙값 · 짝 차이 · **미적용 비율**(후보 없는 명시 스팬 ÷ 명시 스팬) · **재탐지 비율** = 실제로 바꾼 스팬 중, 최종 문자열의 그 치환 구간과 겹치는 **같은 유형** 스팬이 다시 탐지된 스팬의 비율
- 비공개 · 위치태그는 섞지 않는다 — 리라이트만의 효과다. exp10 −58.8%(3단계 누적 · test 표본)는 조건이 달라 **참고치로만** 옆에 둔다
- 판정 기준은 두지 않는다(기술 통계). 정리서에 「모사 하락」과 「실제 후보 적용 시 하락」을 나눠 적는 재료다
