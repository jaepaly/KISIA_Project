# exp42-real-blog-homonyms: 실제 블로그 오탐에서 나온 좁은 규칙 넷 — 동형이의어 지명 · 남의 나이 · 반사실 직업 · 지명 나열

**왜**: 실제 블로그 1개(PM 이 글쓴이에게 허락받은 것 · 30편)를 분석기(main · 1단 v2 + 명시 규칙 + attributes · 2단 v2)로 돌렸더니
낱말 몇 개가 사용자 판정을 통째로 틀리게 만들었다(10/26). 원문 · 문맥 · 주소는 저장소에 두지 않는다 — 아래 예시는 모두 지은 문장이다.

| | 오탐 꼴 (지은 예) | 블로그에서 | 판정에 준 영향 |
|---|---|---|---|
| R1 | 「AI 음성으로 읽어 준다」 → 음성군 · 「동화 속 공주가」 → 공주시 · 「여행 예산」 → 예산군 · 「장수 비결」 → 장수군 · 「한번 해보면」 → 해보면 | 24곳 · 모두 **명시 규칙**(지명 사전)에서 나왔다. 모델 후보는 0 | 지역 근거 1순위가 「공주가」 |
| R2 | 「70세의 한 청취자가」 → 본인 explicit AGE | 1곳 (모델) | 나이 「specified」(60대) |
| R3 | 「만약 내가 가수였다면」 → 본인 JOB | 2곳 (모델) | 직업 근거 |
| R4 | 「지원 지역: 강릉, 경주, 목포, 순천」 → 전부 본인 explicit 지명 | 협찬 글 1편 11곳 (규칙 10 · 모델 1) | 지역 근거 후보 |

임계값(0.7)은 바꾸지 않았다. 모두 **목록 · 꼴이 정해진 좁은 규칙**이다 — #397 B 리뷰(C3 미채택: 「모델이 못 본 규칙 지명은 모두 버림」은 모델이 놓친 진짜 지명을 규칙이 메우는 길까지 막는다)를 따라, 목록 밖 지명 · 지명 문맥이 있는 자리는 건드리지 않는다.

## 1. 규칙

| | 어디 | 무엇을 | 그대로 두는 것 |
|---|---|---|---|
| R1 | `rules.py` `_CONTEXT_ONLY_PLACES` · `is_contextless_homonym` (규칙) · `is_model_homonym_place` (모델 후보 · `merge_with_model` · 통계 `model_homonym_place_dropped`) | 음성 · 공주 · 예산 · 장수 · 해보면 · 강하면 — 지명 문맥이 없으면 LOC_ADMIN 후보에서 뺀다. 기존 진도 · 달성과 같은 방식 | 접미사 붙은 낱말(음성군 · 공주시 · 예산군) · 도 이름 뒤(충북 음성 · 전북 장수) · 이동 · 거주 술어(음성에 산다 · 공주로 향했다 · 공주에 놀러) · 장소 말(음성 쪽 · 예산 농사 · 공주 터미널) · 면 이름 앞에 시 · 군(함평군 해보면) · 모델 스팬에 다른 말이 붙은 것(「음성 쪽」) |
| R2 | `attributes.py` `_age_of_other` (`_RULE_AGE_OTHER`) | AGE 가 「…의」로 끝나거나 뒤가 「의」이고 그다음이 사연 · 방송 속 사람(청취자 · 시청자 · 독자 …) 또는 「한 · 어느 · 어떤 · 모 + 사람 명사」면 subject=other | 「예순넷의 봄」(골드 self) · 「마흔의 엄마로 산다」(꾸밈말 없는 일반 사람 명사) · 앞에 1인칭(「나는 마흔의 한 여자일 뿐」) |
| R3 | `rules.py` `is_counterfactual` (모델 JOB 후보 · 통계 `model_counterfactual_job_dropped`) | 같은 문장 앞에 「만약 · 만일」, 스팬 뒤에 「-었다면 · -었더라면」이면 JOB 후보를 뺀다 | 사이에 부정(「만약 내가 교사가 아니었다면」 = 실제 직업) · 「만약」이 다른 문장 |
| R4 | `attributes.py` `_in_place_list` (`_RULE_ADMIN_LIST`) | 쉼표 · 가운뎃점 · 빗금 · 📍 로 늘어놓은 줄에서 **지명 항목이 셋 이상**이고 스팬이 그 항목이면 LOC_ADMIN subject=unknown (버리지 않는다) | 둘만 늘어놓은 것(「서울, 부산 두 곳」) · 지명이 아닌 것의 나열(「와인, 샴페인, 부산 지역 맥주」) · 지명 판정은 명시 규칙 사전 그대로라 해외 지명 나열은 대상이 아니다 |

R2 · R4 를 「버림」이 아니라 subject 로 한 이유: 골드 관례(label-schema §4-2)상 남의 나이도 스팬이다 — 「[아홉 살] 아들」은 subject=other 로 칠한다. 반사실 직업(R3)은 골드에 한 건도 없고, 「가수였다면」은 「가수가 아니다」라는 뜻이라 단서 자체가 아니어서 버린다.

## 2. 데이터 — test 는 보지 않는다

exp41 `measure.py` 를 그대로 불러 쓴다(골드 읽기 · 추론 캐시 · 채점). test 255편(`splits/test_post_ids.json` 의 `post_ids` · 길이 255 assert)은 읽자마자 빠지고, 골드는 `gold/*_spans.jsonl` 만(`gold/blind/` 는 안 잡힌다) — test 밖 **2,281편 · 스팬 2,194개**. 모델 후보는 exp41 의 10/25 캐시(체크포인트 v2 `d7dc7b06…` · 임계값 0.7 · fingerprint 확인)로 새로 추론하지 않았다.

## 6. 한계 · 위험

- 동형이의어 목록은 실제 블로그 1개와 exp41 에서 본 것뿐이다. 목록 밖 이름(이천 · 진해 · 울진 · 부산 「떨다」 …)의 오탐은 그대로 남는다 — 넓히려면 같은 방식으로 이름을 더한다
- R1 은 목록 안 이름이 지명 문맥 없이 쓰인 진짜 지명도 뺀다 — 「나는 음성 사람이다」 「공주는 조용하다」. 문맥 말(이동 · 거주 술어 · 장소 말 · 도 이름)을 더 넣으면 줄어든다
- R2 · R3 · R4 는 코퍼스에 그 꼴이 없어 근거가 합성 문장과 실제 블로그 1개뿐이다
- R4 의 나열 판정은 같은 줄 · 구분자 · 지명 사전만 본다. 「수도권(서울 · 인천 · 수원)에 산다」처럼 사는 곳을 나열로 쓴 문장도 unknown 이 된다
- 2단 판정은 생성 모델이라 실행마다 근거가 조금 다를 수 있다(이번 비교는 각 1회)
