# exp-005: 2단 모델 크기 결정 — qwen3:1.7b vs qwen3:4b

## 무엇을 왜 재는가

- **배경**: W4 설계서에 2단 베이스 모델 크기를 확정해 써야 한다. W2 스모크는 **표본 1건**이었다([#121](../../pull/121)).
- **핵심 질문**: 파인튜닝 전, **프롬프트만으로** 1.7B 와 4B 가 계약 과제를 얼마나 하는가.
- **대응 지표**: `D-stage2.md` §4 · README W3 D절 판정 우선순위 4단계.

## 해석

**4B 를 쓴다.** 판정 우선순위 ①②③ 에서 전부 4B 가 앞선다. ④(토큰·지연)는 동률일 때만 보는 축이라 적용되지 않는다.

**갈린 자리는 「말을 아끼는 능력」이다.** 양성(단서가 있을 때 발언)은 98.3% 로 완전 동률이고, 차이는 전부 **단서가 없을 때 기권하는가**(71.2% → 80.3%)와 **남의 정보를 근거로 쓰지 않는가**(91.2% → 64.7%)에서 나왔다. 개인정보 도구에서 이 방향의 오류가 더 비싸다.

⚠️ **함정 오용은 두 모델 다 심각하다.** 4B 도 34명 중 22명에서 `subject=other` 스팬을 본인 속성의 근거로 썼다. 계약(`stage2-io.schema.json`)이 금지한 동작이고 **기존 도구와 갈리는 지점이 정확히 여기다.** 프롬프트만으로는 안 된다는 뜻이고, **W4 QLoRA 학습의 1순위 목표**로 둔다.

⚠️ **1.7B 는 `confidence` 를 30~80 으로 냈다**(D02, 6칸). ollama 의 `format` 은 구조만 강제하고 값 제약은 강제하지 않는다 — `stage2-io.schema.json` 이 이미 경고해둔 것이 실제로 나왔다.

## 한계 — W4 설계서에 같이 적는다

1. **prompt-only 스팬 판정에 한정된 선택이다.** 전체 `Stage2Output`(추천·리라이트·`provenance`), 글 간 결합, k 값, QLoRA 후 성능은 재지 않았다.
2. **`D-stage2.md` §4 의 「7속성 중 5개 적중」을 입증하지 않았다.** 그 기준은 **값 적중** 수이고 이 측정의 ①은 **특정 가능성 판정**이다. 계약 `Finding` 에는 속성 값 필드 자체가 없다.
3. **선행 PoC 의 R1~R5 7/7 · R6 6/7 과 직접 비교할 수 없다.** R1~R6 원 조건이 저장소에 없다(`HANDOFF.md` · `poc/` 부재). 아는 것은 R1=40대 · R4=60대 뿐이다.
4. **값 프로브는 `scoring_keywords` 품질에 좌우된다.** 35명 중 `sex` 24명 · `income` 26명만 채워져 있고, 비진단적 어휘가 섞여 있다([#125](../../pull/125) 리뷰 참조). 부지표로만 읽는다.
5. **n=35 · 단일 seed · 1회 실행.** 반복·외부 holdout 없음.
6. **`sex` 는 표본이 5칸뿐이다** — 코퍼스에 성별 단서가 5명에게만 있다([#116](../../issues/116)).

## ⚠️ 한계 — 이 실험이 재지 않은 것 [MF-012]

> 멘토 피드백(2026-09-02): **「탐지 성능을 단순 정확도만으로 평가하지 마라. F-score 등을 함께 보라.」**
> 같은 원자료를 다시 채점했다 — `python experiments/exp05-model-size/rescore.py`

### ① 이 실험은 「2단 추론 성능」이 아니라 **속성 단위 탐지 성능**이다

각 칸은 「그 속성에 단서가 있다고 봤는가(`verdict != abstain`)」 대 「골드에 단서가 있는가」의
**이진 판정**이다. **`verdict` 의 내용·근거 스팬·추론값의 정확성은 채점하지 않는다.**
아래 표를 「2단이 93.5% 맞았다」로 읽으면 안 된다.

### ② 정확도를 단독으로 읽으면 안 된다 — 기준선이 73.1% 다

```
클래스 분포   양성 179칸(73.1%) · 음성 66칸(26.9%)
다수 클래스로만 찍는 더미의 정확도 = 73.1%
```

### ③ 재채점 결과 — 4B 가 모든 지표에서 앞선다

| | 정확도 | F1 양성 | **F1 음성** | **macro F1** | **특이도** | 재현율 | MCC |
|---|---:|---:|---:|---:|---:|---:|---:|
| **4B** | .935 | .957 | **.869** | **.913** | **.803** | .983 | **.831** |
| 1.7B | .910 | .941 | .810 | .876 | .712 | .983 | .765 |

```
        TP   FP   FN   TN
4B     176   13    3   53
1.7B   176   19    3   47
```

**두 모델이 놓친 것은 3개로 동일하고 재현율도 같다(.983). 차이는 전부 오탐이다.**
정확도는 이걸 흐리고 **특이도(.803 vs .712)** 가 드러낸다.

### ④ 🔴 그러나 통계적으로 유의하지 않다

```
McNemar 정확검정 (대응표본)
  4B만 맞음 9칸 · 1.7B만 맞음 3칸 · 양측 p = 0.146   → 유의하지 않음
```

**n=35 에서 이 차이가 우연일 가능성을 배제할 수 없다.** 게다가 245칸은 독립이 아니라
**인물 35명 안에 7속성이 군집**돼 있어 실효 표본은 더 작다. 확증하려면 인물 단위
cluster bootstrap 이 필요하다.

> **[DEC-004] Qwen3-4B 확정은 유지한다** — 4B 가 지는 지표가 하나도 없고, 다른 축
> (형식 준수 35/35 vs 34/35 · 근거 정확도 83.1% vs 69.6%)에서도 앞섰기 때문이다.
> 다만 **「4B 가 유의하게 낫다」고 쓰지 않는다.** W4 학습 후 평가에서 **인물 115명**
> 기준으로 재검증한다 (코퍼스가 35명 → 115명으로 늘었다).

### ⑤ 약한 자리 둘

```
location  F1 .852  ← 7속성 중 유일하게 .9 미만. 오탐 9건
sex       양성 5칸 ← F1 1.000 을 신뢰하지 않는다. 표본 부족
```

**location 오탐 9건 중 8건이 근거로 `subject: other` 스팬(함정)을 들었다.** 사례를 열어
확인한 값이다. **모델이 「남의 거주지」를 「이 사람 거주지」로 채택한다** — 우리 함정 설계가
잡으려던 바로 그 실패다. **W4 QLoRA 학습의 1순위 교정 목표**로 삼는다.
