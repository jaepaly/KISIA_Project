# exp30-review-distill: Claude 의 문맥 보정 판정을 작은 분류기로 옮기기 (증류)

**왜** (10/16 · PM 결정 「3순위도 최대한」): exp28b 에서 함정 오탐과 맞는 단서 버림이 **함께 낮은 것은 Claude 뿐**이었다(함정 4/94 · 버림 5.8%). 자체 호스팅 모델(4B~32B)은 한쪽만 했다. Claude 는 앱에서 매번 부를 수 없으므로(외부 전송 · 비용), Claude 의 판정을 **단서 하나씩 판정하는 작은 분류기**로 옮겨 GPU 부담 없이 쓸 수 있는지 본다.

이 문서는 **교사 라벨을 받기 전 · D1c · D4 결과를 보기 전에** 커밋한다.

## 1. 교사 — Claude 보정 판정 (프롬프트 v3)

exp28b 프롬프트 v2(`review.py`)에서 계약과 어긋난 두 곳만 고친다(exp29 README 「왜」 · 결과 뒤 브레인스토밍):
1. **subject**: self 가 기본. other 는 문장이 **명시적으로** 남에게 돌릴 때만(「친구가」 「옆집」). **가족 · 배우자 · 형제 호칭은 글쓴이의 성별 · 가족 단서라 self**(「아내가」 「누나가」 「아들」 — §3-2). 글쓴이 **부모** 호칭이 성별로 잡힌 것만 other(#378 앱 규칙)
2. **장소**: 다녀온 곳은 self(계약 예 「신갈저수지 다녀왔다」). **여행 말이 꾸미는 여행지 · 매체 속 장소만** unknown

버리기는 v2 와 같다(좁게 · 애매하면 남김). 출력은 후보마다 `self · other · unknown · drop` 하나.
모델 `claude-opus-4-8` · KISIA 게이트웨이 · temperature 0 · 글 5편씩 묶음.

## 3. 학생 — 단서 판정 분류기

- `monologg/koelectra-base-v3-discriminator` (1단과 같은 계열) · 문장 분류 4값
- 입력: `[유형] 앞 문장 + 스팬 문장(스팬을 ⟦ ⟧ 로 표시) + 뒤 문장` · 최대 256토큰
- 학습: GPU 서버(L4 · 분석기와 같이 올라간다) · 최대 5 epoch · 고르기용 10% 의 macro-F1 로 멈춤
- 적용: 1단 A0 출력의 각 후보에 argmax — drop 이면 버리고, 아니면 subject 를 그 값으로. **문턱은 두지 않는다**(D1c · D4 로 고르지 않는다)

## 5. 지표 · 판정 (사전 등록)

지표 정의는 exp29 §4 · exp28 §3 과 같다. D1c 에서 **Ta**(함정 전체) · **V**(역함정 손실) · **R**(본인 단서), D4 에서 **G**(버림 · subject 뒤집힘).

채택 후보 = 모두 만족:
1. **Ta** ≤ A0 의 절반
2. **V** 손실 ≤ 3자리
3. **R** ≥ A0 − 2
4. **G 버림** ≤ 3%
5. **G 뒤집힘** ≤ 5% — exp28 의 3% 에서 바꾼다. 근거: 교사 라벨 subject 일치 0.959(10/16)라 3% 는 라벨 잡음보다 낮다. **D4 · D1c 를 보기 전에** 정한다
6. **L** 글당 중앙 ≤ 1초 (CPU 또는 L4)

- 교사(T3)가 이 기준을 못 넘으면 학생도 못 넘는 것으로 보고 그 사실을 적는다
- 채택 후보가 나와도 **앱 반영은 별도 PM 결정**이다. 동결(10/25)까지 판정이 안 나오면 「동결 뒤 과제」로 정리서에 적는다

## 9. 결론

- **학생(S1) 채택 아님** (V · G 뒤집힘). 함정은 교사보다도 잘 걸렀지만(28 → 5) 그 대가로 생활권 · 가족 단서를 잃는다
- **교사(Claude v3)는 품질 기준 5개를 넘었다**(L 은 재지 않음). exp28b 의 Claude v2(같은 모델)는 D3 뒤집힘 15% 였다. 다만 평가셋(D1b · D3 → D1c · D4) · 함정 정답 정의 · 프롬프트 · 뒤집힘 허용치(3% → 5%)가 **함께** 바뀌었으므로, 프롬프트 · 기준 고침이 얼마나 기여했는지는 이 결과로 가를 수 없다. T3 뒤집힘 4.9% 는 옛 기준 3% 로는 탈락이고, 1건만 늘어도 5% 를 넘는다 — 「가능성을 보였다」 정도로 읽는다
- 남은 문제는 이것을 **작은 모델로 옮기는 것**이다. 학생의 실패 양상(매체 · 여행 말 옆이면 내림 · 가족 호칭을 other 로)은 학습 예(1,846개) · 대조 예(역함정 · 가족 호칭)가 적은 탓으로 **보이지만**, 보강 · 절제 실험으로 확인하지 않은 가설이다
- 지표의 사각지대: V 는 역함정 32자리 중 A0 가 self 로 잡은 30자리만 본다 · 함정 64자리 중 A0 가 애초에 안 잡은 자리는 보정 없이 맞음으로 센다 · R 22/40 은 1단 재현 자체가 55% 라는 뜻이다 · D4 재현은 유형 + IoU 만 보고 subject 는 보지 않는다 · D4 정답은 Claude 라벨이라 사람 검수가 아니다 · 학습 반복에 따른 변동 · 실제 글의 함정 빈도 · CPU 지연은 재지 않았다
- D1c · D4 는 이제 결과를 본 셋이다 — 학생을 고쳐 다시 재려면 **새 판정셋(D1d) · 새 회귀 셋(D5)** 이 필요하다
- 사후 메모: ① 보강 글 거르기에서 1단 잡음 조각 「에서」가 지명 목록에 들어가 81편이 잘못 걸려, 조사 조각을 빼고 다시 걸렀다(교사 라벨 전) ② `student.py` 는 서버 가상환경에 sklearn 이 없어 macro-F1 을 직접 계산하도록 바꿨다(학습 전) ③ Gemini 과부하(503)로 생성이 여러 번 멈춰 이어 돌렸다(버린 글 0) ④ (10/17 · exp31 Codex 검토) V 는 역함정 자리에 **아무 유형이든** self 가 남으면 보존으로 센다. 목표 유형까지 맞춰 세면 학생 S1 13/25 · 교사 T3 1/25 · exp29 규칙 R1 0/25 — 결론은 같다(`../exp31-distill-v2/README.md` §8)
