# exp41-precision-rules: 1단 정밀도 규칙 — 조각 버림 · 「X 안에서」 다듬기 (모델이 안 본 규칙 지명 버림은 미채택)

**왜**: 1단 v2(임계값 0.7 · 명시 규칙 병합)의 test 밖 골드 오탐 1,249개를 유형별로 나눠 보니, 고치기 쉬운 묶음이 셋 있었다(PM 분석 10/25). 그중 1 · 2 만 채택했다(아래 「채택」 · main + #396 기준 1,248 → 1,186).

1. 모델이 조사 · 어미 조각만 스팬으로 낸 것 — 「집⟦에⟧ 갔다」 「수첩⟦의⟧ 버스 시간표」 「⟦하는⟧ 학회」
2. LOC_ADMIN 이 범위 말까지 먹은 것 — 「⟦서울 안에서도⟧」 (골드는 「서울」)
3. 명시 규칙(지명 사전)이 지명과 글자가 같은 일반 낱말을 잡은 것 — 「냄새가 ⟦강하면⟧」 「⟦장수를⟧ 세다가」 「천 원 ⟦이천⟧ 원」 「아침부터 ⟦부산⟧ 떨었음」. 이런 자리에서는 모델이 점수와 상관없이 아무 후보도 내지 않는다

임계값(0.7 · `apps/analyzer/engines/real.py` `_MIN_SPAN_SCORE`)은 바꾸지 않았다.

**채택: C1 + C2. C3 은 미채택 (B 리뷰 #397 · 10/26)** — C3 은 모델이 전혀 못 본 진짜 지명을 규칙이 메우는 길까지 막는다. test 밖 골드 2,281편은 v2 학습에 쓴 데이터라, 거기서 잃은 골드가 0 이라는 것만으로 코퍼스 밖에서도 안전하다고 보기 어렵다. 그래서 앱 코드(`rules.merge_with_model` · `infer.py` · `apps/analyzer`)에서 C3 과 「모델이 본 스팬」 전달을 뺐고, 아래 표의 C3 행은 이 실험 스크립트 안에서만 재현한 참고 기록이다.

### C3 재현 (미채택 · 이 스크립트 안에서만)

C3 은 「모델이 그 자리에서 아무것도 안 봤나」를 봐야 해서 임계값(0.7) 아래 · 겹침 해소로 빠진 스팬까지 필요하다. 처음 PR 은 이것을 `predict_raw` 의 `model_seen_spans` 로 앱까지 넘겼지만, 미채택으로 그 연결을 모두 뺐다. 지금은 `measure.py` 의 `UnbackedAdminFilter` 가 10/25 캐시(겹침 해소 전 모델 스팬 포함)로만 C3 을 재현한다. 캐시 없이 새로 추론하면 C3 구성은 건너뛴다.

**Codex 검토(10/25)로 고친 것** — 처음 구현은 겹침 해소 **뒤** 남은 스팬만 「모델이 본 것」으로 넘겨, 해소로 빠진 자리의 규칙 지명을 잘못 버렸다. 해소 전 스팬 전부를 쓰도록 고쳤다. 이 기록은 C3 재현의 정의로 남긴다. 모델이 본 스팬은 3,869개(해소 뒤 3,824개).

**채택한 C1 · C2 는 병합 안에서 걸리므로** 지난 실험 스크립트(`exp06-finetune/evaluate_rules.py` · `exp11-risk-correlation/inputs/predict_293.py` · `exp28-context-review/review.py` · `exp28b-context-review-v2/review.py`)를 지금 다시 돌리면 예전 결과와 조금 다를 수 있다. 계약 출력(span.schema)은 그대로다.

## 5. 한계 · 위험

- 채택 규칙의 효과는 학습에 쓴 test 밖 골드에서만 쟀다. 코퍼스 밖에서의 효과는 11/2 최종 측정(test 239편 한 번)에서 다른 모든 것과 함께 본다
- C1 목록의 한 글자 「도 · 이 · 가 · 서」는 각각 행정 「도」 · 성 「이」 등과 글자가 같다. 골드에 이런 한 글자 스팬은 없었다
- 「강하면 · 장수를」 같은 지명 사전 오탐은 C3 을 빼서 그대로 남는다. 고치려면 모델이 놓친 지명을 막지 않는 다른 방법이 필요하다(후속 과제)
- 사람 글이 아니다(코퍼스 · 판정셋 모두 합성)
