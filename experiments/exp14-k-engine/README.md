# exp14-k-engine: 여러 글을 엮은 k (`estimate_k`) 검증 — #302

## 1. 왜

대회 데모 체험 피드백 중 가장 많았던 것 — **「여러 글을 써도 엮어서 좁혀지지 않는다 · k 가 다 똑같다」**. 코드로 확인한 원인:

| 원인 | 결과 |
|---|---|
| k 를 지역 × 나이대 × 성별 인구표로만 계산 | 직업·가족·통근·시설을 써도 k 가 안 움직인다 |
| 여러 글의 위치를 교집합하지 않고 「가장 좁은 지명 하나」만 | 「서울」(글 1) + 「중구」(글 2) 가 서울 중구로 엮이지 않는다 |
| 사전이 정식 이름만 안다 | 「서울 · 수원 · 일산 · 송도 · 신촌에서 · 천안고속터미널」 같은 실제 말이 조건이 되지 못한다 — 명시 위치 스팬의 26.5% 만 해석됐다 |
| 조건 목록 전체 → k 함수가 없다 | 앱은 목 특정성을 쓴다 |

## 2. 무엇을 만들었나 — `src/kopl/c2_specificity/k_engine.py`

```python
from kopl.c2_specificity.k_engine import conditions_from_posts, estimate_k
out = estimate_k(conditions_from_posts([{"post_id": ..., "spans": [...], "geo_tag": ...}, ...]))
# → specificity.schema.json 의 output (k · k_level · steps · assumptions · risk · …) — 계약 변경 없음
```

**C-specificity.md §4 네 규칙 그대로** + 세 가지를 더했다.

1. **위치 해석기** — 조사 떼기(신촌에서 → 신촌) · 시도/시 약칭(서울 · 수원 · 광주) · 어간(송도1동 → 송도 · 일산동구 → 일산) · 역 · 지명이 앞에 붙은 장소(천안고속터미널 → 천안). 장소 스팬은 역을, 지명 스팬은 행정구역을 먼저 본다. 추정(어간·앞머리)은 신뢰도 ×0.8. 오탐을 막으려 장소 이름에는 읍면동 어간을 쓰지 않는다(「호수공원 → 호수동」 방지)
2. **글끼리 엮기** — 위치·나이는 강한 단서(명시·암묵, 신뢰도 ≥ 0.8)의 **교집합 상태**를 모두 만든다. 같은 곳을 가리키는 단서가 **서로 다른 글**에 있으면 noisy-OR 로 신뢰도를 합친다 (추론 0.5 × 3편 → 0.875 → 직접 좁힘). 역·장소 단서는 같은 글에 거주 표지(REL_HOME)가 없으면 **관계 불명**이라 신뢰도 ×0.5 — 「선릉역에서 친구를 만났다」로 사는 곳을 좁히지 않는다
3. **방어적 최소** — 가설 = (위치 상태 × 연령 상태 × 성별) — 「제한 없음」은 항상 포함, 법정동 확장은 후보 동마다 각각. 가설마다 약한 단서·비율 축까지 **다 적용한 최종 k** 를 계산하고 가장 작은 값을 쓴다. 공격자가 고를 수 있는 가장 좁은 해석이고, C 의 법정동 `k_min` 과 같은 원칙이다. **단서를 더해도 k 가 커지지 않는다** (모든 단서가 비율 후보로도 남고, 가설·후보는 늘기만 한다)

`risk` · `risk_by_axis` 는 기존 `risk_total` 그대로다 — exp10 · exp11 · 추천 엔진 수치는 바뀌지 않는다. 비율표는 `data/dict/priors/priors.json` (해상도별 대표값 · **통계 원표 대조 전 초기값**).

「정답 미포함」 예시는 대부분 해석 오류가 아니라 직장·출신지·여행지다(사는 곳이 아닌 실제 장소) — 그래서 위치 결합에서 장소 단서의 관계를 따지고 방어적 최소로 다룬다.

### LLM 추론 성공과의 관계 (exp11 교사 LLM 적중 수와 Spearman)

| | 기존 위험도 (exp11) | 새 k (−log k) |
|---|---|---|
| 전체 ρ | 0.813 | 0.823 |
| 전체 — 글 수 통제 부분상관 | 0.412 | 0.438 |
| 튜닝군 부분상관 | 0.470 | 0.593 |
| **보고군 부분상관** | **0.397** | **0.268** (같은 글 수 내 순열 p=0.11) |

**새 k 가 실제 추론을 더 잘 예측한다고는 말할 수 없다.** 전체 관측값은 비슷하지만 보고군에서는 기존 위험도보다 낮고 유의하지 않다 — 일반화 동등성은 확인되지 않았다. 이번 개선의 성과는 **k 가 글에 따라 실제로 움직이고, 여러 글을 엮고, 단서를 더해 커지지 않으며, 좁힌 위치가 사는 곳을 놓치지 않는다**는 것이다. α 는 사전 지정 0.6 을 유지했다 (튜닝군 민감도: 0.4 → 0.579 · 0.6 → 0.593 · 1.0 → 0.643 — 1.0 은 감쇠 없음이라 C 매뉴얼의 붕괴 위험).

## 4. 검증

- 테스트 57개 (`src/kopl/c2_specificity/test_k_engine.py`) — 기존 `specificity_l1` 과 같은 입력이면 같은 k (4건) · 글이 쌓이면 감소 · 교집합 · 방어적 최소 · 계약 스키마 · Codex 검토 반례 회귀 · **실제 인물 20명 × 무작위 순서 3개로 「조건을 더해도 k 가 안 커진다」** · 실제 인구표 무작위 300개에서 교차표 직접 조회값 이하로 내려가지 않음 · 글 40편 2초 이내
- Codex(gpt-6.1-sol) 검토 4회 — 1차 10건 · 2차 4건 · 3차 3건 지적을 고쳤다. 4차에서 「상한 밖 단조성 성립」 확인

## 5. 한계

- **비율표가 대표값이다** — 직업·가족·통근·소득 `p` 는 통계 원표와 대조 전이다 (W9). k 의 절대값은 거칠다. 순서·변화를 주장하고 「정확히 몇 명」은 주장하지 않는다
- **방어적 최소는 경고를 강하게 하는 쪽**이다 — 서로 겹치지 않는 위치 단서(이사·직장·여행지)가 있으면 그중 가장 좁은 해석을 쓴다
- **합성 인구표(극단적 상관)에서는** 「제한 없음」 가설의 주변 비율 곱이 교차표 직접 조회보다 작아질 수 있다 — 실제 인구표 2,919개 조합에서는 0건 (테스트로 고정)
- **교집합 상태 상한 20,000** — 인위적으로 겹치게 만든 입력(2^15)에서 상한에 걸리면 단조성이 깨질 수 있다. 실제 데이터의 상태 수는 수십 개
- 역 사전(764개, 2019~2021 공공데이터)에 인천 1호선 등이 없다 — 「작전역」 미해석. 해외 거주(E03 상하이)는 국내 사전 밖
- 시제(예전 거주지)를 모델링하지 않는다 — 겹치지 않는 위치는 방어적 최소로만 다룬다
- 골드 스팬 기준이다 — 1단 예측 스팬(정밀도 0.40)으로는 오탐 단서가 k 를 잘못 내릴 수 있다
