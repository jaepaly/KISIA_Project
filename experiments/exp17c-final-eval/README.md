# exp17c-final-eval: 1단 교체 후보 최종 판정용 평가셋 — **한 번만 채점**

## 1. 왜

DEC-011 이후 운영 규칙 3번 — 교체 후보가 생기면 새 평가셋으로 기준선과 후보를 **한 번씩만** 채점해 최종을 정한다 ([#322](../../../../issues/322)).

- 후보: **C그룹 + o-weight 0.05 + 기존 규칙 · 임계값 0.7** (B · 10/9 고정) — exp17(개발용)에서 4개 변형 중 골랐다
- 기준선: **기준선 v2** (기존 재학습 + 기존 규칙 · 임계값 0.7) — exp17b 로 10/8 에 한 번 쟀다
- exp17 은 후보를 고르는 데 썼고 exp17b 는 기준선을 이미 봤으므로, 같은 설계의 **새 값 · 새 표현**으로 다시 만든다

## 2. 규칙 (프로토콜)

1. 데이터는 아래 해시로 **고정**한다. 바꾸지 않는다
   `data/posts.jsonl` SHA-256 (LF 줄바꿈 · git 에 저장된 내용 기준) = `b7d12a24140da3d38a1f6d6bd4b55f59e8b30df10abacdb97026c17c61734cc1`
2. 채점은 기준선과 후보를 **같은 날 한 번씩만** — 채점 전에 위 해시를 확인한다
3. 오답을 열어 규칙 · 모델을 고치지 않는다. 고치면 그 뒤의 수치는 exp17c 로 주장하지 않는다
4. 결과는 **묶음별**로 따로 본다 (`recall_by_group` — targeted · untargeted · trap)
5. 판정 기준은 DEC-011 운영 규칙 2번 — 기준선보다 **확실히** 나을 때만 교체. 본인 재현율이 조금 오르고 다른 지표가 떨어지면 교체하지 않는다. self 유출이 늘면 안 된다

```bash
# 채점 (기준선 · 후보 각 한 번)
python experiments/exp17-planted-eval/score.py --data experiments/exp17c-final-eval/data/posts.jsonl <기준선 예측.jsonl> <후보 예측.jsonl>
```
