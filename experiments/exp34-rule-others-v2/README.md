## 2. 판정 (사전 등록)

A = main `attributes.py` · R = 이 브랜치. 채점은 exp33 `score.py` 와 같은 방식(두 파일을 같은 입력에 부른다).

R 채택 = 모두 만족:
1. H-pos — 패턴마다 R 정답 비율 **≥ 0.75**
2. H-neg — **A 가 맞힌 반례를 R 이 틀리는 수 ≤ 패턴마다 1** (전체 ≤ 3)
3. H-neg — R 정답 수 ≥ A 정답 수
4. 골드 — 사람 검수 lost **≤ 1** · 전체 lost **≤ 5** · R 일치 ≥ A 일치
5. 단위 테스트 통과 · 정규식 시간: 5,000자 공백 · 반복 입력에서 `subject_of` 한 번 **≤ 0.05초**
6. H-post 가 있으면 1 · 2 를 H-post 에도 같은 문턱으로

- **패턴별 부분 채택을 허용한다** — 패턴마다 1 · 2 를 따로 보고, 통과한 패턴의 규칙만 남긴다(규칙이 패턴별로 분리돼 있어야 한다). 3 · 4 · 5 는 남긴 규칙 전체로 다시 잰다
- R 이 떨어진 패턴은 판정셋을 본 뒤 다시 맞추지 않는다

### 판정셋 확정 (결과 전 · 10/17 밤)

- H-pos 90줄(P1 · P2 · P3 각 30) · D 검토 제외 1(H-P3-10 「방년 열여덟 꽃다운 나이올시다」 — 농담인지 실제 나이인지 모호) → 89
- H-neg 140줄(Codex) = neg 125(P1 45 · P2 40 · P3 40) + pos-hard 15(패턴마다 5 · 정답 other · 「묻다 · ~라고 했다」가 섞임). D 검토 제외 0
- 기준 2 · 3 의 「반례」는 neg 와 pos-hard 를 함께 센다 — 둘 다 규칙이 넓어지거나 좁아질 때 A 가 맞히던 것을 R 이 틀리는지 보는 문장이다
- P2 pos 에는 표준 호칭(「울 엄마」 「우리 아빠」)도 섞여 있다 — main 이 이미 맞히는 것이라 A 와 R 의 차이는 사투리 쪽에서 난다
- 시간(기준 5)은 `score.py worst_time` 의 긴 공백 · 반복 입력 4종 × 유형 3종 중 최악값
- 구현은 판정셋 확정 전에 끝났다(91f762c · 판정셋 폴더를 열지 않음) — 채점은 이 커밋 뒤에 한다
