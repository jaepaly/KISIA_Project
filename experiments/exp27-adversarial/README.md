# exp27-adversarial: 적대적 1라운드 (소규모) — 같은 단서를 숨기기 전후 1단 재현율

README W9 D 섹션 「적대적 1라운드」(실험 ⑧ · 10/25). roadmap 의 「같은 단서를 일부러 숨기기 전후로 재현율이 얼마나 떨어지나」를 **새 합성 글 20쌍**으로 잰다. 이미 쓴 판정셋(exp17 · 17b · 17c · 17d)과 개발셋(17e)은 쓰지 않는다.
이 문서의 정의는 **결과를 보기 전에** 적고 커밋한다(DEC-011 과 같은 원칙). 판정 기준은 두지 않는다 — 기술 통계로 정리서 「한계 · 회피 내성」 칸의 재료를 만든다.

## 1. 짝 만들기 — 글은 같고 단서 표현만 다르다

1. Gemini 가 **원래 표현**(아래 「원래」)을 글쓴이 자신의 정보로 정확히 한 번 넣은 SNS 글(2~4문장)을 쓴다 — 생성기 · 시스템 지시는 exp17e 와 같다(코퍼스 GPT · 교사 Claude · 2단 Qwen 과 다른 계열)
2. **숨긴 판**은 그 글에서 원래 표현을 「숨긴 표현」으로 **문자열 치환만** 한 것이다 — 나머지 글자는 전부 같다. 생성 차이가 섞이지 않고 숨기기 효과만 남는다
3. 정답 스팬 = 그 표현의 위치 · 유형 · subject self

## 2. 20쌍 — 단서 유형 5 × 숨기는 방법 4

- 원래 표현은 exp17 · 17b · 17c · 17d · 17e 의 글에 부분 문자열로도 없는 것만 골랐다(10/13 확인 — 처음 고른 9개가 겹쳐 바꿨다)
- 「돌려 말하기」는 정보를 그대로 담되(오십대 초반 · 강릉 · 서울대입구역 · 보육교사 · 형수) 그 낱말을 쓰지 않는 표현이다. 다른 지명 · 시설이 섞인 것(경포대 · 샤로수길)은 그 자체가 단서라 아래 「느슨한 일치」로 따로 본다

## 3. 재는 것 — 1단 v2 앱 경로

- 탐지: 1단 v2(`model.safetensors` SHA-256 `d7dc7b06…`) + 명시 규칙 · 앱 경로(`c1_rules.detect` · `kopl.c1_span.attributes.resolve`) · 임계값 0.7 · CPU
- **주 지표 — 엄격 일치**: 탐지 스팬 중 정답과 `type` 이 같고 IoU ≥ 0.5 인 것이 있으면 「잡음」 (계약 partial match 와 같은 기준)
- **보조 — 느슨한 일치**: 같은 묶음 유형(위치 = LOC_ADMIN · LOC_FACILITY · REL_HOME / 그 밖은 같은 유형)의 탐지 스팬이 정답과 한 글자라도 겹치면 「잡음」 — 「위치라는 건 알아챘다」를 따로 센다
- 적는 것: 원래 · 숨긴 판 재현율(20개 중) · **원래는 잡았는데 숨긴 판은 놓친 쌍 수** · 숨기는 방법별 · 유형별 · 잡은 스팬의 subject(본인으로 판정했는지)
- 숨긴 판이 원래 판보다 많이 잡히는 쌍도 그대로 적는다
- 2단 · 위험도는 재지 않는다 — 1단이 놓치면 그 뒤도 못 본다. 「2단 평가는 하지 않았다」를 한계로 적는다

## 4. 검토

생성 뒤 20편을 전부 읽고, 원래 표현이 글쓴이 자신의 정보로 쓰이지 않았거나 문장이 깨진 글은 **결과를 보기 전에** `excluded` 를 달고 이유를 적는다(exp17e 와 같은 방식). 치환한 숨긴 판의 조사가 어색해도 고치지 않는다 — 실제 회피 글도 그렇게 쓴다.

## 5. 한계 (미리 적는다)

- 20쌍 · 유형당 4 · 방법당 5 — 작다. 경향만 본다
- 숨기는 방법 4가지는 사람이 실제로 쓰는 회피의 일부다(오타 · 이모지 · 다른 언어 섞기 · 이미지 속 글자 등은 없다)
- 합성 글이고 문장이 짧다(2~4문장)
