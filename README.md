## A · 이은선 — 데이터 리드

> **이번 주 목표**: 합성 인물 10명 + 글 200편, 그리고 **라벨 스키마 확정**
> 배경은 [A-data.md](docs/roles/A-data.md)

### 월 — 인물 설계 양식 확정

[docs/persona-design.md](docs/persona-design.md)를 읽고 인물 1명을 JSON으로 정의해 본다.

```json
{
  "persona_id": "S01",
  "gt": {
    "age": 34, "gender": "F", "residence": "서울 성동구 성수동",
    "job": "카페 매니저", "family": "배우자, 자녀 없음",
    "commute": "지하철 2호선", "income": "중간"
  },
  "voice": {
    "종결어미": "~해요체", "이모지": "거의 안 씀",
    "글 길이": "짧음(300자 내외)", "말버릇": "'뭐랄까' 자주 씀"
  },
  "clue_plan": [
    {"post": "b03", "clue": "성수동 팝업 다녀옴", "attr": "residence", "level": "inferential"},
    {"post": "b07", "clue": "2호선 사람 많아서", "attr": "commute", "level": "implicit"}
  ]
}
```

> ⚠️ **학력 · 학교 · 전공 · 정치성향 · 건강 · 지적 수준은 단서로 심지 않는다.** 방어 도구가 민감 속성 추론을 학습하면 그 자체가 무기가 된다.

### 월 — 리얼리즘 기준 확보 ⭐

**"단서가 티 안 나게"와 "사람이 쓴 글처럼"은 다른 축이다.** 둘 다 만족해야 한다.

| 축 | 실패하면 나오는 반박 |
|---|---|
| 단서 은닉 | *"심어둔 걸 찾은 것 아니냐"* |
| **리얼리즘** | ***"합성이라 실제와 다르다"*** ← 이 프로젝트 최대 약점 |

계획서 §6의 외적 타당성 5중 방어 중 **①번이 "실제 글의 비식별 분석 카드에서 역설계 — 임의 창작이 아님"** 이다. 기준 자료가 없으면 이 방어가 통째로 빠진다.

**✅ 이미 저장소에 있다.** 선행 PoC에서 이관 완료 — 읽고 쓰기만 하면 된다.

| 파일 | 내용 |
|---|---|
| [`data/realism/REALISM_GUIDE.md`](data/realism/REALISM_GUIDE.md) | 문체 특성 · 구조 · 단서를 흘리는 방식 (88줄) |
| [`data/realism/cards/`](data/realism/cards/) | 비식별 분석 카드 **10장** — 화자 유형별 톤 참조 |

**월요일에 할 것: 가이드 1회 정독 + 카드 10장 훑기 (1시간).**
그다음 **카드의 특징을 프롬프트에 그대로 넣는다.** 예를 들어 S1 카드는 이렇게 되어 있다.

```
- 극도로 파편적인 의식의 흐름: 종강→축제→음식→술→드라마로 폭발적 전환
- 쉼표 남발(",,,"), 느낌표 폭발("!!!!!!!")
- 오타·축약: 출긘·퇴긘·머금·마쉿·왤케·조아
- 덕질 콘텐츠가 분량의 절반 = 순수 노이즈
```

카드가 부족하다고 느끼면 **추가로 만들어도 된다.** 방법은 아래.

<details>
<summary>카드를 추가로 만드는 법</summary>

공개된 한국어 블로그·SNS 글을 **읽고 표층 특징만** 카드로 적는다.

```markdown
## 카드 03 — 30대 직장인 일상글

- 평균 문장 길이: 약 25자, 편차 큼 (4자 ~ 70자)
- 종결: "~함" "~했다" 혼용, 존댓말 아님
- 오타: 2건 (띄어쓰기 1, 자모 1)
- 이모지: 없음. 대신 "ㅋㅋ" 3회
- 단락: 1~2문장씩 짧게
- 특이: 중간에 점심 메뉴로 샜다가 안 돌아옴
- 제목: 5자 이내 명사형
```

> ⚠️ **원문을 저장하지 않는다. 인용하지 않는다.** 읽고 특징만 서술한다.
> 이건 [RULES-DO-NOT.md](docs/RULES-DO-NOT.md) #1(무동의 수집 금지)에 걸리지 않는다 — 수집이 아니라 관찰이고, 남는 것은 원문이 아니라 통계적 서술이다. 계획서가 말한 *"원문은 저장하지 않았고"* 가 정확히 이 방식이다.

</details>

이 카드가 프롬프트의 스타일 지시가 되고, W3 분포 검증의 비교 기준이 된다.
상세는 [A-data.md §3](docs/roles/A-data.md).

### 월~화 — 라벨 스키마 확정 (최진필과 함께) ⭐

**이게 이번 주 1순위다.** 스키마가 없으면 글을 만들어도 라벨을 못 붙이고, 최진필도 학습을 시작할 수 없다.

정할 것 — 결과는 `docs/contracts/label-schema.md`:

| 항목 | 예시 |
|---|---|
| 스팬 유형 목록 | `LOC_FACILITY` `AGE` `JOB` `FAMILY` `COMMUTE` … |
| 단서 등급 | `explicit` / `implicit` / `inferential` |
| 위치 표기 | **문자 offset** (start, end) — 바이트나 토큰 인덱스 아님 |
| 겹치는 스팬 | 허용? 최장 우선? |
| 관계어 처리 | "집 근처" "퇴근하고"를 별도 유형으로 둘지 |

**TAB(Text Anonymization Benchmark) 주석 가이드라인을 기준으로 삼되 한국어·게시글에 맞게 손질한다.** 백지에서 설계하지 않는다.

### 화~목 — 글 생성

1. 인물 **3명**으로 시범 생성 → 직접 읽어 보고 문제 찾기
2. 프롬프트 수정 — 아래 ✗/○ 대조 + **위에서 만든 리얼리즘 카드**를 프롬프트에 넣는다
3. **10명 × 20편 = 200편**
4. **10편 뽑아 리얼리즘 검수** (아래)

| ✗ | ○ |
|---|---|
| "저는 34살입니다" | "**서른넷** 되니 체력이…" |
| "성수동 살아요" | "**집 앞** 성수 팝업 다녀왔어요" |
| "2호선 타고 출근해요" | "**퇴근길** 2호선이 오늘따라…" |

**노이즈가 70~80%여야 한다.** 20편 중 신상 단서가 실린 건 4~6편이고 나머지는 맛집·드라마·날씨다.

**리얼리즘 검수 — 10편만 뽑아서**

| # | 볼 것 | 걸리면 |
|---|---|---|
| 1 | **소리 내어 읽어** 어색한 문장이 있나 | 프롬프트에 카드 특징을 더 구체적으로 |
| 2 | 문장 길이가 들쭉날쭉한가 | AI는 문장을 고르게 쓴다 |
| 3 | 오타·띄어쓰기 오류가 1~2개 있나 | **0개면 부자연스럽다** |
| 4 | "~것 같습니다" "그리고"로 시작하는 문장이 잦은가 | AI 특유의 문어체 |
| 5 | 딴 얘기로 새는 부분이 있나 | 사람 글은 완결적이지 않다 |
| 6 | 다른 인물 글과 섞어놓고 구분되나 | 안 되면 `voice` 설정을 강화 |

### 목~금 — 교사 LLM 자동라벨 착수

생성한 글에 AI가 1차로 라벨을 붙이는 스크립트. **글을 만든 모델과 라벨을 붙이는 모델은 반드시 다르게 쓴다** — 같으면 자기가 심은 걸 자기가 찾는 셈이다.

### 만들 것

```
data/corpus/v0/personas/S01.json …    인물 정의 (GT 포함)
data/corpus/v0/posts/S01.jsonl …      생성된 글
docs/contracts/label-schema.md        라벨 스키마 (최진필과 공동)
src/kopl/c5_corpus/generate.py        생성 스크립트
```

### 완료 기준

- [ ] **리얼리즘 가이드·카드 10장 정독** 후 프롬프트에 반영 ⭐
- [ ] 인물 **10명 이상**, 글 **200편 이상**
- [ ] 노이즈 비율 70~80% (직접 세어 확인)
- [ ] **리얼리즘 검수 10편 통과** (6개 항목)
- [ ] 라벨 스키마 문서 확정 — **최진필 승인**
- [ ] 학력·정치성향·건강 단서 **0건**
- [ ] 인물마다 문체가 다름 (랜덤 3개를 읽고 구분되는지 확인)

### 막히면

| 상황 | 대처 |
|---|---|
| 글이 다 비슷하게 나온다 | 인물 JSON의 `voice`에 말버릇·이모지 습관·글 길이를 **구체적으로** 쓰고 프롬프트에 넣는다 |
| AI가 단서를 대놓고 쓴다 | 위 ✗/○ 표를 few-shot 예시로 넣는다 |
| 10명이 너무 많다 | **비율을 지키면서** 줄인다. 노이즈 70~80%가 먼저다 |
| API 크레딧이 빨리 준다 | 생성은 저렴한 모델, 교사 라벨은 좋은 모델로 분리 |
| **글이 너무 매끄럽다** | 프롬프트에 *"오타를 한두 개 섞어라"*, *"문장 길이를 들쭉날쭉하게"*, *"중간에 딴 얘기로 새라"* 를 명시한다 |
| 카드 톤이 내 인물과 안 맞는다 | 10장 중 가까운 걸 고르거나 **섞는다.** 그래도 없으면 카드를 추가로 만든다 (위 접힌 부분) |

### 월~화 — 라벨 스키마 확정 (이은선과 함께) ⭐

A 항목의 표를 함께 채운다. **학습할 사람이 스키마를 안 보고 나중에 받으면 반드시 되돌아온다.**

특히 이것만은 확실히 — **위치 표기를 문자 offset으로 할지 토큰 인덱스로 할지.** 토크나이저마다 다르므로 **문자 offset을 권한다.**

**이번 주 C의 가장 중요한 일이다.**

박재현의 가명화(`성수동 → [서울의 특정 동]`)와 내 특정성 계산(`성수동은 몇 명으로 좁히나`)은 **같은 지명 사전을 쓴다.** 가명화기는 특정성 엔진의 역함수다. 사전 형식이 어긋나면 나중에 복원이 깨진다.

- 가명 라벨 형식은? (`[시설A·저수지]` 같은)
- 계층을 어디까지? (동까지? 리까지?)

결과는 `docs/contracts/geo-dictionary.md` — **신정현·박재현 공동 소유**.

| 상대가 "아직 모르겠다"고 한다 | 그러면 **일단 정하고 나중에 바꾼다.** 미정으로 두는 게 제일 나쁘다 |
| 웹 개발을 많이 안 해봤다 | 이번 주는 코딩이 아니라 **문서**다. 구현은 W3부터 |

## 이번 주 반드시 지킬 것 3가지

**① 주 3회 이상 커밋한다.**
제출 전날 40커밋은 증빙이 아니라 **반증**이다. 작아도 좋으니 나눠서 푸시한다.

**② 계약은 목요일에 고정된다.**
그 후 `docs/contracts/`를 바꾸려면 2명 승인이 필요하다. 할 말이 있으면 **수요일 회람 때** 한다.

**③ 실데이터는 절대 커밋하지 않는다.**
실제 블로그·SNS 글을 긁어오지 않는다. 지인 글도, 공개된 글도 안 된다. 훅과 CI가 막지만 **막히면 우회하지 말고 왜 막혔는지 본다.**

전체 목록은 [docs/RULES-DO-NOT.md](docs/RULES-DO-NOT.md).

## 막히면

| 상황 | 어떻게 |
|---|---|
| 기술적으로 막혔다 | **수요일 블로커 체크**에 올린다. 혼자 이틀 붙잡지 않는다 |
| 다른 사람 산출물이 안 와서 못 한다 | **가짜 데이터로 먼저 만든다.** 형식만 맞으면 나중에 교체된다 |

| 일정이 안 될 것 같다 | **미리** 말한다. 금요일에 말하면 대응할 시간이 없다 |
