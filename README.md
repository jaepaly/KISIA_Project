#### ③ ⭐ 중단 기준의 임계값 — ✅ **정해졌다** ([#128](../../issues/128))

**측정 전에 정했다.** 2026-08-31 B·PM 합의. 목요일 멘토 확인 안건 ①.

```
미탐 공간     implicit ≥ 45%  AND  inferential ≥ 45%
도달 가능성   implicit ≥ 60%  AND  inferential ≥ 60%
explicit      게이트 밖 — 진단값으로만 기록

판정   둘 다 넘으면 통과 · 하나만 넘으면 보류 · 둘 다 미달이면 중단
경계   45.0% · 60.0% 과 정확히 같으면 「넘은 것」으로 본다
채점   partial(IoU ≥ 0.5) 주 지표 · exact 부 지표로 병기
상한   LLM 은 **Gemini** — 생성(GPT)·교사(Claude) 어느 쪽과도 겹치지 않는 유일한 자리
```

**왜 총계가 아니라 등급별인가.** W2 실측(`exp01-baseline` · 185 단서 문장 · exact)을 등급별로 쪼개면 이렇다.

| 등급 | 골드 | 3종 전원 미탐 | 미탐율 |
|---|---:|---:|---:|
| `explicit` | 45 | 27 | **60.0%** |
| `implicit` | 76 | 38 | 50.0% |
| `inferential` | 64 | 33 | 51.6% |
| 합계 | 185 | 98 | 53.0% |

**`explicit` 미탐율이 제일 높다.** 총계로 게이트를 세우면 **explicit 미탐이 떠받쳐서 통과**하는데, explicit 미탐은 우리 주장(준식별자 누적·결합)이 아니다. 그리고 총계는 골드셋 등급 구성에 좌우되고 그 구성은 이번 주에 정해진다 — 「측정 전에 정한다」가 총계로는 지켜지지 않는다.

> ⚠️ **이 역전을 B 가 (가) 로 판정했다** — 설정 문제가 아니라 **기존 도구의 구조적 한계**다. `label-schema` §4-1 이 이미 「"마흔여덟"은 explicit 이며 **기존 도구가 못 잡는 explicit**」이라고 못박아뒀다. 목요일 멘토링에 이 표를 들고 간다.

```
월 오전   ① 생성 경로 실측·결정   ② 검수 속도 측정   ③ 중단 기준 임계값     (전원)

   ↓
화~수     글 생성 3,082편                                    (A·B·C·D, 넘치면 D)
   ↓
화~수     ⭐ blind 200 — 교사 라벨을 보기 전에                              (C 단독)
   ↓
수        교사 자동라벨 — ⚠️ 도구를 먼저 만들어야 한다                        (A)
   ↓
```

### ⭐ blind 200 이 교사 라벨 **앞**에 오는 이유

`A-data.md` §5 가 이유까지 적어 못박았다.

> 원래는 blind 200을 마지막에 뒀었다. **그러면 blind가 성립하지 않는다.** ⑤ 검수를 한 사람은 교사 출력을 전량 본 뒤이고, 그 사람이 "정답을 안 보고" 매길 수는 없다.
>
> **blind 200은 C가 맡고, C는 `data/corpus/v0/gold/`(검수분)와 교사 라벨 원본에 접근하지 않는다.**

그래서 이번 주 배치는 이렇다.

| | blind 200 | 교사 라벨 검수 |
|---|---|---|
| **C** | **단독 200 스팬** (화~수) | ❌ **하지 않는다** |
| A · B · D · E | ❌ | 각 100~125 스팬 (수~금) |

**C 가 검수를 겸하면 blind 가 무효가 된다.** 축소해도 이 분리는 사수한다.

> ⚠️ **검수분 저장 전 `python scripts/check_gold.py <파일>` 통과 필수.**
> 사람이 손으로 검수·수정하며 offset 이 밀리거나 스팬이 겹쳐도 눈으로는
> 못 잡는다. `label-schema.md` §11 의 14개 규칙(type·level·subject enum,
> offset 일치, 겹침, span_id 유일성 등)을 기계적으로 검사한다.
> `label.py` 의 `finalize()`는 생성 시점만 보므로, 검수 이후 안전망은
> 이 도구뿐이다. A·B·D·E 전원 해당.

### ⭐ 새 인물은 `post_plan.total` 을 **30편**으로 쓴다

지금 35명이 평균 **19.5편**으로 쓰였고, **30편을 선언한 인물은 0명**이다. 로드맵의 「3,000글 ÷ 인물당 15~30글 ⇒ 100명」은 **상한 30편을 가정한 산술**이다.

```
새 80명 × 30편 = 2,400편  +  기존 682편  =  3,082편   ✓
새 80명 × 19.5편          +  기존 682편  =  2,242편   ✗ 목표 미달
```

`post_plan.total` 은 숫자 하나라 30 으로 쓰는 것이 20 으로 쓰는 것보다 오래 걸리지 않는다. **노이즈 비율은 그대로** 유지한다(단서 보유 글을 늘리지 말고 잡담 글을 늘린다).

### 왜 나누나 — 막는 것이 토큰이 아니라 요청 횟수다

```
RPD  하루 20회에서 429        ← 여기서 막힌다
TPM  9.06K / 250K = 3.6%      ← 토큰은 27배 여유

```

⚠️ **무료 등급이면 4계정 × 20편 × 5일 = 400편이 상한이다.** 3,082편은 **RPD 가 없는 경로**를 전제한다. 그 경로의 처리량이 아직 측정되지 않았다 — **월요일 오전 실측이 게이트인 이유다.**

### 절차

```bash
pip install -e .        # 안 했으면 반드시

# ① 배선 확인 — 키 없이, 더미 텍스트
python -m kopl.c5_corpus.generate \
  --persona data/corpus/v0/personas/B06.json \

# ② 실제 생성 — provider 는 월요일에 정한 것

  --persona data/corpus/v0/personas/B*.json \
  --out data/corpus/v0/posts \
```

| 옵션 | 언제 |
|---|---|

## ⭐ 골드셋 — blind 는 C 단독, 검수는 나머지 넷

| 누가 | 무엇을 | 얼마나 | 언제 |
|---|---|---|---|
| **C** | **blind 200** — 교사 라벨을 **보기 전에** | **200** | **화~수** |
| A · B · D · E | 교사 라벨 검수 | 각 **100~125** | 수~금 |
| **합계** | | **600~700** | |

**C 는 검수를 하지 않고, A·B·D·E 는 blind 를 하지 않는다.** 섞으면 blind 가 무효가 된다.

### 스팬 레코드 형식 — `label-schema` §8-1

```json
{"span_id": "S01_b07_s02", "text_id": "body", "start": 12, "end": 17, "text": "신갈저수지", "type": "LOC_FACILITY", "level": "inferential", "subject": "self"}
```

**붙는 필드는 이 8개까지.** `blind` 같은 필드를 새로 만들지 않는다 — blind 분은 **디렉터리로 가른다.**

### 파일 경로 — 계약이 인물 단위로 정했다

```
data/corpus/v0/gold/<persona_id>_spans.jsonl          검수분      예: A11_spans.jsonl
data/corpus/v0/gold/blind/<persona_id>_spans.jsonl    blind 분    (C 만)
```

> `label-schema` §8: **인물 단위로 나눈다.** 생성 산출물이 이미 인물 단위라 1:1 로 대응시키면 병합·재생성·부분 재라벨이 파일 하나 단위로 끝난다. **작업자 이니셜로 나누면 인물이 여러 파일에 흩어져 재생성 때 추적이 어렵다.**

### ⚠️ 자주 틀리는 것 넷

**① 겹치는 스팬은 금지 — 최장 우선.** BIO 가 겹침을 표현하지 못한다.

**② `level` 은 표기 형식과 무관하다.** 「마흔여덟」도 `explicit` 이다. 반대로 「시험이 일주일 남았다」에는 나이 값이 없으므로 `inferential` 이다.

**③ `subject` 는 그 스팬의 주체**이지 글 전체의 시점이 아니다. 「처남이 광교 살아서」에서 광교에 사는 사람은 처남이다.

**④ 밈과 세대 신호는 스팬으로 잡지 않는다** (§7). `flags.meme_hits` · `flags.gen_signal` 로 간다. 스팬에 넣으면 라벨러끼리 갈려 IAA 가 깎이고, **B 의 목표치가 IAA 에 묶여 있어** 목표치까지 같이 깎인다.

```

data(c5): blind 200 스팬 (C)
```
