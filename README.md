### 명시 단서 개선 — 규칙 보강(수·목) → 학습 데이터 보강(금)

**왜** — [#283](../../issues/283) 분석(9/29)에서 명시 단서를 놓친 97개 중 **88개는 겹치는 예측이 아예 없었고**, 그중 74개가 AGE 21 · LOC_ADMIN 26 · LOC_FACILITY 27 이다. 경계 어긋남은 6개, 유형 틀림은 3개뿐이다. B 가 임계값을 낮춰 확인했을 때도 후보가 생기지 않았다(9/29 구두 · 수치는 #283 에 남겨 주세요) — **모델이 이 세 유형을 못 배웠다.** 학습에 쓴 검수 골드 331편에는 명시 단서가 LOC_ADMIN 15 · AGE 6 · LOC_FACILITY 0 개뿐이다 (JOB 113 · FAM 88 로 쏠림 → FP 의 JOB·FAM 70% 와 같은 원인).

> ⚠️ **이번 개선은 test 를 보고 설계했다** — 보강할 유형(AGE · LOC_ADMIN · LOC_FACILITY)을 #283 의 test 오류 분석으로 골랐고, 아래 「test 상한」도 PM 이 test 에서 잰 값이다. 그래서 개선 후 test 수치는 **「test 분석을 반영한 개선 결과」라고 표시해서** 중간점검에 낸다. 그 이상 새지 않도록: 정규식·제외 목록·약칭 목록은 **train 쪽 글(검수 골드 331편 · 내부 dev)만 보며** 만들고, test 는 설정을 모두 정한 뒤 **한 번만** 채점한다.

**① 규칙 보강 — AGE · LOC_ADMIN 명시 단서 (수·목, 재학습 없음)**

모델 출력에 규칙으로 찾은 스팬을 합친다. 명시 단서는 표현이 정해져 있어 규칙이 잘 잡는 종류다. 규칙 코드는 `experiments/exp06-finetune/` 안에 새 파일로 둔다 (예: `rules.py`) — `src/kopl/` 은 CODEOWNERS 경로라 이번 실험에서는 건드리지 않는다.

- **AGE** — 한글 수사 나이 `(스물|서른|마흔|쉰|예순|일흔|여든|아흔)(한|두|세|네|다섯|여섯|일곱|여덟|아홉)?` · `숫자+살/세` · `한글수+살/세`(「세 살」「아홉 살」) · `NN년생`
  - 오탐 막기: 뒤에 수량 단위가 붙으면 제외 (「서른 번」「스무 개」「마흔 명」「서른 분」 등). 나이 문맥이 아닌 경우를 거르는 목록은 train 글에서 오탐을 보며 만든다
  - (참고 · test 상한) test 명시 AGE 22개 중 21개가 이 정규식에 걸린다
- **LOC_ADMIN** — C2 행정구역 사전 `kopl.c2_specificity.engine.RegionDictionary().resolve(이름)` 을 조회에 쓴다
  - **조사를 떼고 조회한다.** `resolve()` 는 이름이 정확히 같아야 찾는다 — 「부천으로」「서울에서」「해운대구는」은 모두 못 찾는다. 어절 끝의 조사·문장부호를 떼어 조회하고, **출력 스팬에는 조사를 다시 포함한다** (label-schema §5-2: 끝 어절의 조사·어미 포함, 서술어는 제외)
  - **약칭을 붙여야 효과가 난다.** 사전은 「부천시」「서울특별시」「해운대구」만 찾고 「부천」「서울」「해운대」는 못 찾는다 (`regions.json` 의 `aliases` 에 정식 이름만 들어 있다). 약칭은 **코드 안에서** 만든다 (`data/dict/` 는 CODEOWNERS C·D 경로라 사전 파일은 고치지 않는다):
    - 대상은 `level` 이 `sido` · `sigungu` 인 것만. 읍·면·동은 약칭을 만들지 않는다
    - **긴 접미사부터** 뗀다: `특별자치시 · 특별자치도 · 특별시 · 광역시 · 도 · 시 · 군 · 구` 순 (「서울특별시」에서 「시」만 떼면 「서울특별」이 된다)
    - 약칭 하나에 코드가 여럿이어도 된다 (「고성」 2곳 · 「중구」 5곳) — 1단은 type(LOC_ADMIN)만 맞히면 되므로 어느 지역인지는 정하지 않는다
    - 일반 명사와 겹치는 약칭(예: 「진도」「구미」「화성」 — 실제 목록은 train 글에서 확인)은 제외 목록으로 뺀다. 1글자 약칭은 쓰지 않는다
  - (참고 · test 상한) 약칭 없이 31개 중 13개, 약칭을 붙이면 약 24개. 「판교」「오송」 같은 생활권 이름 · 「시드니」 같은 해외 지명은 사전 밖이라 남는다
- **LOC_FACILITY** 는 규칙으로 안 된다 (시설 이름은 끝이 없다) → ② 로
- **합치는 방법** — 모델 후보와 규칙 후보를 한데 모은 뒤, **학습·추론에서 쓰는 것과 같은 최장 우선 무겹침 함수** `train.resolve_overlapping_spans()` 를 채널별로 적용한다 (계약 `span.schema.json` 5번: 같은 text_id 안 겹침 금지 · 최장 우선). 출처에 따라 우선순위를 따로 두지 않는다. 계약 출력에 새 필드는 넣지 않는다 — 규칙 출처는 로그·metrics 에만
- **평가 — `rescore_saved()` 를 그대로 쓰면 멈춘다.** 이 함수는 다시 계산한 점수가 저장된 점수와 같은지 확인하는 검증용이라(`Original partial metric changed during rescore`), 규칙 스팬을 더하면 반드시 실패한다. 저장된 예측 파일을 직접 고치지도 않는다. 대신 **규칙 결합 전용 평가 경로**를 따로 둔다:
  1. 저장된 `predictions.jsonl` 을 읽는다 (원본 그대로 — 입력 지문 검사는 기존처럼 통과해야 한다)
  2. 글마다 규칙 후보를 더하고 위 합치기 함수를 적용한다
  3. `score_subset()` · `fp_breakdown()` 으로 채점해 **새 metrics 파일**에 쓴다
  - 규칙 **전·후**를 나란히: 명시 재현율 · proxy F1 · 전체 정밀도 · type 별 TP/FP · **noise 80편의 FP 변화**(`by_kind` 의 noise — 규칙이 잡담에서 얼마나 오탐하는지)
  - ⚠️ 저장 예측의 입력 지문에는 `splits/train.jsonl` 도 들어 있다 — **① 평가를 끝내기 전에는 splits 를 다시 만들지 않는다** (#284 뒤 다시 만들면 train.jsonl 이 `E09_b08` 한 편만큼 바뀐다)

**② 학습 데이터 보강 — 검수 안 된 교사 라벨 추가 재학습 (금)**

- 지금 `prepare_bio.py` 는 최상위 골드 중 `reviewed: true` 만 읽는다 (train 쪽 331편). 최상위 골드에서 **test 125편을 뺀 train 쪽 미검수 1,950편은 교사 라벨**이다

| 등급별 F1 에서 예측 스팬의 등급을 정할 수 없다 | 모델은 등급을 예측하지 않는다. 재현율은 정답 등급별로 센다. 어떤 정답과도 안 겹친 예측(FP)은 등급이 없어서, 정밀도를 「매칭된 정답의 등급」으로만 세면 FP 가 빠져 부풀려진다 — 산식은 [#276](../../issues/276)에서 확정 — 본 지표 proxy F1 · 참고치 보수적 F1 |
| `age_band` 로 못 좁히는 나이 표현 (경로당 · 야자 · 「40대」) | 좁히지 않는다 — `kind` 를 따로 두고(예: `age_hint`) `value` 는 원문, resolution 1 그대로 ([#272 리뷰](../../pull/272) 제안) |
| LOC_ADMIN 코드가 시도인지 읍면동인지 모르겠다 | `engine.resolve(text)` 는 코드 **목록**을 준다. 계층은 사전 `regions[code]["level"]` (`sido`·`sigungu`·`emd`) 로 본다 — **자릿수로 판별하지 않는다**, 사전 코드는 전부 10자리 |
| 지명 후보가 여러 개 나온다 (동명이인) | 가장 넓은 level 을 쓴다 (좁게 잡으면 위험도 과대). `geo_code` 를 어느 것으로 할지는 #272 리뷰 7번 결정을 따른다 |
| 조건 계약 검증에서 `value` 또는 `geo_code` 필수라고 나온다 | `specificity.schema.json` condition 은 `anyOf[value, geo_code]` — 둘 중 하나는 있어야 한다. 확정된 지역·시설 코드가 있으면 `geo_code`, 코드가 불확실한 시설은 `value` 원문, 후보가 여럿인 지명은 #272 리뷰 7번 결정을 따른다 |
| exp8 축약판에서 위험도를 다시 계산하는 법을 모르겠다 | 남은 글로 `risk_total(build_conditions(...))` 을 다시 부른다 — `risk_total` 은 `c2_specificity`, `build_conditions` 는 #272 머지 뒤. 글을 내린 순서별 위험도는 `c3_contribution/loo.py` 의 `leave_one_out()` 출력 `greedy_path` (`remove` · `risk_after`). 모르면 C 에게 |
| LLM 을 불러야 하는데 키가 없다 | PM 에게 받는다. 키는 `.claude/settings.local.json` 처럼 커밋 안 되는 곳에만 둔다 ([AGENTS.md](AGENTS.md) 금지 사항) |
| 테스트가 cp949 오류로 죽는다 | `PYTHONIOENCODING=utf-8 python -m pytest` |
| `check-jsonschema` 명령이 없다 | `pip install check-jsonschema` |
| PR 머지가 안 된다 | 리뷰어에게 요청 — 재촉하지 말고 한 번만 |
