# 파도풀 — 공개 게시글 누적·결합에 따른 재식별 위험 자가진단 및 보호조치 추천 시스템

**KISIA 2026 AI 보안기술개발 · 개인정보 트랙 3팀** · 2026-08-17 ~ 11-08 (12주) · 담당 멘토 권영길

> 이름도 주소도 쓰지 않은 글이 쌓이면 나이·성별·사는 곳·직장·가족이 드러난다.
> 파도풀은 **내 글이 얼마나 나를 특정하는지 이용자 기기 안에서 진단하고**,
> **가장 적은 부담으로 위험을 줄이는 조치**를 추천한다.

**[▶ 시연 영상 (약 6분)](https://youtu.be/1espV-Mg_S0)** — 가상 SNS Veilo와 파도풀 분석기. 등장 계정은 모두 합성 인물이고 실존 개인과 관계없다.

## 문제 — 한 편씩은 평범한 글

```
야간 3일차, 퇴근길            → 교대 근무
마흔다섯인데 회복이 예전 같지 않음  → 40대 중반
공단 정문까지 차로 십오 분         → 공단 근처 거주
아들 중간고사 기간이라 문을 살살    → 중학생 자녀
```

글 하나만 보면 신상 정보가 없다. 그런데 이 단서들을 합치면 **같은 조건의 사람이 약 783명**으로 좁혀진다(시연 계정 `3교대인생` · 합성 인물).

주제를 정하기 전 사전 실험에서 합성 인물 한 명의 글을 늘려 가며 LLM에게 신상을 추론시켰다.

| 투입 글 수 | 1편 | 5편 | 10편 | 19편 |
|---|---:|---:|---:|---:|
| 추론에 성공한 속성 | 4/7 | **7/7** | 7/7 | 7/7 |
| 재식별 위험도 (0~100) | 26.7 | 69.2 | 71.9 | **79.7** |

- **5편이면 7개 속성이 모두 드러난다.** 위험은 글 하나가 아니라 글이 쌓이고 결합하는 데서 생긴다.
- 기존 도구 3종(정규식 · Presidio · 한국어 NER)은 단서 문장 967개 중 **47.3%** 를 모두 놓쳤다. 「마흔다섯」 같은 명시 정보만 잡고, 「중간고사」「공단 정문」 같은 암묵 단서는 보지 못한다.
- 선행 연구(Staab et al., ICLR 2024)는 LLM이 공개 글에서 작성자 속성을 최대 85.5% 정확도로 추론함을 보였다. 다만 위협을 실증하는 데 그쳤고, 개인이 직접 점검하고 줄이는 방법이나 한국어 글은 다루지 않았다.

기업은 개인정보 영향평가(개인정보 보호법 제33조)로 위험을 점검하지만, **개인에게는 그런 수단이 없다.** 파도풀은 그 빈자리를 겨냥한다.

## 무엇을 만들었나

| | 기능 | 내용 |
|---|---|---|
| ① | **실시간 점검** | 글을 쓰는 동안 직업·지역·가족·성별 단서를 종류별 색으로 표시하고, 후보 인원이 얼마로 좁혀지는지 보여 준다. 누구 정보인지 불분명한 단서는 점선으로 표시하고 계산에서 뺀다 |
| ② | **계정 진단** | 지금까지 쓴 글 전체를 묶어 7개 속성(나이 · 성별 · 거주지 · 직장 · 가족 · 통근 · 소득)별로 드러났는지 판정한다. 같은 조건의 사람 수와 위험도(0~100)를 보여 주고, 판정 근거를 단서 단위로 펼친다. 「내 얘기 아님」을 누르면 그 단서를 빼고 다시 센다 |
| ③ | **최소 조치 추천** | 위험에 크게 기여하는 글부터 골라 **부담이 적은 조치부터** 추천한다 — 글 몇 편 비공개 → 위치태그 삭제 → 바꿔 쓰기. 조치별 예상 효과를 미리 보여 준다 |

- **분석은 이용자 기기 안에서만 돈다.** 프라이버시 위험을 검사한다고 글을 외부 서버로 보내면 그 도구가 곧 침해가 되기 때문이다. 시연 빌드에서 분석 중 외부 서버로 나간 요청은 **0건**이다([동결 재검증](docs/evidence/freeze-W11.md)).
- 화면은 따로 두지 않고 가상 SNS **Veilo**의 글쓰기 화면과 「내 글 점검」 메뉴 안에 넣었다. 실제 플랫폼에 붙일 때의 형태를 그대로 보여 주기 위해서다.

## 어떻게 동작하나

```mermaid
flowchart LR
    A["글 N편<br/>제목 · 본문 · 사진 설명"] --> B["1단 · 단서 찾기<br/>KoELECTRA-base 110M<br/>+ 명시 규칙"]
    B -->|"단서 스팬<br/>유형 · 등급 · 누구 정보"| C["2단 · 속성 판정<br/>Qwen3-4B + QLoRA<br/>llama.cpp GGUF"]
    B --> D["후보 수 k<br/>주민등록 인구 통계"]
    C -->|"7개 속성<br/>드러남 / 기권"| E["위험도 · 기여도 엔진"]
    D --> E
    E --> F["최소 조치 추천<br/>비공개 → 위치태그 → 바꿔 쓰기"]
```

**1단 — 단서 찾기.** KoELECTRA-base를 21개 라벨(10개 유형 × B/I + O)의 토큰 분류로 학습했다. 찾은 단서마다 유형, 등급(명시 · 암묵 · 추론), 누구 정보인지(본인 · 타인 · 불분명)를 붙인다. 임계값 0.7에 명시 정보용 규칙을 더했고, CPU에서 글 한 편당 중앙값 160.5ms로 돈다.

**2단 — 속성 판정.** 1단 결과를 프롬프트로 묶어 Qwen3-4B(QLoRA r16)가 7개 속성마다 「드러남」 또는 「기권」을 판정한다. 근거가 약하면 기권하도록 학습해서, 아무 글에나 겁을 주지 않는다. llama.cpp GGUF(Q8_0 + LoRA)로 실행하고, GPU가 없는 PC에서는 같은 기준의 규칙 판정으로 대신한다.

**후보 수와 위험도.** 행정안전부 주민등록 인구 통계(읍면동 × 5세 구간 × 성별, 152,166행)에 단서 조건을 걸어 「같은 조건에 해당하는 사람 수」를 센다. 전체 인구 5,108만 명이 글 한 편의 단서만으로 약 4,973명까지 줄어드는 식이다. 위험도는 속성별 판정에서 따로 계산하고, 글마다 위험에 얼마나 기여하는지를 닫힌 식으로 구한다.

**데이터 — 전량 합성.** 실제 사람의 글을 모으지 않고 가상 인물 115명의 블로그 글 3,092편을 만들었다. 단서를 직접 드러내지 않게 쓰고(✕ 「자동차부품 회사에 다닙니다」 → ○ 「완성차 공장 출장이 잦아서 피곤하네요」), 신상과 무관한 일상 글을 70~80% 섞었다. 정답 라벨은 교사 모델로 초안을 만든 뒤 437편을 사람이 직접 검수했고, 159편은 교사 라벨을 보지 않은 채 따로 라벨링했다. 최종 시험셋은 239편 · 단서 358개다.

## 결과

**필수 지표**

| 지표 | 목표 | 결과 | |
|---|---|---:|:---:|
| 명시 단서 탐지 F1 | ≥ 0.80 | **0.6738** | △ 목표의 84% |
| 글 1건 탐지 시간 (CPU) | < 300ms | **160.5ms** | ✓ |
| 조치 3단계 위험도 감소 (인물별 평균) | −54 ~ −61% | **−59.2%** (평균 위험 17.7 → 6.7) | ✓ |

**목표 지표**

| 지표 | 목표 | 결과 | |
|---|---|---:|:---:|
| 위험도와 LLM 추론 성공의 순위 상관 (Spearman ρ) | ≥ 0.7 | **0.813** | ✓ |
| 로컬 모델 판정 일치도 (대형 LLM 기준) | ≥ 0.8 | **0.853** | ✓ |
| 기존 도구 대비 추가 탐지 | > 0 | **58.77%** | ✓ |
| 최적 조치 대비 추가 부담 (중앙값) | ≤ 15% | **0%** | ✓ |
| 암묵 단서 탐지 F1 (사람 간 일치도 대비) | ≥ 80% | **105%** (0.4668) | ✓ |

**도전 지표** — 적대적 회피 후 재현율 하락 −40%p(목표 ≤ 15%p) · Triage 토큰 절감 −51.9%(목표 70%+). 둘 다 미달이라 한계로 남겼다.

- 위험도 40점을 넘던 가상 인물 49명 중 **48명**이 추천 조치만으로(대부분 글 1~3편 비공개) 권장 기준 아래로 내려갔다.
- 시연 계정은 추천 조치를 모두 적용하면 위험도가 **57.1 → 29.3**(예상)으로 내려간다.

<sub>명시 F1은 11/5 교체 모델(수정 KoELECTRA)을 관례를 맞춘 보수 수정 정답(계약 v1.5)으로 잰 proxy 값이다. 정답 기준을 정한 경위는 [DEC-018](docs/decisions.md) · [DEC-019](docs/decisions.md)에 있다. 나머지 지표는 11/2 최종 측정([#404](../../pull/404) · [러너](experiments/bench/README.md))이다.</sub>

| 지금의 한계 | 다음 단계 |

**활용 방안**

1. **기업 · 기관 중심이던 재식별 위험 평가를 개인으로.** 개인이 자기 게시글로 직접 점검한다.
2. **한국어 준식별자 벤치마크.** 데이터가 전량 합성이라 공개할 수 있고, 다른 탐지 모델을 평가하는 기준으로 쓸 수 있다.
3. **게시 전 경고.** 플랫폼의 글쓰기 화면에서 게시 전에 단서와 결합 위험을 안내한다.

# 터미널 2 — 파도풀 분석기 (http://localhost:8000)
$env:SNS_PUBLIC_URL="http://localhost:3000"
$env:ENGINE_MODE="real"
$env:STAGE2_MODE="rules"
$env:PYTHONPATH="src"
